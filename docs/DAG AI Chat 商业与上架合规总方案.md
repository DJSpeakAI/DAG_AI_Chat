# 第二部分 · 商业模式终稿：司忆点（SP）体系

## 1. 命名策略（司忆点一名通吃，分层使用）

| 层面 | 名称 | 说明 |
|---|---|---|
| **产品内（UI/用户协议/所有对外文案）** | **司忆点**（SP = SiYi Point） | 与「司忆区」成套：司忆区（记忆知识库）→ 司忆点（体系内流通凭证），完整产品世界观；**对外文案彻底抛弃「积分」二字** |
| **代码内部** | 字段 `siyi_point`，缩写 **sp** | 变量/方法命名用 sp 前缀（camelCase：siyiPoint / spBalance） |
| **IAP 商品名** | 「司忆点礼包」 | 商品描述复制下方定义文本 |
| **审核机制表述** | 消耗型虚拟商品（虚拟服务凭证） | 审核类目/备案材料里的机制性描述，与商品名并行不冲突 |

**★ 合规定义文本（写死，用户协议 + IAP 商品描述 + 首页/礼包弹窗小字三处同款，给华为审核看）**：

> 司忆点｜司忆区体系专属服务凭证，可用于 AI 对话、获取知识卡片、支持创作者。仅限本 APP 内使用，不可提现、不可转让。
>
> 司忆点，是本应用「司忆区」体系下的**虚拟服务凭证**，仅用于本应用内兑换 AI 学习服务、知识卡片内容、对创作者进行打赏。司忆点**不具备现金价值，不可提现、不可转让、不能兑换现实财物**。

**兜底备选**：若审核对自创名词「司忆点」提出疑问 → 无缝切换「学习点（LP）」——仅改名，定义文本/机制/代码结构零改动。

**命名红线（DeepSeek §3.2 沿用）**：任何场合禁用「虚拟货币/币/单独使用的充值」表述；无抽奖开箱等随机性玩法表述。

## 2. 司忆点双循环（核心商业飞轮）

```
赚取侧（行为激励，拉留存）                消耗侧（价值兑换，做变现）
┌─────────────────────────┐            ┌─────────────────────────┐
│ 每日打卡                 │            │ ① AI 回答（对话/解析/批注）│
│ 复习单词/复习卡片         │   ────→    │ ② 下载官方卡包（首版自营） │
│ 需求反馈/素材征集奖励(首版) │            │ （阶段二）购买创作者知识包 │
│ 注册赠送                 │            │ （未来）③ 高级模型/多语种语音│
│ （阶段二）出售知识包100%归己│           └─────────────────────────┘
└─────────────────────────┘
```

- 学习行为赚 司忆点 → 司忆点花在 AI 与知识上 → 更高效学习 + 创作优质知识包 → 赚更多 司忆点——**学习越勤奋，AI 用得越多**，与产品价值完全同向。
- 与 V2.0 框架完全兼容：奖励积分=司忆点（赠予池）、充值积分=司忆点（付费池）；等级体系保留（行为驱动、折扣/权益形态）。

## 3. 三层算力定价结构（积分制的正当性叙事重建）

| 层 | 算力来源 | 司忆点消耗 | 定位 |
|---|---|---|---|
| **L1 基础层** | 小艺开放平台（免费） | **极低**（可被每日赠送额度覆盖） | 普惠打底：人人用得起、吃相好看、零门槛拉新 |
| **L2 高级层** 🚧 | 第三方付费 API：**火山多语种语音对话**（西语/墨西哥语等，全球独一无二的语言学习场景）、**DeepSeek/GLM 强推理** | **高**（锚定真实成本） | 付费墙：语言类/深度推理用户的刚需，市场比价后「相对便宜」即是价值 |
| **L3 流通层** 🚧 | 首版=自营集市（下载扣点归平台流水）；阶段二=UGC 知识包交易（**100% 归创作者**，平台零抽成） | 下载扣点 | 首版自营=合规安全；阶段二 UGC=生态货币，创作激励最大化闭环 |

**叙事定稿**：「基础学习永远便宜（L1），为稀缺高级能力付费天经地义（L2），创作还能赚钱养学习（L3）」——完美回应 V3.0 提出的「免费的东西怎么收费」矛盾：小艺免费不是积分制的死穴，而是把 L1 做成普惠、把收费锚点全部移到真实付费成本的 L2/L3。

**L2 接入清单（用户已定方向）**：
1. 火山引擎多语种语音（西语/墨西哥语对话）——语言类学习用户的独特刚需，「市场上找一个能对话练墨西哥西语的 AI 本身成本就不低」，定价可对标市价打折；
2. DeepSeek / GLM 等强推理大模型——高质量问答与卡片生成兜底；
3. 接入时序：**先小艺（阶段 0）→ 上架前接入火山**（目标双供应商同期可用；火山是 ApiClient 现有 provider，技术零新增，只做商用配置+语音扩展）。

## 3.4 通道选择器与扣点策略（❓小艺扣点推荐方案待用户确认）

**产品形态（用户定案）**：对话界面提供通道选择——用户自选「小艺（省）/ DeepSeek（强）/ 火山语音（专业）」，**每个通道实时显示本次消耗 司忆点数**，让用户自己权衡贵与便宜。

**通道定价框架**（基础点数待 §9 数值清单拍板，梯度关系如下）：

| 通道 | 单次对话消耗（相对值） | 定价依据 |
|---|---|---|
| 小艺 | **1×（基准，极低）** | 免费→象征性扣点（见下） |
| DeepSeek / GLM | 3~5× | 真实 token 成本 + 30% 毛利公式（用户已有换算） |
| 火山多语种语音 | 10~20× | 真实成本高 + 市场稀缺性定价（对标市价打折） |

**★ 小艺通道扣点推荐：象征性扣点 + 每日赠送覆盖（推荐 A'，非纯免费）**

用户直觉「要让他有痛的感觉」是对的，落地为：
1. **小艺也扣点，但压到基准 1×（数量级低于付费通道）**——所有 AI 操作统一走 司忆点经济系统，一套扣费状态机/流水/退款逻辑通吃（工程上省一半复杂度）；
2. **每日打卡/复习赠送的点数 > 日常小艺消耗**——轻度用户永远不缺点、零门槛体感（成本为 0 的平台红利转化为「每日白送额度」）；重度用户超额自然导向充值或升级付费通道；
3. 「1 点痛感」=价值感知锚：用户从第一天建立「AI 是有成本的服务」心智，付费墙（充值/高级通道）的认知阻力最小；纯免费的东西反而不被珍惜，将来加收费阻力更大；
4. **将来小艺若 token 计费，只调小艺通道的点数数值**，整个经济系统零重构（对冲政策风险的软着陆垫）。

> 反方案（纯免费小艺）被否的理由：①免费/付费双轨计费逻辑复杂②「以前免费将来收费」的心理阻力③司忆点经济缺了最大流量入口，与 UGC 购卡脱节④小艺收费时无退路。

## 3.5 求卡广场（小论坛）产品定义（⛔ V5.0 推迟至阶段二；首版替代=§3.6 模块 2）

> 产品定义保留备用（企业主体+ICP 证到位后启用）。首版用「需求提交表单」承接相同用户需求，零社区属性。

**本质：多对多的「知识需求 ↔ 供给」信息对齐平台**——不是 1 对 1 接单悬赏，是需求公示 + 供给响应。

```
需求侧                          供给侧
┌──────────────────────┐      ┌──────────────────────────┐
│ 「我需要刑法总则知识卡片， │      │ 创作者看到需求 →           │
│  谁整理过？愿意出100 司忆点下载」│ ──→ │ ①已有现成卡→直接上架       │
│  （发需求帖+悬赏点数）     │      │ ②没现成但有时间→马上做一套 │
│  其他有同需求者可见可跟     │      │   →审核→挂卡片集市         │
└──────────────────────┘      └──────────────────────────┘
              ↓ 需求帖与卡片集市打通：响应需求的卡直接挂到帖下
```

- **解决两个信息不对称**：①需求方「我要的卡没人做」②创作者「我有时间做但不知道有没有人要」——需求帖=需求聚合器+创作指路牌；
- **多对多**：一个需求帖可以被多人响应/多个版本竞争，一份优质卡可以被所有同需求者反复购买（创作者长尾收入）；
- **与 司忆点经济联动**：悬赏点数=需求强度信号；成交后下载扣点 100% 归创作者（L3 零抽成原则一致）；
- **合规绑定**：求卡广场=信息发布类功能（舆论属性）→ **必须进《安全评估报告》覆盖范围**（DeepSeek §4.2，工单确认个人可做但需安评+内容管控五机制）——开发排期与安评申报周期对齐；
- MVP 边界建议：首发=需求帖（标题/描述/悬赏点数/响应数）+ 跳转卡片集市；评论/关注/私信等社交重功能后置（降低安评与内容审核压力）。

## 3.6 ★ 首版功能范围（V5.0 定稿）：低风险渐进式三模块

**背景（新情报，2026-10-16 豆包稿）**：华为审核规则——APP 内存在 UGC 用户上传、用户公开发布内容、用户互相可见的帖子/求卡广场/BBS 社区功能 → **需要 ICP 增值电信业务经营许可证（仅企业主体可办，个人无法办理）**；缺证直接驳回上架；隐藏功能上架后后台开启 → 触发巡检 → 下架 + 个人开发者账号冻结。**与此前工单/DeepSeek 口径（安评即可）冲突，待工单 Q2 回复终裁；首版按最严口径执行，不赌。**

### 模块 1：卡片集市（自营集市）✅ 首版

- 集市内全部卡包**上架主体=平台（开发者本人）**，全部由开发者/AI 制作、审核后手动入库；**普通用户不能在 APP 内上传卡片文件**。
- 展示：卡包名称/简介/预览/标签/消耗司忆点下载；**仅开放五星星级打分，无任何文字评论、留言**。
- 前台标注「DAG AI Chat 平台整理制作」；**前台不展示用户/创作者 ID、昵称、个人主页**（创作者信息仅后台留存，对外不可见）。
- 司忆点规则：任务获取、下载卡包消耗；**首版不做按下载量自动分成**。

### 模块 2：需求提交表单（替代求卡社区）✅ 首版

- 页面名称「提交卡片需求」，定位=**产品反馈表单**；⚠️ 严禁使用社区/广场/求卡等文案。
- 用户仅能提交文字需求（描述想要的知识卡包主题）；需求**仅后台开发者可见，用户之间互相看不到**；无公共需求列表、无评论、无点赞。
- 后台逻辑：检索平台自营卡库 → 有匹配则通知用户可下载；无匹配收录需求，卡包制作完成后推送通知该用户。

### 模块 3：创作者素材征集（全部剥离至 APP 外部）✅ 首版

- APP 内仅一行文字提示：意向用户通过指定邮箱联系平台；❌ 不提供文件上传入口、不内置微信群二维码/社群入口。
- 流程：邮件投稿意向 → 人工沟通 → 微信私域群 → 微信/邮箱交付素材（**素材传输不走本项目服务器**）→ 签简易内容授权 → 开发者手动导入后台 → 上架自营集市。
- 激励：素材审核入库后**后台一次性人工发放司忆点/券**（征集奖励），**不是按下载次数自动结算**。

### 分阶段上线阈值

1. **阶段一（首版上线，个人主体）**：仅上述三模块，无 APP 内 UGC、无社区。目标=验证核心产品、卡包下载、付费转化数据。
2. **阶段二触发条件**：**稳定月活 ≥1000，且卡包下载/司忆点消耗/付费数据表现正向**。
3. **阶段二动作**：注册公司 → 办 ICP 增值电信业务经营许可证 → AGC 个人应用迁移企业主体 → 大版本迭代开放原生 UGC 上传/创作者广场（求卡广场+100% 分成自动结算）。
4. **不达预期**：维持现状，不再投入 UGC 生态，聚焦核心学习功能迭代。

## ⭐ 下一版本预告：锚点卡片（内部代号：钩子模式）——小艺免费红利的核心变现

> 命名定案：**UI/用户侧=「锚点卡片」（全局设置既有叫法，官方感）；内部开发代号=「钩子模式」（好记，hook 机制描述准确）——两个名字一回事，全队共用映射。**

```
用户提问 ──→ 付费通道（DeepSeek/火山，扣司忆点多）──→ 高质量回答
                                                        │
                     免费小艺 Agent（成本≈0）⟵──────────┘
                     ① 针对回答内容生成「锚点卡片」（知识锚点）
                     ② 卡片中穿插互动问题（小艺生成）
                     ③ 用户答对 → 司忆点奖励 / 等级成长（好奇宝宝→…→领域宗师）

                        针对当前提问内容推荐可复习的存量卡片
```

- **商业闭环**：贵模型的价值被小艺「二次榨取」成复习资产（锚点卡片入库→复习→再消耗/再活跃），一次付费多次回收；

### 12.2 ICP 许可证定性判断与预咨询打法

**有利预期（可先放宽心）**：①监管实践中 ICP 许可证主要针对**网站形态**的经营性信息服务；App 内 IAP 售卖虚拟商品走华为收银台，普遍不被认定为「经营性 ICP」——应用市场里大量个人开发者 AI 应用卖积分/会员在架，是实操层面的旁证②DeepSeek/工单均未给出「需要许可证」的判定，只说「无明确结论」。**但预期≠结论，正式口径必须拿到手。**

**预咨询两步走（兼顾快慢与效力）**：
1. **先问 AI 客服**（即时）：快速拿官方条款依据与口径方向，5 分钟出结果，用于预判；
2. **无论 AI 答什么，必发人工工单**（互动中心）：人工正式回复有记录效力，将来提审遇质疑可作为凭据——**怕等也要发**，工单处理与开发并行，不阻塞任何事。

**问法要点（决定答案质量，两步都用这套）**——把场景说具体，别问笼统的「能不能卖积分」：
> 「我是个人开发者，鸿蒙应用（已实名认证+已开通商户服务），计划：①通过华为 IAP 售卖**消耗型虚拟商品**（司忆点礼包，仅限应用内使用、不可提现不可转让），司忆点用于兑换应用内的 AI 对话/文档解析功能（模型能力来自小艺开放平台及第三方已备案大模型 API）；②应用内提供免费的 UGC 知识卡片分享社区与需求发布区。请问：该模式下是否需要办理《增值电信业务经营许可证》（ICP 许可证）？还是仅需完成 App 备案即可？」
