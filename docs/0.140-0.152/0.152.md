# 内置屏幕圈选标注功能 — 0.119
> 归属版本：v0.1 内部迭代，不升级产品版本号
## 一、需求概述
新增屏幕圈选标注能力，作为第四大产品亮点。

### 底部输入栏UI布局变更（重要）
原底部排序：`+`，输入框，添加图片，模式选择，发送
**修改后底部排序**：`+`，输入框，**画画Icon（屏幕标注能力，核心新增亮点）**，发送
> 发送按钮右侧增加小三角下拉按钮；点击小三角弹出菜单，包含三项：对话模式（2个选项）、回复长度（3个选项）、图片添加。

用户可直接在APP当前屏幕画面上圈选区域、涂鸦标注。圈画标注完成后，提供3种操作选项：
1. 当前对话导入：图片+文字直接追加至当前对话
2. 创建子气泡分支：新建子气泡，继承父节点完整上下文，沿用现有上下文截断规则：10+15，不破坏原有上下文读取逻辑
3. 创建知识库卡片：提取圈选区域内容，提交ai，走存入知识库流程

**核心规则**：圈选生成的消息，图片仅作为辅助参考材料，不会剥离、替换父节点上下文；子气泡沿用项目既定上下文策略，原有底层会话逻辑完全不变，不改动现有后台/消息链路。

本次迭代不做翻译功能：圈选是像素级选取，天然存在边界误差，容易误圈多余文字，会污染单词音标、单词库数据，翻译场景不使用圈选能力，翻译功能不在本次开发范围内。

### 产品亮点定位
1. 第一亮点：气泡树DAG对话架构（底层核心，任意节点分叉，继承上游上下文）
2. 第二亮点：知识库+循环复习体系
3. 第三亮点：全局持久自定义称谓 + 前置上下文学习鼓励
4. 第四亮点：内置屏幕圈选标注提问（一步完成截图、圈画、标注，快速导入当前对话 / 创建子气泡 / 存入知识库，大幅降低重度学习者操作成本）

## 二、核心约束（不可改动，硬性规则）
1. 圈选操作如果选择创建子气泡，强制继承父节点上下文，沿用现有10+15上下文窗口策略，绝不新建无根独立气泡；图片仅作为辅助参考材料发给大模型，原有上下文机制完全保留，底层消息模型不变。
2. 本次迭代不实现圈选翻译功能。圈选存在误识别多余文本的风险，无法达到翻译所需文字精度，会污染单词库、音标数据，翻译能力排除在本功能之外。
3. 圈选图片存储策略：
   - 默认：图片保存在APP私有临时缓存目录，发送成功/存入知识库24小时后自动清理；不会自动写入系统相册
4. 权限：首次使用屏幕圈选，申请鸿蒙屏幕捕获权限，提示文案：用于屏幕圈选标注提问，不会后台录制屏幕。系统隐私页面（密码等页面）捕获会黑屏，做友好提示。

## 三、交互流程
1. ChatPage底部输入栏，点击【画画Icon】，触发屏幕圈选能力。
2. 捕获当前APP屏幕画面，进入涂鸦标注页面，支持画笔圈画、撤销、清空画布。
3. 标注完成，页面提供3个操作选项：
   - ① 当前对话导入：图片带回当前对话，输入框可追加自定义文字，发送后追加到当前对话消息
   - ② 创建子气泡分支：新建子气泡节点，携带标注图片，输入框可追加文字；发送时携带图片 + 父节点完整上下文（10+15规则不变）
   - ③ 创建知识库卡片：调用多模态模型提取圈选区域文本，生成知识库卡片存入本地知识库，不新建对话
4. 发送按钮右侧小三角下拉菜单入口：点击弹出菜单，包含：对话模式（2项）、回复长度（3项）、图片添加。

### 关键技术路线（与文档约束的对应与取舍）
1. **截图路线 — APP 内组件快照，不申请系统截屏权限**：采用 `this.getUIContext().getComponentSnapshot().get('chatSnapshotRoot')` 截取自身界面。原因：系统级截屏权限（CAPTURE_SCREEN）为 system_basic 级，三方应用不可申请；组件快照无需任何权限、无权限弹窗，且天然不存在「隐私页黑屏」问题（只截本 APP 组件树）。捕获失败（组件 id 无效/资源不足）走 try-catch 友好提示「截图失败，请重试」。首次使用仍弹说明弹窗（文案：用于屏幕圈选标注提问，不会后台录制屏幕），定位为功能说明而非权限申请。
2. **图片存储 — base64 data URI 全程内存流转，不用临时目录**：截图 → base64 → data URI，与相册图片消息、知识卡片配图同模式（ChatMessage.imageUrl 既有约定）。相较文档「临时缓存目录 + 24h清理」方案更干净：无临时文件即无清理需求，规避 cacheDir 被系统清理导致图片丢失的风险，重启不丢图；全程不触碰系统相册，天然满足「不写相册」约束。
3. **底层零改动（硬性约束达成）**：`sendMessage`（pendingImages 通道）、`addBubble`（新建子节点+切换）、`buildBranchMessageList`（10+15：THRESHOLD=25/SUMMARY_COUNT=10/RECENT_COUNT=15）、ChatModel/BubbleNode 序列化全部原样复用，未改一行底层逻辑。
4. **流式回复中的防御**：AI 流式输出期间（isLoading）创建分支会被现有 addBubble 防御拦截（防流式回调写错气泡），此时「创建子气泡」降级为「导入当前对话」+ toast 提示，图片不丢失。
5. **本次不做翻译**：未引入任何圈选翻译链路（按文档排除项执行）。
