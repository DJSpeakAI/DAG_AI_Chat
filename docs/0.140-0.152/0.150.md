# 全局设置：AI自定义称呼 + 自动鼓励提示词 — 0.117
> 归属版本：v0.1 内部迭代
## 一、需求背景
增加学习正反馈能力，属于产品小亮点。支持用户自定义AI称呼，以及开启/关闭自动鼓励。
鼓励文本放在AI回复最开头，主体内容在后，符合人性先获取正向激励，再阅读知识内容。
两套页面（ChatPage、BBTreeCanvas）都提供设置入口，打开同一个全局设置弹窗，使用选项卡管理配置。

## 二、功能详细定义
### 2.1 全局设置面板（Tab选项卡）
1. Tab1：API配置（原有配置项）
2. Tab2：AI对话偏好（新增）
    - 自定义称呼输入框：默认空。填写后全局生效；为空时不添加称呼文本。短、中、长全部回复模式都会带上称呼。
    - 自动鼓励开关：默认开启，可手动关闭。
        - 生效范围：仅中回复、长回复模式生效；短回复不生成鼓励语句
        - 关闭状态：无论中/长回复，都不会生成鼓励话术；仅保留自定义称呼（填写时）。

### 2.2 Prompt拼接规则（核心）
AI回复文本结构顺序：
【称呼（可选）】【1~2句鼓励语句】【主体回答内容】

鼓励语句约束：
1. 鼓励放在回复最前面，主体知识内容放在鼓励之后；
2. 鼓励内容必须结合当前对话上下文、当前学习主题（代码/数学/论文等），不能是通用固定套话；
3. 每次生成鼓励话术尽量多样化，避免重复；鼓励适度，允许轻微夸张，不生硬尬聊；
4. 鼓励文字控制在1~2句话，篇幅简短，不能挤占主体回答；
5. 短回复模式：不生成鼓励，仅保留称呼（填写的情况下）。

### 2.3 UI入口规则
1. ChatPage右上角：设置按钮，唤起全局设置弹窗
2. BBTreeCanvas画布页面右上角：设置按钮，唤起完全相同的全局设置弹窗
   两个页面共用同一套全局配置数据，修改一处，两处同步生效，数据持久化保存，App重启保留配置。


## 五、风险&约束
1. 鼓励逻辑依靠系统提示词实现，前端不内置固定鼓励文案库，由大模型实时生成鼓励语句。
2. 鼓励只在中/长回复启用，短回复禁用，避免短文本被鼓励话术挤占。
3. 本次只完成偏好配置和prompt组装逻辑，不改动原有API请求、流式渲染核心流程。

## 二、设计决策

1. **AiPreference 独立 key**：`'ai-preference-v1'`，避开 0.143 教训（往已有磁盘快照的类新增字段不落盘）；全新 key 首次创建即含全部字段。
2. **单组件自包含**：Tab1 表单直接搬进 GlobalSettingsDialog（不拆 ApiConfigPanel 子组件），未保存状态八项（Tab1 六项 + Tab2 两项）组件内直接可查。
3. **自绘 Tab 切换**：@Local currentTab + 两按钮条件渲染（不用 Tabs 组件），选中态高亮同款配色（#1976D2 / #E3F2FD / #1E3A5F）。
4. **遮罩点击不关闭**（0.148 教训防误触丢输入）；**✕ 走 requestClose**：有未保存 → AlertDialog 二次确认 → onClose，无 → 直接 onClose。
5. **返回键路径也走未保存确认**：父组件（ChatPage handleBack / BBTreeCanvas onBackPressed）递增 `closeReq` 计数器 → 弹窗 `@Monitor('closeReq')` 触发内部 requestClose（含确认），不直接丢弃输入。
6. **保存不关弹窗**：保存两 Tab 全部 + toast「已保存」，用户自己 ✕（showToastSafe try-catch 模式，0.149 教训）。
7. **0.139 迁移逻辑随表单搬入**弹窗 aboutToAppear（原在 SettingsPage，其无入口后迁移职责转移；幂等无害）。
8. **Toggle 用 onChange 回调**写 @Local（isOn 仅初始值；不用 $$ 双向绑定，回调模式最稳）。
9. **鼓励位置修正**：需求 2.2 明确「鼓励放回复最开头（先激励后知识）」——prompt 指令与 Tab2 提示文字均按「开头（称呼之后、主体之前）」实现（初版误写「末尾」，装机前已修正）。

## 三、Prompt 拼接实现（核心）

`ChatPage.buildPreferencePrompt()`：按设置生成 system 指令，sendMessage/regenerateMessage 在长度 prompt 之后、播客 prompt 之前追加（不持久化、不进后续上下文，与 0.133/0.144 同机制）：
- 称呼填写时：`请在回答中自然地称呼用户为「XX」。`（短/中/长全部生效）
- 鼓励开启且非 short 时：`在回答的最开头（称呼之后、主体内容之前）附加 1~2 句简短的鼓励话语：必须结合本次对话的具体内容或学习主题（如代码、数学、论文等）给出针对性鼓励，禁止通用套话；每次措辞多样化，避免重复之前用过的表述；允许轻微夸张但不要生硬；篇幅务必简短，不挤占主体回答内容。`
- 两段拼为一条 system 消息 push 进 messagesToSend。
