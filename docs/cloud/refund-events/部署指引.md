# AGC 云函数 refund-events 部署指引（0.291.0 退款感知主链路服务端件）

> 与 track-events 同项目同基建（复用 `cloud-server-deps` 依赖层 + `agc-credential.json` 凭证）。
> 源码：本目录 `handler.js`（部署时拷贝到 `E:\track-events\refund-events\`——**老机器工作目录，凭证绝不入 git**）。
> ⚠️ 全程 AGC 网页操作必须**非无痕窗口**（0.206.x 假提交事故铁律）。

## 架构

```
华为 IAP 服务器（退款完成）
  → POST {jwsNotification} → 本函数 HTTP 触发器 URL（AGC 应用内支付「通知接收地址」）
  → 解码 JWS payload：notificationType=REVOKE + purchaseToken
  → Cloud DB refunds 表 upsert（objectId=purchaseToken，幂等）
  → 立即 200 {"resultCode":"000000"}（防通知重发堆积）

app（IapUtil.pullRefundMarks：启动/回前台/进账单页三时机）
  → cloud.callFunction('refund-events', {action:'query', tokens:[本地包tok]})
  → 命中已退款 tok → writeOffRefundedPackage 核销作废（用户零操作）
```

## 部署步骤（老机器/用户操作）

### ① Cloud DB 建 refunds 表
控制台 → 云开发 → Cloud DB → 对象类型 → 新建 `refunds`：

| 字段 | 类型 | 主键 | 非空 |
|------|------|------|------|
| objectId | String | ✓ | ✓ |
| orderId | String | | |
| environment | String | | |
| signedTime | **Long** | | |
| notifiedAt | **Long** | | |
| raw | String | | |

- 存储 → 确认存储区 `default` 存在（track-events 已建则复用）
- 时间戳必须 **Long**（Integer 32 位装不下 13 位 ms——events 表同坑）

### ② 创建函数
- 云函数 → 创建：名称 `refund-events`、运行时 nodejs、内存 128MB、超时 10s
- 函数代码 → 上传 zip（`handler.js` + `package.json` 打包，**不含 node_modules**——依赖走层）
- 层：挂 `cloud-server-deps`（track-events 已建，同款 cloud-server@1.0.5）
- 凭证：`agc-credential.json` 与函数代码同级上传（或按 track-events 实测方式挂载）
- ⚠️ handler.js 中 Cloud DB API（`db.zone('default').upsert/query`）按 **track-events/handler.js 实测写法**校准——本文件按 cloud-server 标准用法编写，如 API 签名有出入以 track-events 为准改这里

### ③ HTTP 触发器
- 函数 → 触发器 → 创建：HTTP 触发器，**无需鉴权**（华为服务器调用，无法带我们的鉴权；安全靠 JWS 验签+URL 不公开）
- 记录生成的 HTTPS URL（形如 `https://xxx.cn-north-4.agc-connect.../refund-events`）

### ④ AGC 绑定通知地址（关键）
- AGC → **应用内支付服务**（我的项目 → 常用服务 → 应用内支付）→ 激活服务和配置事件通知
- 通知版本必须 **v3**（REFUND_TRANSACTION 子类型仅 v3 有）
- 生产环境服务器地址 = ③ 的 URL；沙盒环境地址也填同一个（沙盒测试退款也走同链路）
- 保存后用「测试服务端通知」功能（notificationType=TEST）验证链路通

### ⑤ 冒烟验证
1. 测试面板贴：`{"action":"query","tokens":"[\"x\"]"}` → 期望返回 `{"refunded":"[]"}`
2. app 侧：真机买 200 万包 → 华为侧退款（沙盒订单在 AGC「订单管理」可直接退/真单走客服）→ 等 REVOKE 通知 → 进账单页看「已自动核销」提示 + SP 作废

## 上线前必做（安全债务清单）

| # | 项 | 说明 |
|---|----|------|
| 1 | JWS 验签 | 当前仅解码不验签（测试期：URL 不公开+伪造无收益）。上线必须按官方「对返回结果验签」补华为支付公钥验签 |
| 2 | 对账 API 兜底 | 服务端定期跑「应用购买记录相关支付订单查询」（180 天窗口）核对 refunds 表漏单 |
| 3 | `raw` 字段清理策略 | 存档量可控（退款频次低），暂留；量大后做归档 |

## 已知边界

- 沙盒通知失败**不重发**（官方文档实锤）——沙盒验证退款时网络抖动可能丢事件，重测即可
- 通知仅是触发器：官方建议收到通知后回调订单状态查询 API 核实——测试期直接信通知（raw 存档可追溯），上线随验签一起补
