## ① Cloud DB 建对象类型（AGC 控制台 → 我的商品 → 云数据库 → 对象类型）

导出默认 zone=`default`，两张表（字段名/类型与 handler.js 类定义一一对应）：

**SpMirror**（主键 objectId String）：
`objectId` String PK ｜ `availableSp` Integer ｜ `frozenSp` Integer ｜ `permSp` Integer ｜ `permCons` Integer ｜ `bonusSp` Integer ｜ `bonusCons` Integer ｜ `giftSp` Integer ｜ `giftCons` Integer ｜ `pkgJson` String ｜ `deviceModel` String ｜ `reportedAt` Integer **（秒级！Integer=32 位，毫秒戳溢出报 3007007——2026-10-23 冒烟实锤）**

**SpLedger**（★ 0.302.0 事件流水，主键 objectId String）：
`objectId` String PK ｜ `accountId` String ｜ `ts` Integer（秒级） ｜ `event` String（grant/consume） ｜ `src` String（sign/welcome/iap/admin/rookie_*/quiz/consume） ｜ `amount` Integer（正=发放 负=消耗） ｜ `pool` String（如 gift:-5000,bonus:-3000） ｜ `balAfter` Integer ｜ `deviceModel` String ｜ `note` String

**SpCommand**（主键 objectId String）：
`objectId` String PK ｜ `target` String ｜ `type` String ｜ `amount` Integer ｜ `note` String ｜ `status` String ｜ `claimedBy` String ｜ `claimedAt` Integer（秒级） ｜ `confirmedAt` Integer（秒级） ｜ `resultAmount` Integer ｜ `createdAt` Integer（秒级）

> 权限：两表全部角色给「读写」均可（函数走管理员凭证不受此限；此表无用户敏感内容）。

## ② 建云函数 sp-admin

1. AGC 控制台 → 云函数 → 创建函数：名称 `sp-admin`（小写中划线铁律），运行时 Node.js 18+
2. 代码：上传 `AI交接/sp-admin-函数全量.zip`（handler.js+node_modules+agc-credential.json 齐装——**勿用控制台裸贴代码**：依赖+凭证都在 ZIP 里）
3. 函数入口：`handler.myHandler`
4. ⚠️ SDK 版本坑（2026-10-23 实锤）：`@hw-agconnect/cloud-server` 新版把实例 API 改为命名导出 `{ cloud }`，≤1.0.5 是顶层导出——handler.js 已双路径兼容，**直接跑新版即可**；若自建同族函数报 `cloud.createInstance is not a function` 就是这个坑
5. 凭证：`agc-credential.json` 在 ZIP 内（项目设置 → Server SDK → 认证凭据下载）

## ⑥ 部署后直调自证（★ 0.309.1 固化——不再靠端侧现象猜版本）

任何会话可在本地用 **Server SDK 直调线上函数**（走现有 HTTP 触发器，无需 AGC 控制台）：

```js
const m = require('@hw-agconnect/cloud-server');
const cloud = m.cloud || m;
cloud.createInstance('<docs/cloud/agc-credential.json 绝对路径>', 'default', m.Region.REGION_CN);
const cf = new m.CloudFunction('default');
// call 只收一个 FunctionParams 对象（name/version/data）——传两个参数=签名错位报 160404 Trigger not exist
const r = await cf.call({
  name: 'sp-admin', version: '$latest',
  data: { action: 'probe', accountId: '<账号ID>', deviceModel: 'LOCAL-VERIFY' }
});
// 新版函数 → { probe: 'y'|'n'|'e' }；旧版 → { ok:false, err:'unknown action' }
```

**触发器事实（2026-10-24 截图实证）**：sp-admin 现有 HTTP 触发器=POST / 鉴权 HDA-SYSTEM / 认证类型 **apigw-client** / URL `/functions/6aekbicn/sp-admin-$latest`——**一个函数只能一个 HTTP 触发器**（再建需审批），本通道够用勿再加。
**踩坑**：①`inst.function()` 不是调用入口，正确类=`CloudFunction`（构造函数参数=AGC 实例名，与 createInstance 名一致）；②`version` 必须传 `$latest`（对应触发器 URL 后缀）；③返回值已是业务对象（SDK 内部已 getValue()），不用再解 responseBody。
