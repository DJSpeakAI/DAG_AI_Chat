# 0.164 华为账号登录（云同步第一步）

> 0.164.1~0.164.7 六轮排查 1001502003 → 0.164.7 收官。**核心教训：DevEco 自动签名=内部调试应用通道，Account Kit 登录必须 AGC 手动申请调试 Profile + 手动签名。**

## 0.164.1 需求与方案

**需求（用户原话）**：华为账号登录 + 云同步，本次先做登录（云同步后续版本）。登录按钮在首页「进入对话画布」下方，登录后显示昵称/ID，支持退出。

**技术方案（Account Kit）**：基于 `@kit.AccountKit` → `authentication`，`createAuthorizationWithHuaweiIDRequest`。

| 项 | 结论 | 依据 |
|---|------|------|
| 登录方式 | `scopes=['profile']`（openid 默认无需传） | 个人开发者可用，无需申请账号权限 |
| 登录后显示 | `nickName` + `openID`/`unionID` 兜底 | 客户端直接返回，无需服务端 |
| 退出账号 | `createCancelAuthorizationRequest()` | 取消授权 + 清本地登录态 |
| 前置配置 | module.json5 `metadata` 配 `client_id` | AGC 应用 Client ID |
| 公钥指纹 | **无需配置** | compatibleSdkVersion≥20 免配（本项目 6.1.1(24)） |

**改动清单**：
1. 新建 `HuaweiAccountUtil.ets`：`HuaweiAccountStore`（PersistenceV2 key `huawei-account`）+ `loginWithHuaweiID`/`logoutHuaweiID`/`errorToTip`
2. 改 `Index.ets`：首页加华为账号登录区（未登录=按钮，已登录=昵称+退出）+ 防连点 + 错误提示
3. 改 `module.json5`：module 层 `metadata` 配 `client_id`（占位值，**拿到真实 Client ID 后替换**）

## 0.164.2~0.164.3 1001502003 根因收口

**现象**：装机后点登录 → 「登录参数异常，请更新后重试」（错误码 **1001502003**）。

**0.164.2 排查**：`scopes=['openid','profile']` → 改 `['profile']` 仍报错，**scopes 非根因**。

**0.164.3 根因（决定性证据）**：

```
安装包 Profile：app-identifier = 6918742736119759756（DevEco 9-19 自动签名时 AGC 自动创建的应用）
代码 client_id = 6917618071300773117（用户 10-03 手动创建的 AGC 应用）
→ 两个不是同一个 → 服务端「Invalid clientId or profile」→ 1001502003
```

**时间线实证**：9-19 首次自动签名时 AGC 上无应用，DevEco 自动创建了包名同名应用；10-03 用户手动又建了一个。Profile 绑定前者，client_id 配后者，不匹配。

**修复（方向 A）**：module.json5 client_id 改为 6918742736119759756。v0.164.2→v0.164.3。

## 0.164.4~0.164.6 方向 A 证伪 → 方向 B（手动签名）

**0.164.4 错误码上屏**：errorToTip 末尾附【code=xxx | 服务端原始 message】→ 服务端原话「Invalid clientId or profile」与根因完全吻合。

**0.164.5 方向 A 证伪**：client_id 对齐 Profile 的 6918742736119759756 后仍报 1001502003 → 该 ID 不是有效 Client ID。**DevEco 自动签名走的是内部「调试应用」通道，无有效 Client ID，自动签名 + Account Kit 走不通。**

**0.164.6 方向 B（官方指定路径）**：官方 1001502003 处理步骤 2 原文「**手动签名**」——AGC 手动申请调试 Profile 绑定真实应用。

- module.json5 client_id 改回 6917618071300773117
- 用户 AGC 手动申请调试 Profile（应用 DAG AI Chat + 调试证书 + MatePad 设备）→ 下载 .p7b
- AI 侧：build-profile.json5 只换 profile 路径，**证书/密钥库/密码全不动**（绕开 .p12 明文密码问题）
- 编译 SignHap 161ms 通过，HAP 内嵌 Profile app-identifier=6917618071300773117 ✅ 与 client_id 一致

## 0.164.7 9568289 最优解：删误加的 READ_PASTEBOARD 权限

**装机报错**：`code:9568289 | install failed due to grant request permissions failed. PermissionName: ohos.permission.READ_PASTEBOARD`

**根因**：AGC 手动申请 Profile 时未勾选受限权限，allowed-acls 为空。grep 实证：代码里 pasteboard 仅 2 处 `setData`（写剪贴板），**无任何 `getData`（读剪贴板）**——READ_PASTEBOARD 属早期误加，删后划词复制/长按复制功能不受影响。

**本轮改动**：
1. module.json5：删除 READ_PASTEBOARD 权限申请（只留 INTERNET）
2. string.json：删 read_pasteboard_reason 资源
3. v0.164.7；versionCode 1000004→1000005

**HAP 验证**：requestPermissions 只剩 INTERNET，现有 .p7b（allowed-acls 为空）即可安装。

## 0.164.7 收官：✅ 登录成功

v0.164.7 装机 → 点「华为账号登录」→ **成功拉起华为账号授权页 → 授权后显示昵称 + 退出账号** 🎉

## 核心教训（0.164 线沉淀）

1. **DevEco 自动签名=内部「调试应用」通道**（Profile 的 app-identifier 非正常 AGC 应用、无有效 Client ID），Account Kit 登录必须 **AGC 手动申请调试 Profile + 手动签名**
2. **手动签名只换 Profile 不换证书**：改 build-profile.json5 的 profile 路径即可，证书/密钥库/密码全不动（绕开 .p12 明文密码问题）
3. **受限权限须 Profile 的 ACL 显式授权**：自动签名自动带上，手动申请须在 AGC 勾选；申请了没用的权限直接删（写剪贴板 setData 无需权限）
4. **错误码上屏（code+服务端原始 msg）是排查利器**，0.164.4 用户提议立大功
