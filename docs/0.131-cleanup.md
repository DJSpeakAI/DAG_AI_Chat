## 二、A 组：消除编译警告（4 处）

上次编译输出 5 条警告，全部可消除：

### A1. ApiClient.ets:164 — `off('headerReceive')` 废弃 ❌→✅

**现状**（cleanupRequest 函数）：

```typescript
httpRequest.off('dataReceive');   // 未弃用，保留
httpRequest.off('dataEnd');       // 未弃用，保留
httpRequest.off('headerReceive'); // ← 'off' has been deprecated
httpRequest.destroy();
```

**核对文档结论**：官方文档明确标注 `on("headerReceive")/off("headerReceive")` 自 **API 8 起废弃**，建议用 `on("headersReceive")/off("headersReceive")`（注意是**复数 headers**）。而 `dataReceive`/`dataEnd` 在文档中**未标记弃用**，无需迁移。

**修改**：

```typescript
httpRequest.off('headersReceive'); // ★ 0.131：API 8 起废弃单数 headerReceive
```

### A2. ApiClient.ets:210 — `on('headerReceive', ...)` 废弃 ❌→✅

**现状**：

```typescript
httpRequest.on('headerReceive', (header: Object) => {
  console.info(`[ApiClient] ③ headerReceive: ${JSON.stringify(header)}`);
});
```

**修改**（事件名改复数，回调不变）：

```typescript
httpRequest.on('headersReceive', (header: Object) => {
  console.info(`[ApiClient] ③ headersReceive: ${JSON.stringify(header)}`);
});
```

### A3. BBTreeCanvas.ets:259 — `AlertDialog.show()` 废弃 ❌→✅

**现状**（长按删除气泡的确认弹窗）：

```typescript
AlertDialog.show({
  title: '删除节点', ...
});
```

**原因**：全局静态 `AlertDialog.show()` 自 API 12 起废弃（警告 `'AlertDialog' has been deprecated` + `'show' has been deprecated`），官方推荐通过 UIContext 调用，避免在多实例/跨窗口场景拿到错误上下文。

**修改**（参数完全不变，仅调用入口变化）：

```typescript
this.getUIContext().showAlertDialog({
  title: '删除节点', ...
});
```

### A4. ChatPage.ets:127/325/674 — `TextAreaController` 设备兼容性警告 ⚠️→✅

**现状**：

```typescript
private inputController: TextAreaController = new TextAreaController(); // line 127，编译警告：
// The system capacity of this api 'TextAreaController' is not supported on all devices
...
this.inputController.stopEditing(); // line 325（发送后收起键盘）
...
TextArea({ text: $$this.inputText, placeholder: '输入问题...', controller: this.inputController }) // line 674
```

**原因**：`TextAreaController` 的系统能力不是全设备支持（官方编译警告原文）。它在本项目里唯一用途是发送后收起键盘（stopEditing）。

**修改**：改用 `focusControl.clearFocus()`（API 9+，全设备支持），行为不变（发送后收键盘）：

```typescript
import { focusControl } from '@kit.ArkUI'; // 追加到现有 import
// 删除 inputController 字段
// line 325 改为：
focusControl.clearFocus(); // ★ 0.131：替代 TextAreaController.stopEditing（全设备兼容）
// line 674 改为：
TextArea({ text: $$this.inputText, placeholder: '输入问题...' }) // 去掉 controller 参数
```

## 三、B 组：数据一致性（1 处）

### B1. ChatModel.ets:181 — `ApiConfig.model` 默认值与预置列表不符 ❌→✅

**现状**：

```typescript
@Trace model: string = 'doubao-pro-32k';
```

**原因**：`doubao-pro-32k` **不在** SettingsPage 的 5 个预置模型列表中（预置第 0 项是 `doubao-seed-2-1-lite-260915`），属早期遗留值。SettingsPage 虽有兜底（找不到就重置为第 0 项，现有用户不受影响），但默认值本身不一致。

**修改**：

```typescript
@Trace model: string = 'doubao-seed-2-1-lite-260915'; // ★ 0.131：与 SettingsPage 预置列表第 0 项一致
```

## 四、C 组：深浅色适配补齐（2 个页面）

**原因**：README 声称「深浅色主题 跟随系统深浅色切换，**全页面适配**」，但两个页面漏了：

### C1. Index.ets 首页 — 硬编码浅色 ❌→✅

**现状**：标题 `#333333`、副标题 `#999999`，背景跟随系统默认。深色模式下白底黑字刺眼，且与 BBTreeCanvas/ChatPage（均已适配）不一致。

| 元素 | 浅色 | 深色 |
|------|------|------|
| 首页背景 | `#FAFAFA` | `#1A1A1A` |

| 「进入对话画布」按钮 | 沿用默认蓝 | 沿用默认蓝 |

### C2. SettingsPage.ets — 整页硬编码浅色 ❌→✅

**现状**：label `#666`、输入框 `#333333`/`#F5F5F5`、下拉面板 `#FFFFFF`、选中项 `#E3F2FD` 等 13 处颜色硬编码。深色模式下白底刺眼。
