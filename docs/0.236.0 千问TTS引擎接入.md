## 一、需求背景与拍板决策

### 1.1 背景

用户有重度 TTS 需求。现有 TTS 为双引擎：云端火山 openspeech（0.232.0 回归）+ 本机 CoreSpeechKit 兜底。用户在**千问 AI 平台**（DashScope 兼容中转，域名 `maas.qianwenaiapi.com`）有账号与 API Key，要求接入其 CosyVoice TTS（模型 `cosyvoice-v3.5-plus`），支持情感/语速/音量调节与用户复刻音色。

### 1.2 用户已拍板的 6 条决策（不可推翻）

| # | 决策 |
|---|---|
| 1 | UI **留在全局设置弹窗 TTS 区**（不独立页面），档位从两档扩为三档：火山引擎 / 通义千问 / 自定义 |
| 2 | 千问引擎走 **HTTP 同步合成**（不做 WebSocket 流式） |
| 3 | 千问档加**试听按钮**（配置当场验证） |
| 4 | **情感/语速/音量只给千问档暴露**，火山档与自定义档不加 |
| 5 | 音色默认=**拉取列表第一个复刻音色**，拉不到兜底官方音色 |
| 6 | 自定义档**维持现状**（=火山协议兼容的自定义端点），仅修 bug |

### 1.3 铁律：三引擎物理互斥

用户原话级要求：**选了哪个引擎就只调哪个，哪怕其他引擎 Key 填得再全也绝不发请求**。分发只看 `ttsProvider` 单一字段（见 §3.1），禁止任何"按 Key 是否存在自动切换"的逻辑。

## 三、技术方案

### 3.1 数据模型（ApiConfig 尾部追加，Schema 铁律：只追加不改不删）

```
@Trace ttsProvider: string = 'volcano';  // 'volcano' | 'qianwen' | 'custom'
@Trace ttsEmotion: string = '开心';       // 千问专属，默认开心
@Trace ttsSpeed: number = 1.0;            // 千问专属 0.5~2.0
@Trace ttsVolume: number = 50;            // 千问专属 0~100
```

- **旧数据迁移**：PersistenceV2 旧快照无新字段时默认值即 'volcano'，与现状（端点推导火山）等价；对已改自定义端点的老用户，首次保存 TTS 区时按现有端点推导写入正确 provider，勿在读取路径做迁移。
- 复用现有字段承载"当前生效引擎"的值：Key=`audioKey`、模型=`audioModel`、音色=`audioVoice`、端点=千问档内置常量（不占 `audioEndpoint`，或存千问端点亦可——**推荐不占**，audioEndpoint 留给火山/自定义体系）。
- 云同步 cfg 行自动携带新字段，老设备收到缺字段 JSON → 默认值兜底，无需 migration。

### 3.2 引擎层：新建 `entry/src/main/ets/utils/QianwenTtsEngine.ets`

**对齐 CloudTtsEngine 骨架复用**（分段 `splitTextForTts(text, 280)` 串行 + base64 缓存 + AVPlayer fd:// 播放 + generation 代际号 stop + session 回调 onStart/onComplete/onError），仅"单段合成"实现不同：

- `POST https://maas.qianwenaiapi.com/api/v1/services/audio/tts`
- 头：`Authorization: Bearer <audioKey>`、`Content-Type: application/json`
- 体（两种形态先实测定，见 §4.1）：`{"model":"cosyvoice-v3.5-plus","input":{"text":"..."},"parameters":{"voice":"<voice_id>","speed":1.0,"volume":50,"emotion":"开心"}}`
- 响应（两种形态先实测定）：二进制 mp3 流（`expectDataType: ARRAY_BUFFER` 直接 base64 入缓存）或 JSON `output.audio` base64
- **情感回退**（仿火山音色回退）：请求带 emotion 报错（音色不支持情感类错误码/信息）→ 去掉 emotion 参数整会话重试一次
- `configured()`：`ttsProvider==='qianwen' && audioKey 非空`（模型空值兜底常量 `cosyvoice-v3.5-plus`，音色空值兜底官方音色）
- 导出单例 `qianwenTts`

**ChatPage 调用点改分发**（唯一调用点 1944 行）：

```
ttsProvider==='qianwen' ? qianwenTts.speak(...) : cloudTts.speak(...)
```

两引擎任一返回 false（未配置）→ 现有本地 LocalTtsEngine 兜底链不动。`stop()` 同理按 provider 分发（或两个都 stop，幂等无害）。

### 3.3 UI：GSD TTS 区三档

1. **档位分段按钮**：火山引擎 / 通义千问 / 自定义（三段并排，现有两段按钮样式扩展；`editTtsProvider` 三值）。
2. **三档独立缓存**（现有 0.232.2 双档缓存机制扩展）：切走时缓存该档全部编辑值（Key/音色/模型档位/情感/语速/音量），切回恢复。缓存存 GSD `@Local`/普通成员（会话级即可，不持久化）。
3. **千问档字段组**（仅 editTtsProvider==='qianwen' 渲染）：
   - API Key 输入框（预填见 §3.5；占位提示 sk-ws- 开头）
   - 模型：TextInput 预填 `cosyvoice-v3.5-plus`（空值引擎兜底该常量；不做下拉，平台模型迭代快手填最灵活）
   - **音色：拉取式下拉**（§3.4）
   - 情感下拉：开心（默认）/ 中立 / 生气 / 悲伤 / 恐惧 / 惊讶（枚举值以 §4.1 实测为准，中文值优先）
   - 语速滑条 0.5~2.0 步进 0.05 默认 1.0（旁显 ×1.0）
   - 音量滑条 0~100 步进 5 默认 50
   - **试听按钮**（§3.5 后述结构）
   - 底部说明小字 + 「打开千问平台 →」外链按钮（浏览器开 `https://maas.qianwenaiapi.com` 控制台，获取 Key/复刻音色入口）
4. **火山档**：字段原样（模型下拉三档、音色按模型档位联动、内置端点）。
5. **自定义档**：原样（接口地址+Key+模型下拉）+ §3.6 bug 修复；音色保持隐藏（0.233.0 规则）。
6. **音色 ID 字段可见性规则更新**：火山档=按模型档位联动（现状不动）；**千问档=音色行恒显示**（拉取式下拉）；自定义档=恒隐藏（现状不动）。GSD 回显逻辑：`editTtsProvider` 从 `apiConfig.ttsProvider` 读（不再从端点推导；端点推导仅作旧数据首迁兜底）。
7. `ttsCloudOn` 标签顺带细化：显示当前引擎名（如「云端已启用·千问」/「云端已启用·火山」），判定改按 `ttsProvider` 对应字段非空。

### 3.4 音色拉取（消灭 VoiceNotFound 坑，用户贴资料实证）

- 音色行 = 下拉框 + 右侧「拉取」小按钮（或点击下拉时 Key 非空即自动拉取，二选一，实现者定，倾向后者+手动刷新钮）。
- 拉取调用：`POST https://maas.qianwenaiapi.com/api/v1/services/audio/tts/customization`，头 `Authorization: Bearer <key>`，体 `{"model":"voice-enrollment","input":{"action":"list_voice","prefix":""}}`。
- 响应取 voices 数组的 `voice_id` + 名称字段（**先实测确认字段名**），渲染下拉：**复刻音色（默认选第一个，§1.2 拍板5）→ 官方音色预置若干（候选 longxiaochun 龙小淳等，实测可用性后定 3~5 个）→ 手动输入…（兜底 TextInput）→ 「去千问平台复刻音色 →」（外链）**。
- 拉取失败中文提示：「拉取失败：请检查 API Key；复刻音色须与 Key 属同一工作空间」。
- 拉到的列表仅存会话内存（每次开弹窗重拉，音色列表不是持久数据）；**选中的 voice_id 落盘 audioVoice**。

### 3.5 试听按钮

- 千问档内「试听」按钮：以当前表单值（未保存也用编辑副本值）走 QianwenTtsEngine 完整合成+播放链路，文案「你好，这是千问语音试听」。
- 出声=配置即验；失败=toast 中文错误（401→Key 无效；VoiceNotFound→音色与 Key 工作空间不一致）。
- 试听中按钮态变「停止」，再点停止（复用引擎 stop 幂等）。

### 3.6 bug 修复：自定义档干净起点补全

- 切「自定义」时：`editTtsModelSel = TTS_MODEL_PRESETS.length`（落"自定义…"档）+ 清 Key/端点/音色（现状已有）。
- 切回「火山」时：恢复缓存含模型档位（缓存结构加 modelSel/modelText）。
- 千问档切换同理走三档缓存机制，天然规避同类问题。

### 3.7 config.json 预填（开发测试期）

- `rawfile/config.json` 新增 `"qwenTtsKey": "sk-ws-..."`（完整值见桌面副本/用户；**本正本打码**）。
- `loadBuiltinApiConfig()` 扩展：`ttsProvider==='qianwen' && audioKey 为空` 时用 qwenTtsKey 填充（沿用"用户自定义值优先"纪律）。
- **默认提供商保持 'volcano' 不变**——预填只是让用户切到千问档时 Key 已就位，不打扰现有火山体验。
- **上架前清单**：config.json 删 qwenTtsKey 字段；桌面副本删除。

## 四、千问平台协议细节（⚠️ 落码前先实测，勿猜）

### 4.1 三条实测 curl（用 config.json 的 Key，本机终端跑）

```bash
# ① 合成——input 两种形态各试一次，看哪个 200；同时确认响应是二进制流还是 JSON
curl -X POST https://maas.qianwenaiapi.com/api/v1/services/audio/tts \
  -H "Authorization: Bearer <KEY>" -H "Content-Type: application/json" \
  -d '{"model":"cosyvoice-v3.5-plus","input":{"text":"你好，测试"},"parameters":{"voice":"longxiaochun","speed":1.0,"volume":50,"emotion":"开心"}}' -o t1.mp3 -w "%{http_code} %{content_type}\n"
# （若 400 再试 input 裸字符串形态："input":"你好，测试"）

# ② 情感值验证：emotion 分别传 "开心" 与 "happy"，以 200 者定枚举
# ③ 音色列表
curl -X POST https://maas.qianwenaiapi.com/api/v1/services/audio/tts/customization \
  -H "Authorization: Bearer <KEY>" -H "Content-Type: application/json" \
  -d '{"model":"voice-enrollment","input":{"action":"list_voice","prefix":""}}'
```

实测要定死的三件事：① input 形态（对象/裸串）② 响应形态（二进制 mp3 / JSON output.audio base64）③ 情感枚举（中文/英文）。**全部以 curl 实测为准写进引擎代码，资料文档与实际 API 有出入时信实测。**

### ★ 4.1 实测终稿（2026-10-14 深夜 28+ 次探测定案——本文档上述预设全被推翻）

| 事项 | 实测结论 |
|---|---|
| 中转域名 | **maas.qianwenaiapi.com 对 TTS 合成全路径 url error、WS api-ws 吞帧——完全不可用**（仅 customization 音色管理通） |
| 可用域名 | **sk-ws- Key 直通百炼官方 `dashscope.aliyuncs.com`**（同一复刻音色池，list_voice 双域名同池实证） |
| 合成端点 | `POST /api/v1/services/audio/tts/SpeechSynthesizer`（HTTP 同步，鉴权 Bearer） |
| 请求体 | 参数**全在 input 内**：`{model, input:{text, voice, volume:0-100, rate:0.5-2.0, instruction:"用开心愉悦的语气说"}, parameters:{format:"mp3"}}` |
| 情感 | **无 emotion 枚举字段**——用 `instruction` 自然语言指令（200 实证）；UI 情感下拉=档位映射指令文案 |
| 响应 | JSON `output.audio.url` = OSS **mp3** 下载链接（format=mp3 生效）→ GET 下载音频字节 |
| 音色 | **cosyvoice-v3.5-plus 无系统音色**——官方音色 longxiaochun 同报 418；voice 必须是复刻 voice_id；音色错误形态=HTTP 400 message 含 "Engine return error code: 418" |
| 音色列表 | `POST /api/v1/services/audio/tts/customization`（body `{model:"voice-enrollment", input:{action:"list_voice", prefix:""}}`）→ `output.voice_list[].voice_id/target_model/status`（**无名称字段**） |
| 其他 | 连发 3 段无限流；401=Key 无效；qwen3-tts-flash 不支持复刻音色（用户底线确认） |

（背景补充：千问平台客服与 DeepSeek/豆包三方回答互有出入，最终以本机实测为准；用户拿着提问工单问过阿里客服确认了官方端点与 instruction 参数方向。）

### 4.2 已知错误形态（转友好中文提示）

- HTTP 401 / InvalidApiKey →「API Key 无效」
- VoiceNotFound →「音色不存在：请用拉取按钮选择音色；复刻音色须与 Key 同一工作空间」
- 情感不支持类报错 → 引擎自动去 emotion 重试一次（§3.2）

## 五、新用户完整操作旅程（★ 用户强调必须写清：零基础、未登录过任何账号的第一次）

**前提认知（先讲清，防误解）**：千问 TTS **没有"绑定账号/授权登录"环节**——APP 与平台之间只靠 **API Key** 通信（Key 即身份），不像华为账号那种 OAuth 登录态。**唯一需要登录千问平台网页的场景是"复刻自己的音色"**（录音上传必须网页做），日常合成调用永远只认 Key。

| 步骤 | 用户操作 | APP 侧对应 |
|---|---|---|
| ① 注册平台 | 浏览器打开千问 AI 平台（maas.qianwenaiapi.com），手机号注册 | 千问档底部「打开千问平台 →」外链直达 |
| ② 拿 API Key | 平台控制台 → API Key 管理 → 创建/复制（sk-ws- 开头） | 同上外链；输入框 placeholder 提示格式 |
| ③ 复刻音色（可选） | 平台网页的音色复刻/声音克隆功能：浏览器录音 10~20 秒 → 起名（如 guagua）→ 等状态 OK | 拉取下拉尾部「去千问平台复刻音色 →」外链 |
| ④ APP 配置 | 设置 → API 配置 → 展开「语音朗读（TTS）」→ 切「通义千问」→ 粘贴 Key | 开发期 Key 已预填（§3.7），正式版用户手粘 |
| ⑤ 选音色 | 点音色下拉（自动/手动拉取）→ 复刻音色在前，默认选第一个；没复刻过就选官方音色 | §3.4 拉取式下拉 |
| ⑥ 调参数 | 情感默认开心；语速/音量滑条随好 | §3.3 |
| ⑦ 试听 | 点「试听」→ 出声即成 | §3.5 |
| ⑧ 保存 | 点弹窗底部「保存」 | 现有 saveAll 链路 |

**开发期预填现状**：用户（开发者本人）的 Key 已放 config.json `qwenTtsKey`，装机即就位；正式上架前删除，用户走 ①-⑧ 全流程。

**故障排查表**（写进 APP 内提示文案的依据）：

| 症状 | 原因 | 处理 |
|---|---|---|
| 拉取音色列表为空 | Key 与复刻音色不在同一工作空间 / 没复刻过 | 确认同空间；或直接用官方音色 |
| VoiceNotFound | 手填了网页展示名（非 voice_id） | 用拉取下拉选，勿手抄网页名称 |
| 401 | Key 错/失效 | 重新复制 Key |
| 试听无声且无报错 | 设备静音 | 检查媒体音量 |
