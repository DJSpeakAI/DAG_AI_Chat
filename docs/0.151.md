# 画布多树模式切换（气泡选项卡） — 0.118
> 归属版本：v0.1 内部迭代
## 一、需求背景
当前画布支持多个顶级根气泡平铺，根节点增多后画布拥挤杂乱。新增两种画布管理模式，用户可在全局设置自由切换，用来管理多棵独立DAG气泡树。
默认模式：多根平铺模式（原有逻辑，降低新用户认知负担，突出DAG多根并行概念）；可选模式：选项卡多树模式。

## 二、功能详细定义
### 2.1 全局设置入口
全局设置弹窗 → Tab2 AI对话偏好，新增单选配置项：
- ○ 多根平铺模式（默认）
- ○ 选项卡多树模式

切换模式仅改变画布渲染与UI交互逻辑，底层气泡树数据持久化保存。

### 2.2 模式A：多根平铺模式（默认）
1. 画布内可同时存在多棵独立气泡树，所有顶级根气泡在画布同一行对齐并排展示。
2. 右上角按钮功能：【添加根气泡】，点击直接在画布新增一个顶级根节点（新树）。
3. 无顶部Tab选项卡栏。
4. 原有所有Canvas能力保留：拖拽、缩放、节点高亮、分叉子气泡逻辑不变。
5. 子气泡创建唯一入口：进入Chat对话页面添加子气泡，画布页面不提供新增子气泡入口。

### 2.3 模式B：选项卡多树模式
1. 画布顶部出现Tab选项卡栏，一个Tab对应一棵完整独立气泡树，树之间数据完全隔离。画布同一时间只渲染当前选中Tab对应的气泡树。
2. Tab操作：
    - Tab栏末尾加号按钮：点击新增Tab，自动创建一棵全新气泡树，自带空白根气泡，对话内容为空。
    - Tab标签支持重命名：用户可编辑每棵树的名称；UI文字溢出时自动截断，末尾展示省略号。
    - Tab可删除：删除Tab同步删除整棵气泡树全部数据。
    - Tab栏支持左右横向滚动：当Tab数量较多（例如10、20个），超出可视区域时，Tab栏可以左右拖动平移，保证所有Tab都能被访问点击，不会出现部分Tab看不见、点不到的问题。
3. 右上角【添加根气泡】按钮隐藏；新增树只能通过Tab栏加号创建。
4. 原有Canvas能力全部保留：拖拽、缩放、节点高亮、分叉子气泡逻辑不变。
5. 子气泡创建唯一入口：进入Chat对话页面添加子气泡，画布页面不提供新增子气泡入口。

### 2.4 模式切换核心规则
1. 平铺 → 切换到选项卡模式：销毁顶部所有Tab标签。切换进入选项卡模式后，需要用户重新创建Tab，每新建Tab生成独立气泡树。原有的多棵根气泡数据不会删除，保留在底层存储。
2. 选项卡 → 切换到平铺模式：移除顶部Tab选项卡栏，底层全部气泡树的根气泡，统一在画布同一行并排对齐渲染。
3. 模式切换只是UI交互形态变更，底层气泡树数据不会被自动删除。只有用户手动删除Tab/手动删除气泡节点，才会销毁数据。
4. 用户切换模式后，模式状态持久化保存，App重启保持上次选择。


## 五、风险&约束
1. 两种模式切换不会自动把旧树映射为Tab，简化数据绑定逻辑，降低复杂度。
2. 子气泡创建入口固定，仅Chat对话页面可以创建子气泡，画布页面不能新增子气泡。
3. Tab文字溢出截断处理，文字超长省略，长名称完整编辑功能保留，UI展示做裁剪。
4. Tab横向滚动仅针对Tab栏本身，不影响画布内气泡节点的缩放拖拽。

## 实施记录（★ 0.151，2026-10-03 完成）

### 架构：两池隔离 + 工作区单例

- **平铺池** = `PersistData.bubbleTreeJson`（现状不动，存平铺视图的全部树）
- **Tab 池** = `TabForestStore.tabsJson`（存选项卡视图每个 Tab 的独立树；字符串持久化与 bubbleTreeJson 同模式，避免嵌套 @ObservedV2 类持久化风险）
- **工作区** = `'bubble-tree'` AppStorageV2 单例（现状不动）：切模式/切 Tab 只换工作区内容，**两池数据永不互搬互删**（满足需求 2.4.3「切换只是 UI 形态变更，数据不自动删除」）
- 全部新增持久化类用全新 key（0.143 教训）：`canvas-mode-v1`（CanvasModeStore：@Trace mode 'flat'|'tabs'）+ `tab-forest-v1`（TabForestStore：@Trace tabsJson、@Trace activeTabId）

### 需求 2.4.2 解释决策（重要）

「选项卡→平铺：底层全部气泡树的根气泡统一平铺渲染」采用**两池隔离解释**：切回平铺时只渲染平铺池的树，Tab 树留在 Tab 池不混入。理由：与 2.4.1 对称（平铺→选项卡时平铺树保留底层、Tab 需重建；反向同理），与约束 1「不自动把旧树映射为 Tab」精神自洽（反向也不自动映射）。两模式数据各自保留、互不删除。
