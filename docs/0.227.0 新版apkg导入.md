# 0.227.0 新版 apkg 导入（Anki 24.11+ zstd 解码）

> 2026-10-12 立项。0.225.0 破案遗留专项：新版 Anki（24.11+）导出的 .apkg 只能读出 1 张「请更新」垃圾卡（17MB 包），用户拍板本轮开发+Pad 实测收官。用户原话任务：①读取新版 apkg 内容（客户下载的都是新版）②Pad 上实测 apkg（TXT/CSV/XLSX 已测过不再测）。

## 需求分析

**新版 apkg 结构（0.225.0 + 本轮 Node 基准实测，两个真实包：自定义学习的进程.apkg 17MB / 范围辅助练习.apkg 1.2MB）**：

| 部件 | 旧版（≤2.1.x） | 新版（24.11+，meta format=3） |
|---|---|---|
| 集合库 | collection.anki2（明文 SQLite） | **collection.anki21b（ZSTD 压缩，魔数 28 b5 2f fd）**；anki2 仅剩 1 张「请更新」兼容空壳 |
| deck 名 | col 表 decks 列 JSON（`::` 分层） | **decks 表（id/name 列）**；col.decks 为空串；**层级分隔符变 `\x1f`**（"Daily Dose of GTO\x1fCash"） |
| media 清单 | media 文件 = JSON `{"0":"a.png"}` | **media 文件 = ZSTD 压缩 + protobuf**（repeated field1 条目{1:fname,2:size,3:sha1}，**条目顺序=zip 编号**——两包 SHA1 全量匹配 51/51、204/204 实锤） |
| 媒体文件 | 明文图片 | **每个编号文件单独 ZSTD 压缩**（两包 255/255 全 zstd） |
| notes/cards 表 | — | 结构与旧版同构（flds 分隔符仍 \x1f），解析零改动 |

**基准数据（sql.js 实测，作验收对照）**：
- 范围辅助练习.apkg：notes 26 / cards 26 / decks：Default +「范围辅助练习」；26 张全纯图卡（正反面都是图）
- 自定义学习的进程.apkg：notes 38 / cards 38 / decks：Default +「Daily Dose of GTO」+「Daily Dose of GTO::Cash」+「自定义学习的进程」；媒体 204 张、解压 22.3MB

## 设计

1. **ZstdUtil.ets（新增）**：fzstd 0.1.1（101arrowz，MIT）纯 TS 解码器移植 → ArkTS。仅导出 `zstdDecompress(u8): u8` + `u8Copy`。移植纪律：无解构/无逗号表达式/无表达式内赋值/全部显式类型/函数级唯一 return 结构类化（FseTable/HufTable/ZFrameState）。
2. **ApkgUtil.ets 改造**：
   - 检测 `collection.anki21b` → zstd 解码 → SQLite 魔数校验（`SQLite format 3\0`）→ 落盘 `decoded.anki2` → relationalStore rootDir 打开（复用 0.208.0 破局路径）
   - deck 名：先试 `SELECT id, name FROM decks`（新 schema；无 unicase 排序需求，纯读无排序不受自定义 collation 影响）→ 失败回落 col JSON（旧 schema）；**新格式 deck 名 `\x1f` → `::` 归一**（ensureFolderPath 零改动）
   - media 清单：zstd 魔数分流 → 新版 protobuf 解析（条目序号=zip 编号）/ 旧版 JSON
   - 媒体读取：zstd 魔数检测 → 解码后 base64（旧版明文直读不回归）
   - **纯图正面兜底**（小包 26 张全图卡暴露的既有缺口）：正面清洗后无文本但有图 → 标题用正面图文件名 stem（去扩展名/去尾部 -hash，须含中文/空格/括号过滤 paste-、纯 hash 名）→ 否则「图片卡」；图仍走 titleImages 图对图通道
   - 收尾 store.close() 再清目录
3. **KnowledgeBankPage 零改动**（parseApkg 全内部消化；toast 文案「大包可能几十秒」已覆盖 zstd 解码耗时）。

## 风险点

- **zstd 解码性能**：22MB 媒体逐文件解码在 UI 线程同步执行（沿用 0.208.0 同步 IO 模式；Node 实测 ~2s，ArkTS 预计数秒级，toast 已提示「大包可能几十秒」）。若 Pad 实测不可接受再议 taskpool。
- **媒体 base64 总量 ~30MB**（大包 204 图）：Pad 内存可承受；**手机端有 0.211.1 前科**（9 张原图直塞崩溃）——本轮只管 Pad 实测，手机端大包导入后续可加「导入时压缩」（复用 0.211.1 选图压缩思路），先记风险不实施。
- fzstd 窗口上限 2145386496（~2GB）：Anki 默认压缩级远达不到，安全。
- unicase collation：SELECT 无 ORDER BY/COUNT 不触发（sql.js LIMIT 实证）；RDB 同为 SQLite，且 decks 表读取失败有 col JSON 回落兜底。
