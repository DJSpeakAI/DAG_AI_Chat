## 二、根因分析

问题不在「没计算气泡」——包围盒计算逻辑一直是对的，**错在参照系**：

### 根因 1：用「整屏尺寸 + 写死 topSafePadding=120vp」估算可视区 ❌

旧代码：

```typescript
const screenWidth = px2vp(display.getDefaultDisplaySync().width);
const screenHeight = px2vp(display.getDefaultDisplaySync().height);
const viewHeight = screenHeight - this.topSafePadding; // topSafePadding = 120，拍脑袋常量
```

**原因**：`display.getDefaultDisplaySync()` 拿的是**整块屏幕**的尺寸，而画布 Stack 实际渲染在 NavDestination 标题栏之下（还有系统状态栏、虚拟导航条）。用 `120vp` 这个写死常量去估算「状态栏 + 标题栏」高度，与真实标题栏高度对不上，估算出来的「可视区中心」整体偏移 → 图3 单节点落在屏幕中下方。

### 根因 2：`Math.max(topSafePadding, calculatedY)` 截断破坏居中 ❌

旧代码：

```typescript
this.canvasOffsetY = Math.max(this.topSafePadding, calculatedY); // ★ 不低于安全区，防 Pan 跳变
```

**原因**：当树稍大时，`calculatedY` 会小于 120，被 `Math.max` 强制钳到 120，结果树顶贴住可视区顶部而不是居中 → 图2「显示全部」后位置不对。这个截断把「居中」退化成了「置顶」。

### 根因 3：缩放下限 0.3 导致大树无法完整显示 ⚠️

旧代码 `Math.max(0.3, Math.min(scaleX, scaleY, 1.0))`：当树特别大时，按 0.3 最小缩放仍放不下屏幕，「显示全部」名不副实。

## 三、改动内容

### 1. 新增画布真实尺寸状态 + onAreaChange（替代整屏估算）

```typescript
// ★ 0.130 画布可视区真实宽高（onAreaChange 获取，替代整屏尺寸 + 写死标题栏高度估算）
@Local viewW: number = 0;
@Local viewH: number = 0;
```

内层画布 Stack 挂上 `onAreaChange`，直接拿组件布局后的真实宽高（自动适配任何标题栏高度、状态栏、虚拟导航条）：

```typescript
.onAreaChange((oldVal: Area, newVal: Area) => {
  this.viewW = newVal.width as number;
  this.viewH = newVal.height as number;
  if ((oldVal.width as number) <= 0 && this.viewW > 0) {
    this.fitViewport(); // 首次拿到画布尺寸时自动适配全树视口
  }
})
```

**为什么坐标能直接用真实尺寸**：气泡用 `.position()` 定位，坐标系是相对内层画布 Stack 左上角，`onAreaChange` 拿到的正是这个 Stack 的尺寸，两者天然同系，无需任何补偿常量。

### 2. fitViewport 重构（核心修复）

```typescript
fitViewport(): void {
  if (this.store.nodeList.length === 0) return;
  if (this.viewW <= 0 || this.viewH <= 0) return; // 画布尺寸未就绪时跳过

  // 计算画布坐标包围盒（不变）
  let minX = Infinity, maxX = -Infinity, minY = Infinity, maxY = -Infinity;
  for (const node of this.store.nodeList) { /* ... */ }

  const treeCenterX = (minX + maxX) / 2;
  const treeCenterY = (minY + maxY) / 2;

  // ★ 缩放：以画布真实尺寸为准，去掉 0.3 下限，任何大小的树都完整可见
  const treeW = maxX - minX + 60;
  const treeH = maxY - minY + 60;
  this.canvasScale = Math.min(this.viewW / treeW, this.viewH / treeH, 1.0);

  // ★ 树几何中心对齐画布正中，-30 气泡左上角定位补偿；去掉 Math.max 截断
  this.canvasOffsetX = this.viewW / 2 - treeCenterX * this.canvasScale - 30;
  this.canvasOffsetY = this.viewH / 2 - treeCenterY * this.canvasScale - 30;
}
```

### 3. 清理死代码

| 删除项 | 原因 |
|--------|------|
| `private readonly topSafePadding: number = 120` | 参照系已改为画布真实尺寸，常量失效 |
| `import { display } from '@kit.ArkUI'` | fitViewport 不再读取整屏参数 |
| `aboutToAppear()` 中的 fitViewport 调用 | 首调时机移到 `onAreaChange` 首次回调（组件创建时画布尺寸尚未确定，此时调用必然被 `viewW<=0` 保护挡住，等于死代码） |

## 五、明确不动的部分

| 项 | 原因 |
|----|------|
| 手动缩小后气泡重叠（图1） | 气泡直径固定 60vp 不随缩放变小，缩太小重叠是预期行为 |
| Pan 拖拽 / Pinch 缩放手势 | 逻辑不受影响；fitViewport 后再点按钮可随时回到居中 |
| `-30` 半径补偿 | 气泡 `.position()` 定位左上角，必须补偿 60vp 直径的一半 |
| `treeW/treeH` 的 `+60` | 包围盒计入气泡直径，保留 |
| onShown 中 needsRelayout 分支 | 逻辑不变，仅受益于 fitViewport 内部修正 |
