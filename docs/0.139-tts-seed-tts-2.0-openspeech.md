# 0.139 TTS 修复（第六轮）：换官方 2.0 协议（openspeech HTTP 单向流 + seed-tts-2.0）

> 状态：**待用户审批**——批准后才动代码。
> 前置：0.138 方案作废（用户找到的官方文档证明「语音合成-2.0」不在方舟 audio/speech 端点上，控制台拿 ID 填旧端点无用；幸好 0.138 未实施，零损失）。
> 决定性证据：用户提供的官方文档《豆包语音合成大模型 2.0（Doubao-Seed-TTS 2.0）概览》（2026-10-02）。

## 一、404 之谜的最终答案

| 问题 | 答案（来自官方文档） |
|---|---|
| 「语音合成-2.0」的模型资源 ID | **`seed-tts-2.0`**（声音复刻 2.0 为 seed-icl-2.0） |
| 它在哪个端点服务 | **`https://openspeech.bytedance.com/api/v3/tts/unidirectional`**（HTTP Chunked 单向流，最常用），**不在**方舟 `ark.cn-beijing.volces.com/api/v3/audio/speech` |
| 怎么鉴权 | 三个请求头：`X-Api-Key`（控制台 API Key 管理，即现有方舟 Key）+ `X-Api-Resource-Id: seed-tts-2.0` + `X-Api-Request-Id`（客户端生成的 UUID） |
| 音色怎么传 | 请求体 `req_params.speaker`，2.0 音色格式如 `zh_female_vv_uranus_bigtts`；**2.0 模型只能用 2.0 音色，不可混用 1.0 音色**（代码里的 zh_female_cancan 是 1.0 格式，必须换） |
| 响应什么格式 | Chunked 流式返回 **base64 编码音频**（data 字段）；`code=0、message=OK` 表示成功；响应头 `X-Tt-Logid` 用于排查 |

两次真机 404（0.134、0.137）的完整解释：**模型与端点是绑定的**——播客模型在 openspeech 的 WebSocket 端点，合成 2.0 模型在 openspeech 的 HTTP 单向流端点，方舟的 audio/speech 端点两个都不服务。0.134 采纳的开源证据（clipforge/Mora 的 doubao-tts 配置）与官方体系不符，弃用。

## 二、改动点明细（3 文件 + 1 配置）

### ① ChatModel.ets（ApiConfig 三个默认值）

| 字段 | 旧值（0.136/0.137） | 新值 |
|---|---|---|
| `audioEndpoint` | `https://ark.cn-beijing.volces.com/api/v3/audio/speech` | `https://openspeech.bytedance.com/api/v3/tts/unidirectional` |
| `audioModel` | `doubao-tts` | `seed-tts-2.0`（语义变为 Resource-Id） |
| `audioVoice` | `zh_female_cancan`（1.0 格式） | `zh_female_vv_uranus_bigtts`（2.0 格式，文档示例音色） |

### ② ApiClient.ets（synthesizeTTS 重写请求层，响应层小改）

**请求层（换协议）**：
- 请求头删 `Authorization: Bearer`，改为三件套：
  - `X-Api-Key: <现有方舟 Key>`
  - `X-Api-Resource-Id: seed-tts-2.0`（取 config.audioModel）
  - `X-Api-Request-Id: <UUID>`（@ohos.util 的 UUID 生成 API，实施时按编译器建议确定具体函数名）
- 请求体从 OpenAI 风格 `{ model, input, voice }` 改为官方格式：
  ```json
  { "req_params": {
      "text": "<分段文本>",
      "speaker": "<config.audioVoice>",
      "audio_params": { "format": "mp3", "sample_rate": 24000 }
  } }
  ```

**响应层（适配 base64 流）**：
- Chunked 响应会被 `http.request()` 自动聚合为完整 body（无需改流式接收）
- 解析：从完整响应体中提取所有 `data` 字段的 base64 音频片段 → 逐段 base64 解码 → 按序拼接为完整音频 ArrayBuffer → 走现有返回链路
- 校验：响应含 `code=0`/`message=OK` 视为成功；无 data 或 code≠0 走失败回调
- **调试消息（★ 0.136-DEBUG）原样保留**：URL/model/voice/文本长度/阶段/HTTP 码/响应体前 300 字符——不确定点靠它实测定位

### ③ ChatPage.ets：**零改动**

分段流水线（280 字分段）、playSegment（mp3 临时文件 + fdSrc 播放）、addTTSDebugMessage 调试消息全部保留——mp3 格式与现有播放链路兼容。

### ④ SettingsPage.ets（小改）

- `AUDIO_MODEL_LIST` 显示名：`Doubao-语音合成` → `Doubao-语音合成2.0`（id 为 seed-tts-2.0）
- 旧值自动迁移：`doubao-tts` → `seed-tts-2.0`；旧 ark 端点 → 新 openspeech 端点（aboutToAppear 迁移逻辑，用户无感）
