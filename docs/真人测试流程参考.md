## 流程 01：手机首启全链路走查（2026-10-24 口述，0.305.1 实测，0.305.2 修复）

**实测设备**：手机畅享90Pro Max（180 测试账户线）
**环境前置**（用户特意构造）：
1. 华为账号 → 云空间 → 应用数据共享，把 DAG AI Chat 的共享**关掉**（模拟无云环境/新账号状态）
2. 更新 app 到最新版（覆盖安装）；从头测=设置→关于→法律条款→「撤回同意」回到门禁态（或卸载重装）

### 场景 1：老用户更新直入
| 项 | 内容 |
|---|---|
| 前置 | 已同意协议的老用户，覆盖更新 |
| 步骤 | 更新完点开 DAG |
| 实测 | 直接进 DAG 主界面；侧边栏版本号（V0.305.x）清晰可读 ✓ |
| 预期 | 不重弹协议门禁；版本号三处同步可核对 |

### 场景 2：门禁页·未勾选点「华为账号登录」
| 项 | 内容 |
|---|---|
| 前置 | 门禁态（未同意协议），勾选框未勾 |
| 步骤 | 直接点主按钮「华为账号登录」 |
| 实测 | 按钮抖三抖 + 提示（0.305.1 文案「请先勾选同意上述协议」——**用户指出 bug：协议在按钮下方，不叫"上述"**） |
| 预期（0.305.2+） | 抖三抖 + 「请先勾选并同意协议」；不发任何登录请求 |

### 场景 3：门禁页·未勾选点「暂不登录，先本地使用」★合规红线场景
| 项 | 内容 |
|---|---|
| 前置 | 门禁态，勾选框未勾 |
| 步骤 | 点「暂不登录，先本地使用」 |
| 实测（0.305.1） | **bug：直接放行**，协议被静默标记同意，落到首页正常态（进入气泡树+登录华为账号页）——用户定性「不打勾不同意隐私协议怎么可以使用，大 bug」 |
| 预期（0.305.2+） | 与登录按钮同款：抖三抖 + 「请先勾选并同意协议」，不放行 |

### 场景 4：未同意协议状态下的功能失守连环（0.305.1 实测 bug 链）
用户顺着场景 3 的漏洞继续走查，验证失守范围：
- 首页正常态点「进入气泡树」→ **能进主界面**（未同意协议照常使用 ✗）
- 未登录华为账号 → 云同步入口**能开启**（✗ 应被登录守卫拦截）
- 点性格测试（测试题目）入口 + 引导「前往开启」→ 链路完全不对（✗）
**预期（0.305.2+）**：场景 3 拦死后本链整体断根（进不了主界面）；测试台回归时仍应逐项验证：未登录开云同步=引导登录弹窗而非可开启；性格测试等 SP 功能走 SiyiGate 门卫

## 流程 02：手机门禁态视觉+负反馈走查（2026-10-24 二测口述，0.305.3 实测，0.305.4 修复）

**环境注意（用户痛点）**：每次冷装 DAG 后，华为云空间里该应用的数据共享会自动恢复勾选——用户为模拟未云环境每次都要去关一次（设置 → 华为账号 → 云空间 → 应用数据共享 → DAG AI Chat 关）。测试台冷装用例的前置清理可参考此点。

### 场景 1：门禁首屏观感
| 项 | 内容 |
|---|---|
| 实测（0.305.3） | 整体视觉重心偏上；下块（协议勾选行/不同意退出/版本号）显得大且位置偏上 |
| 拍板（0.305.4 已实施） | 上部整块（品牌 → 暂不登录）下移（顶部弹性 1→1.6）；下块字号缩小一圈（协议行/不同意退出 13→12、版本号 12→11、行高 20→18）+底部弹性缓冲不贴底 |

### 场景 2：勾选态反馈（正向）
| 项 | 内容 |
|---|---|
| 步骤 | 点勾选框打勾 → 再取消勾选 |
| 实测 | 打勾后「华为账号登录」按钮变亮（品牌实底白字）；取消恢复描边透底——**用户认可「这个还是不错的」**，两态设计保留 |

### 场景 3：未勾选点两个按钮的负反馈（核心拍板）
| 项 | 内容 |
|---|---|
| 前置 | 勾选框未勾 |
| 步骤 | ①点「暂不登录，先本地使用」②点「华为账号登录」 |
| 实测（0.305.2~3） | 按钮各自抖动+红色提示文字「请先勾选并同意协议」 |
| 拍板（0.305.4 已实施） | **抖动设计保留但锚点统一迁到「我已阅读并同意」协议勾选行**（抖"要去勾的地方"比抖按钮更直观引导）；红色提示文字删除（抖动即提示）。未勾选时任何放行按钮点击=协议行抖两抖、零文字、零放行 |

## 流程 03：门禁视觉+主题跟随+本地模式告知走查（2026-10-24 三测口述，0.305.4 实测，0.305.5 修复）

**环境前置**：同流程 02（先关华为云空间 DAG 数据共享 → 冷装 → 首启门禁）。

### 场景 1：门禁布局终调
| 项 | 内容 |
|---|---|
| 实测（0.305.4） | 比 0.305.3 舒服多了，但整体仍偏上 |
| 拍板（0.305.5 已实施） | 上部（品牌→暂不登录）再下移一点（顶部弹性 1.6→2.0）；下部三层（协议行/不同意退出/版本号）下移两倍距离（中部弹性 1→1.4、底部 0.4→0.3） |

### 场景 2：负反馈+门禁各入口验收（全通过）
未勾选点「华为账号登录」/「暂不登录」→ **协议行抖动**，用户认可（「非常棒」）；「不同意，退出」→ 真退出 ✓；协议正文/隐私政策可进可返 ✓；华为认证协议跳华为官方浏览器 ✓

### 场景 3：协议正文页铺满
| 项 | 内容 |
|---|---|
| 实测 | 用户协议/隐私政策正文下方有一段空白 |
| 拍板（0.305.5 已实施） | 正文不满屏时段落间距舒展铺满全屏（SpaceBetween+minHeight('100%')）；超屏时自然滚动不受影响 |

### 场景 4：主题「跟随系统」不生效 bug
| 项 | 内容 |
|---|---|
| 步骤 | 暂不登录进入 → 外观弹窗点「浅色」（界面变亮 ✓）→ 点「跟随系统」（系统实为深色） |
| 实测（bug） | **没变深色**；深色↔浅色互切正常 |
| 根因（0.305.5 实锤） | app 自身 setColorMode(LIGHT) 触发 onConfigurationUpdate 回声 → refreshFromSystem 把 systemDark 快照污染成 false → 点「跟随系统」applyMode('system', 假值) 仍浅色 |
| 修复（0.305.5 已实施） | ①回声哨兵：setColorMode(DARK/LIGHT) 后 150ms 窗内同值 configuration 变化直接忽略；②跟随档 setColorMode(NOT_SET) 恢复跟随（官方 faqs-ability-156：恢复跟随=COLOR_MODE_NOT_SET，无 FOLLOW_SYSTEM 枚举） |

### 场景 5：体验改进计划开关（通过，用户盛赞）
默认关+二选一设计「让用户决策成本变少，非常好」

### 场景 6：本地模式功能告知弹窗（用户设计理念落地）
| 项 | 内容 |
|---|---|
| 用户理念 | 暂不登录=只能①单词库建立②知识卡片手动录入③卡片复习（含复习记录）；云同步开启与账号登录绑定 |
| 拍板（0.305.5 已实施） | 「暂不登录」进入后弹**一次性**告知弹窗（每设备一次，agreement_store 记忆）：告知三项可用功能+「登录华为账号」主按钮（走常规登录链，成功后询问开云同步）+「直接进入」出口 |
| 合规依据（已核官方文档） | 《Account Kit 登录管理细则》仅要求「支持第三方登录须提供华为账号登录选项」；单次告知+可跳过出口不构成强制操作（细则路径：开发指南/Account_Kit_华为账号服务/开发者使用Account_Kit的登录能力的管理细则） |

### 流程 04 补记（2026-10-24 四测）：告知弹窗「没弹」定性
用户四测口述「打勾→暂不登录→直接跳进去了，没有回复说只能用什么」——实测**功能已存在但排在主题选择弹窗之后**（接力弹），用户在主题弹窗阶段即感知「没弹」。教训：**弹窗类功能的用户预期时序=动作后立即反馈，接力链弹窗必须确认前序弹窗的用户感知**。0.305.6 已前置修复。

### 0.305.3 连带变更（测试台用例须同步核对）
- 冷启（已同意用户）=直达气泡树（原「落首页正常态」路径不复存在）
- 首页正常态三件套删除：进入气泡树按钮/华为账号登录区/首页版本号——版本号核对改走门禁态或设置-关于
- 常规登录失败/退出失败提示从首页文本位改 toast
- 手机端登录入口：设置 → 云同步（原首页登录卡片退役）
