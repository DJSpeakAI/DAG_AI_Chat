## 一、需求分析

### 1. 主任务：云同步私域数据链端到端验证
「私域数据链」= 用户私域数据（单词库/知识卡/气泡树聊天/Tab 布局 四域）从 **A 端 UI 产生 → A 端 RDB 落盘 → cloudSync 上行 → 云端 → B 端下行 → B 端 RDB → B 端 UI 可见** 的完整链路。

现状缺口：
- 0.229.1 的 SYNC-DOMAIN 只做**静态一致性快照**（双端行数+md5 比对），不产生新数据，**验证不了「链路活不活」**——双端一致的空库也能绿。
- 0.228.0 PENDING 遗留验证项①：**删除 del 标记行传播**从未真机一键验证（写通道探针实证过"物理删行不传播→del 标记行"，但 app 真实 UI 删除→对端收敛没跑过）。
- 数据链验证正是 0.228.0 重构最需要真机回归的部分（超限分块/僵尸气泡清污等遗留项都挂在这条链上）。

### 2. 附属需求（用户本轮提出）
| # | 需求 | 用户原话要点 |
|---|------|------------|
| A | 登录态=公共前置+收尾保持登录 | "每一个东西都要登录进去""离开的时候尽量保持登录，不要点重新安装点覆盖安装"——任何套件开跑前 ensureLogin，跑完 keepLogin，覆盖装机保留登录 |
| B | PC 外接屏遮挡 | 本机跑 PC 用例 app 弹窗遮挡浏览器；用户 100% 分屏；窗口挪屏做不到也要有缓解 |
| C | 设备组合灵活 | 三设备同跑 / PC+Pad（玩手机）/ Pad+手机（玩电脑）三种组合都要能跑，编排用例按在线+勾选设备自适应 |
| D | 多设备协同体系起步 | C 混合制（通用域能力路由 + 设备专属域 + 跨端编排器），本轮只落编排器最小子集 |

## 二、设计思路

### 1. 新增 SYNC-FLOW 编排套件（跨端编排用例）
用例形态 = **步骤序列跨设备**，核心结构：
```
[PC: ensureLogin → UI 真实操作产生数据] → settle 轮询(默认 60s, 5s 间隔)
→ [PAD: sqlite 行数+md5 断言 + /api/dump 盯屏 UI 可见性抽查] → 反向再来一轮
```

用例清单（初版 5 条）：
| 用例 | 链路 | 说明 |
|------|------|------|
| SYNC-FLOW-WORD | PC 建生词 → PAD 断言；PAD 建生词 → PC 断言 | UI 路径：边栏→单词库→手动添加入口（实施时盯屏校准） |
| SYNC-FLOW-CARD | PAD 建知识卡 → PC 断言 | 知识库有新建卡片 UI（0.200.1 引导弹窗证实） |
| SYNC-FLOW-CHAT | PC 新建分支气泡 → PAD 断言 | 创建分支即落盘 node；不等 AI 回复完成（180s 业务超时内兜底） |
| SYNC-FLOW-DELETE | PAD 删一条 → PC 断言 del/行收敛 | ★0.228.0 遗留验证项①，红了=实锤转 app 修复迭代（先测后修） |
| SYNC-SETTLE | 基建 | 同步静默轮询函数（settle 期间行数/md5 稳定或超时如实报） |

### 2. 断言通道（复用已验证资产）
- **数据真相**：sqlite3 直读双端 RDB（四域分域：word/wfolder+card/kfolder+node+tab/layout+del 行数+键集 md5，假绿根治=报错/非数值=红）
- **UI 抽查**：/api/dump 盯屏（0.229.24 已实证），只做"数据到了 UI 也看得见"的抽查断言，不做全 UI 自动化
- **AI 盯屏工作法**：本轮执行全程 AI 盯屏逐字对照（用户旁观），发现问题当场修当场重跑

### 3. 登录态公共前置/收尾（需求 A）
- `ensureLogin(ctx, serial)`：开跑前查登录态（persistent_storage `huawei-account` 通道），未登录→自动走首页登录流程（协议自动同意+华为授权页人工唯一保留——**PC/Pad 已实测过静默授权，预计零人工**）
- `keepLogin` 收尾：**LOGIN-LOGOUT 用例改为"测完退出→自动登回"**（保留退出断言，收尾不再留登出态）；其余套件跑完不动登录态
- 装机默认覆盖安装（已是默认）→ 登录态天然保留 → 下一轮任意套件起点即已登录
- LOGIN-KEEP 修正：前置=装机前登录快照（startRun prep 阶段记录），快照未登录→skip 文案如实；登录矩阵收尾 keepLogin 后，覆盖轮 KEEP 不再无脑 skip

### 4. PC 遮挡缓解（需求 B）
窗口挪屏系统未暴露命令（鸿蒙 PC 无 wm 命令迹象，不押宝），务实双保底：
- **PC 每条用例断言完成 → 自动 `aa force-stop` 收窗**（窗口即消失，浏览器永不被久挡）
- 冷启动验收同样"启动→断言→force-stop"收尾
- 效果：app 窗口只在断言的几秒内在场，用户盯浏览器全程不被挡

### 5. 能力档案字段（需求 C/D 最小子集）
config.json 设备项加 `caps`（PC: mouse/rightclick/resident-sidebar；Pad: touch/resident-sidebar；手机: touch/drawer-sidebar），本轮仅用于：编排用例按"在线+勾选"设备自适应（缺端 skip+注明）；交互原语设备感知（右键/长按映射）留后续迭代，不本轮铺开。

### 6. 执行模式（用户旁观、AI 全自动）
1. 用户在 **DevEco Terminal** 重启测试台服务（加载 0.229.25，§12.8 老规矩）
2. 用户确认 PC（DevEco 开着）+ Pad USB 在线
3. AI 驱动：起跑 SYNC-FLOW → /api/dump 盯屏 vs 测试台日志逐字对照 → 红了当场定位（判别框架：测试台侧先自查再定性 app）→ 修 → 重跑
4. 跑完交付：双端保持登录 + 结果全绿（或如实红+定位结论）

## 四、风险点
1. **UI 真实路径不确定**：生词手动添加/新建卡片/新建分支的确切 UI 路径需盯屏校准，用例文案可能迭代 1~2 轮（0.229.24 先例：首跑揪 7 个对齐缺陷属正常）
2. **同步时延不定**：settle 默认 60s 可能偏紧（云端中转+对端拉取），超时如实红、不判死
3. **SYNC-FLOW-DELETE 可能红**：红了=0.228.0 遗留 bug 实锤——按先测后修，报告不修，转 PENDING 独立迭代
4. **服务须用户重启**才加载新码（stale 守卫会拦，页面会标红提示）
5. **CHAT 用例依赖 AI API**：发消息需 API key 在位+流式回复落盘才稳定；兜底=创建分支即断言 node 行（不等回复）
6. **手机不在场**：三端编排用例手机侧自动 skip+注明（不算失败）

## 五、验收标准
1. PC+Pad 在线，SYNC-FLOW 套件跑完：全绿，或红项均有明确定性（测试台侧/app 侧）
2. SYNC-FLOW-DELETE 有真机结论（绿=通过 / 红=del 传播 bug 实锤入 PENDING）
3. 跑完双端登录态=保持登录；下一轮覆盖装机后 LOGIN-KEEP 如实断言不再无脑 skip
4. PC 用例执行期间 app 窗口自动收起，浏览器不被持续遮挡
5. 三种设备组合（三全/PC+Pad/Pad+手机）下编排用例自适应 skip 行为正确
6. 版本号 0.229.24 → 0.229.25；node --check 双文件通过；桌面副本同步
