## 一、需求背景（用户原话归纳）

1. **消息信息行合并（方案 1 拍板）**：AI 消息操作行右侧的「模型名」和「输入/输出 token」现在是两个独立横向滑动区，手机窄屏要滑两个、有割裂感。拍板=**合并成一个滑动区**，滑一次看全。Pad/PC 宽屏本来就放得下，合并后视觉不变（零感知）。
2. **API 配置加「测试连接」**：4 个模型提供商（华为云 MaaS / 火山方舟 / DeepSeek / 自定义配置）表单下都要加测试连接按钮，点击后返回连接结果（成功/失败）。让用户填完 Key 能立即验证是否可用。
3. **模型别名**：4 个提供商表单下都加「模型别名」输入框——用户自定义模型的应用内展示名；**留空则显示官方模型名**。输入框下方加一行小字说明（很多人不知道别名是干嘛的），文案方向：「给模型起个应用内展示名称（对话记录里显示它），类似司忆区的展示名；留空则显示官方模型名」。

## 二、改动 A：消息操作行两个 Scroll 合并

### 现状代码（精确落点）

文件：`entry/src/main/ets/components/ChatPage.ets` **约 4677-4708 行**（AI 消息操作行 Row 内，0.237.3 重排后结构：喇叭→刷新→换一批→复制→删除→Blank→模型名 Scroll→token Scroll）：

```typescript
// 现状：Blank() 之后是两个独立 Scroll
Blank()
// 模型名 Scroll（上限 35%）
if (msg.model.length > 0) {
  Scroll() {
    Text(msg.model)
      .fontSize(11)
      .fontColor(TEXT_TERTIARY)
      .maxLines(1)
  }
  .scrollable(ScrollDirection.Horizontal)
  .scrollBar(BarState.Off)
  .constraintSize({ maxWidth: '35%' })
  .flexShrink(1)
  .align(Alignment.Start)
}
// token 统计 Scroll（上限 50%）
if (msg.outputTokens > 0) {
  Scroll() {
    Text(`输入 ${msg.inputTokens} · 输出 ${msg.outputTokens}`)
      .fontSize(11)
      .fontColor(TEXT_TERTIARY)
      .maxLines(1)
  }
  .scrollable(ScrollDirection.Horizontal)
  .scrollBar(BarState.Off)
  .constraintSize({ maxWidth: '50%' })
  .flexShrink(1)
  .align(Alignment.End)
}
```

### 改法

把两个 Scroll **合并为一个 Scroll + 单个 Text**（拼接字符串），滑动区连续不断裂：

```typescript
Blank()
// ★ 0.238.0：模型名+token 合并单一滑动区（方案 1 拍板）——手机滑一次看全，割裂感根除；
//   宽屏（Pad/PC）放得下时视觉与合并前一致（两段文字本就紧挨着）
if (msg.model.length > 0 || msg.outputTokens > 0) {
  Scroll() {
    Text(this.modelDisplayText(msg))
      .fontSize(11)
      .fontColor(TEXT_TERTIARY)
      .maxLines(1)
  }
  .scrollable(ScrollDirection.Horizontal)
  .scrollBar(BarState.Off)
  .constraintSize({ maxWidth: '60%' })
  .flexShrink(1)
  .align(Alignment.End)
}
```

配套在 ChatPage 加一个私有方法（放在类内工具方法区）：

```typescript
// ★ 0.238.0：模型显示文本——别名优先（当前配置模型且别名非空），否则官方模型 ID；拼 token 统计
modelDisplayText(msg: ChatMessage): string {
  const name = (msg.model === this.apiConfig.model && this.apiConfig.modelAlias.length > 0)
    ? this.apiConfig.modelAlias : msg.model;
  const tokenPart = msg.outputTokens > 0 ? ` 输入 ${msg.inputTokens} · 输出 ${msg.outputTokens}` : '';
  return tokenPart.length > 0 ? `${name} ·${tokenPart}` : name;
}
```

说明：
- `maxWidth` 从 35%+50% 改为单区 **60%**（合并后总内容更长，给足空间；窄屏 flexShrink 收缩后仍可滑）。
- 拼接格式：`别名或模型ID · 输入 190 · 输出 230`（间隔符「 · 」与现有风格一致）。
- 别名逻辑见改动 C，此处一并落（若改动 C 未同步实施，`this.apiConfig.modelAlias` 字段不存在会编译错——**改动 A 与 C 必须同版落地**）。

## 三、改动 B：API 配置加「测试连接」

### 设计要点

- **测试语义**：用**表单当前值**（未保存也可测）发一次最小真实请求——与 0.236.0 TTS「试听=以当前表单值走完整链路」同哲学。
- **零侵入主链路**：不改动 `ApiClient.ets` 的 streamChat（那是流式对话链路）；在 GlobalSettingsDialog.ets 内写独立的轻量测试函数，用 `@kit.NetworkKit` 的 http 直接 POST 一次 **非流式** chat/completions（`stream:false` + `max_tokens:1` + 一句「ping」），成功=配置可用。消耗仅几个 token。
- **超时**：15 秒（连接测试不等长请求；项目 180s 规则是业务长请求用的，此处不适用）。
- **结果展示**：按钮旁/下方一行结果文本——成功绿色「✓ 连接成功（耗时 N ms）」；失败红色**中文**提示（禁止展示原始英文报错——项目网络规范 §4 铁律）。
- **防连点**：请求进行中按钮置灰（`testing` 状态），完成后恢复。
- **Key 空守卫**：未填 Key 点测试→红色提示「请先填写 API Key」，不发请求。

### 错误中文化映射（务必照做）

| HTTP/异常 | 中文提示 |
|---|---|
| 401 / 403 | API Key 无效或无权限 |
| 404 | 模型 ID 或接口地址不存在 |
| 429 | 请求过于频繁或额度不足 |
| 5xx | 服务商服务异常，稍后再试 |
| 超时 | 连接超时，请检查网络或接口地址 |
| 其他 | 连接失败（附简短原因） |

## 六、风险点与铁律（执行 AI 必读）

1. **PersistenceV2 换 key 是硬前提**：不换 v4，别名字段重启即丢（0.143/0.190 两次实锤）。迁移代码照抄 v3 工厂函数的既有逐字段写法，别漏 audio 系字段。
2. **新状态变量必须挂 `@Local`**：`testing/testResult/testOk/editAlias` 漏挂 = 真机 UI 不刷新（`@Computed` 依赖链真机不可靠，同族雷多次复发）。
3. **改动 A 与 C 必须同版落地**：`modelDisplayText()` 引用 `apiConfig.modelAlias`，C 没落 = 编译错。
4. **测试连接不走 streamChat**：独立轻量 http 非流式请求，零侵入主对话链路；15s 超时；错误一律中文。
5. **ArkTS 语法雷**：对象方法签名二选一（方法简写或箭头函数属性），禁混写 `cancel(): void => {`；新增常量/声明插在 import 区全部结束之后（`arkts-no-misplaced-imports`）；带参 @Builder 禁按值传参（此处新增 UI 直接内联或用无参 @Builder）。
6. **UI 对齐**：API 配置 Tab 已去卡片化（0.232.2 用户实锤上下宽度必须逐像素对齐）——新字段与现有表单同构裸 100% 宽，勿加卡片 padding。
7. **版本号三处同步**：app.json5 + Index.ets + GlobalSettingsDialog APP_VERSION（现有 0.237.3 → 0.238.0；versionCode 1000269）。Index.ets 显示文本是三度漏改老坑，改完反查一次界面显示文本。
8. **别动 TTS**：用户明确 TTS 本阶段满意，语音朗读区零改动。
