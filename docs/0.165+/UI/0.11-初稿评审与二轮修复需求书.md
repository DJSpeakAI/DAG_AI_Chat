### 问题清单

**A. 用户已发现（本轮修复主线）**

1. **平板端双父节点连线**：「神经网络基础 / 聚类算法 / 特征工程」存在双来源入线（监督学习 + 无监督学习同时指向），违反单父数据模型。
2. **手机端列表无层级**：6 节点平铺 + 细竖线，无缩进无树形连接，父子关系不可辨。

**B. AI 补充发现（建议一并修）**

3. **手机端缩放控件矛盾**：手机端已是垂直列表模式，底部悬浮的缩放控件（- ⌘ +）失去意义——列表不需要缩放。建议删除，该区域留空。
4. **间距标注未完成**：标注页间距区只有 4 组示意图、无具体数值。开发侧落地需要数值（导航项间距、卡片内边距、画布容器内边距、列表边距等）。
5. **连线疑似图标字体而非曲线**：初稿连线是「DAG 父子连线」图标字体拼的，重排拓扑时建议直接换成真正的三次贝塞尔曲线绘制，弧度更自然。

**C. 文字/文案问题（用户要求在 prompt 中指出）**

6. **「+ 新建节点」→ 应为「+ 新建气泡」**：产品核心术语是「气泡」（气泡树、气泡节点、新建子气泡），全产品语境统一用「气泡」。
7. **「知识画布」命名**：设计稿画布页标题用「知识画布」，现有应用首页按钮叫「进入对话画布」——两端不统一。**建议统一为「知识画布」**（更贴「对话式 DAG 学习工具」的产品定位，设计稿已用），落地时首页按钮文案同步改；若用户偏好「对话画布」则反向统一。
8. **手机状态栏「9:41」**：这是苹果发布会的彩蛋时间，鸿蒙设计稿建议换成普通时间（如 10:08）。
9. **用户修复 prompt 中色值漂移 #7C3AED**：0.1 需求书定稿的主紫是 **#7C4DFF**，修复 prompt 里写的 #7C3AED / rgba(124,58,237,…) 是另一个紫（Tailwind violet-600），会导致连线颜色与色板脱节，必须统一回 #7C4DFF / rgba(124,77,255,…)。

### 用户修复 prompt 的三处硬伤（已在下方修正版中修掉）

| # | 原文 | 问题 | 修正 |
|---|------|------|------|
| 1 | 「DAG 规则中一个子节点最多指向一个父节点」 | **概念错误**：DAG（有向无环图）图论本身允许多父节点；「单父」是**本产品 BubbleNode 数据模型约束**（每节点仅存一个 parentID，结构为单父树）。按原表述发给设计师，会误导其理解图的结构自由度 | 改为「本产品数据模型约束」并单独做概念澄清段 |
| 2 | 「一个子节点最多**指向**一个父节点」 | **方向反了**：连线方向是父→子（箭头指向子节点），「子指向父」会让设计师画反箭头 | 改为「每个子节点有且仅有一条**来自**父节点的入线，箭头指向子节点」 |
| 3 | 「特征工程作为第三条独立子节点」 | **歧义**：「第三条独立子节点」读不出挂靠关系（第三分支？无监督下第三个子节点？） | 直接给出 5 条连线的完整清单，拓扑唯一化 |

## 第二部分：第二轮修复 prompt（修正版，可直接整段复制发送）

````markdown
# DAG 画布修复需求：平板连线合法性 & 手机层级展示（第 2 轮）

针对已出的主画布工作台初稿（平板 1280×800 / 手机 360×780 / 标注页）的两处结构问题进行修复，确保气泡树的父子关系在两端均正确表达。

## Goal

1. **平板端**（1280×800）：修复「一个子节点拥有两个父节点」的违规连线，使每个子节点严格只有一条来自父节点的连线。
2. **手机端**（360×780）：修复节点列表缺乏父子层级展示的问题，增加层级缩进与树形连接线。

## 重要概念澄清（请务必按此理解，避免误解）

- **「单父节点」不是 DAG 图论规则**（通用 DAG 允许一个节点有多个父节点），而是**本产品的数据模型约束**：每个气泡节点内部仅保存一个 parentID，整体结构是「单父树」。因此设计稿连线必须满足：**每个子节点有且仅有一条来自父节点的入线**。
- **连线方向：父节点 → 子节点**（箭头指向子节点），语义是「知识从父主题分出子主题」。
- **也就是说一个父节点可能有多个子节点，你在设计的时候一定要考虑进去

## 目标拓扑（唯一标准，请严格按此重排，不要自行发挥）

```
机器学习入门（根）
├── 监督学习
│   └── 神经网络基础
└── 无监督学习
    ├── 聚类算法
    └── 特征工程
        └── 特征工程2
        └── 特征工程3
        └── 特征工程4
```

## 平板端修复要求（1280×800）

1. 删除所有违反单父约束的多余连线。
2. 按目标拓扑重排节点坐标：监督学习分支（监督学习 + 神经网络基础）与无监督学习分支（无监督学习 + 聚类算法 + 特征工程）在纵向清晰分离，避免连线交叉。
3. 连线请用**真正的三次贝塞尔曲线 + 箭头**绘制（不要用图标字体拼连线），弧度自然、粗细一致。
4. 连线颜色用主紫 **#7C4DFF**（注意：不是 #7C3AED，必须与色板主紫一致），可带同色低透明度光晕。
5. 节点卡片、导航栏、账号区、信息条、色板、圆角、字体等其他区域一律不动。

## 手机端修复要求（360×780）

1. 节点列表按层级缩进：根节点不缩进，第二层缩进 20px，第三层缩进 40px。
2. 缩进区绘制树形连接线：竖线（贯穿兄弟节点区间）+ 水平折线连向节点卡片，颜色 **rgba(124,77,255,0.5)**（主紫 #7C4DFF 的 50% 透明度，注意不是 rgba(124,58,237,…)）。
3. 节点卡片宽度自适应缩减（减去缩进量），右侧 › 箭头与屏幕右边距对齐不变，卡片内文字不得截断。
4. 兄弟节点间距 12px，父子层间距 8px。
5. **删除底部缩放控件（− ⌘ +）**：手机端已是列表模式，无需缩放，该区域留空。

## 文案修正（一并修改）

1. 顶部按钮「+ 新建节点」→「**+ 新建气泡**」（产品核心术语是「气泡」：气泡树 / 气泡节点 / 新建子气泡）。
2. 画布页标题统一用「**知识画布**」，全稿不得出现「对话画布」字样。
3. 手机端状态栏时间「9:41」→ 改为「10:08」（9:41 是苹果发布会彩蛋时间，鸿蒙稿避免使用）。

## 标注页补全（间距数值）

当前标注页「间距」区只有示意图、无具体数值，请补全以下数值标注：

- 左侧导航：导航项之间的间距、导航区内边距、Logo 区与导航区的间距
- 节点卡片：内边距（logo 与标题、标题与信息行的间距）
- 画布容器：内边距、顶部信息条与画布区的间距
- 手机端：列表左右边距、缩进步长（20px/级）、列表与顶部信息条间距

## 不包含

- 不改动导航栏结构、账号区、色板、圆角、字体规格
- 不新增或删除节点（仍保持 6 个）
- 选项卡模式本次不设计（顶部「选项卡」按钮保留即可）
- 不涉及交互逻辑、动画或原型连接
````

## 第三部分：设计协作策略建议（回应「一次性全丢 vs 按节奏迭代」）

**建议：维持单页迭代节奏，但升级为「设计系统先行」两阶段法。**

**阶段 1（当前）——主画布打磨到 95 分定型**：
主画布是核心界面，它的色板、圆角、字号、间距、组件规格一旦定稿，就是全产品的**设计 token**。这个阶段值得用最强的模型、最细的反馈轮次去磨（60 → 82 已证明「需求书精确度」是质量杠杆：0.1 修正 7 处换来 22 分）。差距主要在细节打磨：间距数值、连线弧度、图标风格统一、层次感。

**阶段 2——其他页面批量出稿**：
设计 token 定型后，对话页、单词库、知识库、设置页对模型「创造力」的要求大幅降低（照着 token 套即可），那时可以一次丢多个页面、甚至用便宜模型批量出，质量不会塌。

**一次性全丢的坏处**：注意力稀释，每页质量从 82 掉回 70；核心界面设计语言未定型，各页面各自为战，风格会飘，返工成本更高。

**换更强模型**：值得，但性价比最高的是用在阶段 1（主画布定型）；阶段 2 用普通模型即可。
