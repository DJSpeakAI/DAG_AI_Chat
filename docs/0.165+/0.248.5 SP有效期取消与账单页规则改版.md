## 一、需求分析（用户原话归纳）

1. **有效期 100% 取消**：SP 一经获得永久有效（含新用户礼包）——「半年之后再来玩，无所谓，继续保持着」，一个账户统一管控。理由：签到/背单词/礼包各种来源的 SP 混在一起，有效期各算各的、扣减顺序乱，不如全部永久。
2. **口径统一「嘉奖」**：对外统一叫「嘉奖 SP」，不再出现「赠送」字样；此口径规范写进 rules/UI guidelines。
3. **账单页改版**：
   - 顶部 = 司忆点综合（嘉奖 + 充能合计展示）；
   - 充能 SP（购买档位/链接）上移到资产卡正下方；
   - 下方新增「SP 扣点规则」：①先扣嘉奖 SP，再扣充能 SP；②退款规则=按包退款——某个充能包未消耗过任何 SP（哪怕一点没动）可申请退款；该包一旦用过 SP 即整包不可退；
   - 获取途径卡下移；
   - 退款/充值按钮保留现状（IAP 占位），后台充值测试开通后再绑接口。
4. **边栏左下角**：显示全部 SP 综合（不分开）——现状已如此，确认保持。

## 二、改动方案

### 2.1 数据层：取消有效期（ChatModel.ets）

- `siyiTotalSp()`（约 857 行）：删除赠送池过期过滤——`giftSp` 恒计入总余额；
- `grantSiyiWelcomeBonus()`（约 905 行）：不再设置 `giftSpExpireAt`（新礼包到期戳恒 0）；
- `SIYI_GIFT_VALID_DAYS` 常量：随取消删除（唯一消费点即上条）；
- **字段 `giftSp` / `giftSpExpireAt` 保留不删不改名**（Schema 铁律：尾部追加可、删改禁；云同步 `cfg:siyi-points` 行的 max 合并照旧，存量多端数据无损）；
- 存量兼容：已装机设备上已打的到期戳（如 2027-01-16）不再被消费——原「90 天礼包」自动转永久，无需迁移。

### 2.2 账单页改版（BillingPage.ets）

**卡片新顺序（自上而下）**：

1. 司忆点资产卡（位置不变）：综合余额 + 等级头衔 + 池明细改两行——
   - `嘉奖 SP xxx（永久）` = bonusSp + giftSp 合计（UI 不再区分赠送/嘉奖两池，对外口径只有嘉奖）；
   - `充能 SP xxx（永久）`；
   - 删「赠送 SP xxx（X 前有效）」行与 formatDate（若无其他消费）；
2. 充能 SP 卡（**上移至第 2 位**）：两档 ¥9.9→200 万 / ¥19→400 万，点击占位 toast 保留；
3. **SP 扣点规则卡（新增）**：
   - `· 消耗顺序：先扣嘉奖 SP，嘉奖用尽后自动扣充能 SP`
   - `· 退款规则：按充能包退款——某包未消耗过任何 SP 可整包退款；该包一旦产生消耗（哪怕 1 点）即不可退款`
4. 获取途径卡（**下移至第 4 位**）：「新用户礼包：注册即赠司忆点（赠 90 天内有效）」→「（永久有效）」，并删除「充能 SP 永久有效」句（全永久后该句冗余，改口径为全部永久）；
5. 兑换码（不动）；
6. 记录（不动）；
7. 发票说明（不动）。

**保留项**：登录入口、兑换链路、IAP 占位按钮/退款相关占位全部原样保留，等后台充值测试开通后绑接口。

  - 「消耗时优先使用即将到期的赠送 SP」→「消耗时先扣嘉奖 SP，再扣充能 SP」。

### 2.4 UI 规范入档（UI_GUIDELINES.md 第十八章追加）

> **司忆点口径军令**：①对外只称「司忆点 / 嘉奖 SP / 充能 SP」，禁用「赠送」字样（历史「赠送池」仅存在于数据层字段名）；②SP 无有效期概念，任何界面禁出现「X 前有效 / 90 天内有效」类文案；③消耗顺序对外口径=先扣嘉奖 SP、再扣充能 SP。
