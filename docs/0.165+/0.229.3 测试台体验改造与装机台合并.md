## 一、核心诊断：两个真 bug + 一处误解（已定位到行号）

### 诊断 1：版本核验"假绿"——三个版本号是三样东西（不是装错版本）
| 显示位置 | 值 | 含义 |
|---|---|---|
| 应用 首页底部 `Index.ets:650` | `v0.228.0` | **手写版本文本** |
| 应用 关于页/反馈邮件 `GlobalSettingsDialog.ets:126` | `APP_VERSION='v0.228.0'` | **手写版本文本**（注释要求与上处+app.json5 三处同步） |
| `AppScope/app.json5` versionCode / versionName | `1000252` / `"1.0.0"` | **真正被系统识别的版本**（versionCode=0.228.0 线；versionName 还是占位 1.0.0） |
| 测试台顶部副标题 `public/index.html:94` | `0.229.2 …` | **测试台工具自己的版本号**，与应用无关 |
| `testing/console/config.json` expectedVersionCode | `1000252` | 测试台**期望的应用 versionCode** |

→ 实测：PC 装的 versionCode=1000252，与期望一致，`bm dump` 校验本就 pass。**用户看到的"不一致"是"工具版本 0.229.2" vs "应用版本 0.228.0"两个不同维度的数字没被区分显示**，不是装错版本。

### 诊断 2：点了「版本核验」，下面「装机版本核验」没勾上（真 bug）
`public/index.html:266-271`：组标题复选框 `gb` 的 `onclick` 只 `stopPropagation`，`onchange` 只改内存集合 `CASESEL`，**未调用 `renderTree()` 重绘**；而子项行 `it.onclick`（:282）同样不重绘。
→ 直接点组复选框的方块时：`CASESEL` 已被更新（提交时会带上），但**下方子项 checkbox 视觉上不翻转** → 界面与真实选择集错位。这正是需求 4 的现象。

### 诊断 3：版本核验"跑很久"——真正跑的是整套登录+同步
"版本核验"套件里含 `LOGIN-*`（6 个，含人工授权检查点 `loginTimeoutMs=180000`）+ `SYNC-*`（4 个，跨端含 300s 检查点）+ `VERSION`（1 个）。当选择集因诊断 2 错位（或曾点过全选）时，用户以为只勾了「版本核验」，实际跑了 login+sync 全套 → 数分钟级等待 + 人工授权弹窗。
→ 修诊断 2 的重绘后，"跑很久"问题一并缓解；另外需求 1「版本核验移最上」让 VERSION 套件单独可见、易单跑。

## 十、ArkUI Test（hypium）说明与「有 / 无 test」区别（Q2）

**是什么**：DevEco/hypium 的仪器化测试（正本 `entry/src/ohosTest/`），把测试代码**打进一个独立的测试 HAP**（module `entry_test`），部署到设备后由测试框架驱动运行。与测试台现有的 **hdc CLI 黑盒测试**是两套体系：

| 维度 | ArkUI Test（hypium / ohosTest） | 测试台 hdc 黑盒（现状） |
|---|---|---|
| 运行位置 | **设备内**（测试 HAP 进程） | PC 侧脚本 `hdc shell` 遥控 |
| 断言粒度 | **可调用应用内部 API/函数**（白盒） | 只能看 dumpLayout/数据库/hilog 外部现象 |
| UI 能力 | `@ohos.UiTest` Driver 直接点按钮/断文本，稳定 | dumpLayout 文本匹配（PC 端不支持，见 caps） |
| 触发 | `hvigorw ohosTest` / DevEco 一键 Run Test | 测试台点「开始测试」 |
| 产出 | `test_result`（用例级 pass/fail + 耗时） | results.json 历史 + SSE 流 |

**「有 test vs 无 test」区别（用户要看的就是这个）**：
- **无 test**：`hvigorw assembleHap` 只编出应用 HAP，**编译通过 ≠ 功能正确**——比如版本号写错、首页渲染崩，编译都照过。
- **有 test**：`hvigorw ohosTest` 额外编出测试 HAP 并**在设备上真跑断言**——本迭代把默认空模板换成真断言：`app_context_ready`（应用上下文可用）+ `bundle_versioncode_valid`（`bundleManager` 读到的 `bundleName==com.dagaichat.app` 且 `versionCode>0`）。任一断言失败即**红灯**，这就是"多一层设备内真验证"。

**怎么跑**（桌面实测）：
