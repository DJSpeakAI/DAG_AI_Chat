# 0.304.0 TTS 朗读后台/熄屏续读

## 需求（用户口述拍板）
朗读 AI 回复时，切后台/按掉屏幕（熄屏）必须继续读；对话页右上角喇叭入口**不加**（用户自行取消——他知道哪里开喇叭）。

## 官方文档结论（devecocli docs 实读）
1. 后台播音频必须申请 `AUDIO_PLAYBACK` 长时任务；MUSIC/MOVIE/AUDIOBOOK 流类型（云端 TTS 的 AVPlayer 即是）还**必须接入 AVSession**，否则系统检测到后台强制停播；本地 CoreSpeechKit TTS 流不在强制清单但接入无害。
2. 旧接口一个 UIAbility 同时仅一个长时任务——AiStreamGuard 已占 `dataTransfer`，故 TTS 走 **API21+ `ContinuousTaskRequest` 多任务新接口**，独立 `continuousTaskId` 精确 stop，互不误伤（compatibleSdkVersion 24 ≥ 21 可用）。
3. AVSession 一进程仅一个会话对象（重复创建报 6600101）——懒创建一次永久复用，会话间只刷 metadata/播放状态。

## 设计要点
- 会话边界 = `startTTS → stopTTS`（播完/出错/切消息/退页/切气泡全走 stopTTS，结束即停长时任务=系统管控红线）。
- 单词发音（WordSpeaker）/设置页试听为秒级短播不挂守卫（KISS）。
- 播控中心 pause/stop → stopHandler（ChatPage.stopTTS 全收敛）；页面已销毁时守卫兜底直停三引擎。
- AVSession 永不 destroy（复用防 6600101），朗读结束置 PAUSE（听书类标准形态）。

## 风险与边界
- 云端 TTS 后台分段合成（http）依赖长时任务保进程（dataTransfer 先例同族）——真机验证点。
- AI 流式（dataTransfer）与朗读（audioPlayback）并存的混合接口行为：新接口独立 id 设计上兼容；失败均静默降级（前台朗读不受影响）。
- 播控中心 play 键无恢复语义（TTS 无暂停续播），首版不响应。
