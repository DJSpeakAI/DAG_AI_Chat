# 0.242.0 全局设置「修改未保存」误报弹窗移除

## 需求分析
- 用户实测（Pura X）：开全局设置→云同步 Tab→去系统侧开云同步→回 app 点「返回」，弹「修改未保存」确认框（继续编辑/不保存关闭）。
- 用户困惑：云同步 Tab 没有保存按钮；点「不保存关闭」不知道云同步状态；点「继续编辑」找不到保存入口。
- 用户拍板：**移除该弹窗**（云同步已即时生效，提示有害无益）。

## 根因
- 触发链：四个关闭入口（返回/✕/空白遮罩/系统返回键）全走 `requestClose()` → `hasUnsavedChanges()`（12 个比较项）为 true 即弹 AlertDialog。
- 12 个比较项全部是「配置/AI偏好/锚点/复习显示/TTS」编辑副本 vs 持久化，**无一与云同步相关**（云同步开关 0.196.10 起即时生效、不参与脏检查）。
- 真相=该弹窗处于「开弹窗即恒脏」状态（回显后副本≠持久化，候选源：0.240.1 别名回灌对称缺口/千问 TTS Key 预填不落盘/TTS 提供商推导回显/旧模型 ID 映射），任何关闭时机都会弹；与云同步纯属巧合关联。

## 改动文件
- `entry/src/main/ets/components/GlobalSettingsDialog.ets`（唯一改动文件）：
  1. `requestClose()` 移除脏检查分支——直接 `onClose()`（保留方法壳，四个关闭入口调用点零改动）。
  2. 删除死代码 `hasUnsavedChanges()` 与 `hasUnsavedTtsChanges()`（无任何外部调用点，已 grep 实证）。
  3. 附带修（截图实锤）：云同步 Tab「开启云同步」按钮显示条件补 `&& !this.syncOn`——2531 行注释「已开启则不显示」与代码不符，状态卡绿色「已开启」时按钮仍渲染，语义冲突。
  4. 文件头注释「含未保存修改二次确认，0.150 语义原样」同步更新。
- 版本号三处同步：app.json5 versionCode 1000281→**1000282** + Index.ets + GlobalSettingsDialog APP_VERSION → **v0.242.0**。

## 行为变化
- 关闭全局设置弹窗一律直接关闭（不再有「继续编辑/不保存关闭」确认）。
- 配置/AI偏好/复习显示等保存模式 Tab：未点「保存」就关闭=放弃本次草稿（用户已接受此代价）。
- 云同步状态以状态卡为准（绿色「云同步已开启」= 已生效）。

## 风险点
- 用户改了 API 配置误触关闭=草稿丢失（低频、用户拍板接受）。
- 删方法涉及大段代码删除，注意闭合括号错位（ArkTS 同族雷：一处坏全文件崩）。

## 验收标准
1. 云同步 Tab 点返回/✕/空白/返回键 → 弹窗直接关，无「修改未保存」。
2. 云同步已开启时「开启云同步」按钮不再显示。
3. 「保存」按钮功能不受影响（saveAll 原样）。
4. 编译零报错。
