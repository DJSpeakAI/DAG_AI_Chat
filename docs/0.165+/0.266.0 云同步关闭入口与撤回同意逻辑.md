# 0.266.0 云同步关闭入口与撤回同意逻辑重构

> 状态：**方案待用户裁决**（裁决后开工）
> 版本：0.266.0 / versionCode 1000330（当前基线 0.265.0 / 1000329 未装机）
> 来源：用户语音反馈两点——①云同步设置页缺「关闭云同步」功能 ②「关于」页「撤回同意」语义含糊、撤回后云同步仍开启=逻辑矛盾

---

## 一、需求与问题分析

### 问题 1：云同步设置页没有「关闭云同步」入口
- **现状**：`GlobalSettingsDialog.ets:2466`——`syncOn`（已开启）时**不渲染任何按钮**，只有「开启」路径没有「关闭」路径。
- 用户要关云同步目前只能：退出华为账号（0.196.8 退出强制关）——但退出登录≠用户意图，他想保留登录、只停同步。
- **现成基建**：`CloudSyncUtil.ets:181 setCloudSyncEnabled(false)`（0.196.8 已有，退出登录链路在用）——纯 UI 入口缺失，非能力缺失。

### 问题 2：「撤回同意」语义含糊 + 撤回后云同步仍开着（逻辑矛盾）
- **现状**：`GlobalSettingsDialog.ets:2630 revokeAgreementNow()`——一键重置全部协议同意态（用户协议+隐私政策+华为认证协议三态全清）后**只弹 toast**：
  - ❌ 不关闭云同步（若开着，撤回后照常同步——「撤回同意」了数据还在上传，矛盾）
  - ❌ 不立即弹首启门禁（要等**下次冷启动**才弹；本次会话内一切照旧，「撤回」形同虚设）
  - ❌ 按钮与提示文案没说清撤的是什么（「协议内容与首次启动的同意弹窗一致」这句话正是用户困惑源头）
- **0.264.0 已定案的架构**：首启门禁=《用户协议》+《隐私政策》（不同意→二次挽留→仍不同意=退出应用）；《华为账号用户认证协议》=登录前单独征求；撤回应重置两段门禁全部状态。

### 隐藏的一致性问题（本轮一并修）
- **隐私政策第 9 条现文案**：「您可随时关闭云同步、关闭体验改进计划以撤回对应功能的同意，**或卸载应用撤回全部同意**」——但关于页明明有「撤回同意」按钮，文案与功能矛盾（说好了只能卸载撤回，实际能一键撤回）。修复后第 9 条同步改写。
- **体验改进计划（埋点）级联**：撤回总同意时，若体验改进开着应一并关闭（撤回总同意级联撤回子同意，个保法严谨口径）——`TrackUtil.ets:62 setTrackingEnabled(context, false)` 现成（关闸自动清未上报队列）。

## 二、方案

### 改动一：云同步页加「关闭云同步」按钮（无分叉，定案级）

- 位置：云同步 Tab 状态卡下方；`syncOn` 时渲染（替换现在的空分支），关闭后 else 分支「开启云同步」天然回归。
- 行为：`setCloudSyncEnabled(false)` → 状态卡实时刷新（`@Trace enabled` 已通，0.196.10 基建）→ toast「云同步已关闭，数据仅保存在本设备」。
- **语义边界**：关闭云同步 ≠ 退出登录（保持登录态，随时可重开；云端数据不删）。0.196.8「同开同关」指登录↔同步耦合方向是「退出强制关」，不是「关同步=踢登录」。
- 待裁决 1a：**直接关+toast**（可逆操作、风险低）还是 **AppConfirmDialog 确认后关**（防误触，但多一步）？→ 推荐 1a 直接关（可逆+随时重开，交互顺滑；误触代价=再点一次开启）。

### 改动二：撤回同意逻辑重构（有分叉，待裁决）

#### 方案 A（推荐——用户语音意向：「三个都不同意那应该是回到最一开始，你必须同意」）

「撤回同意」= **撤回全部三项协议同意 + 立即回到首启状态**：

1. 点「撤回同意」→ **AppConfirmDialog 二次确认**（高危动作必须有，0.264.0「不同意=退出」同款防误触哲学），文案逐项说清：
   - 撤回范围：《用户协议》《隐私政策》《华为账号用户认证协议》全部三项
   - 直接后果：云同步立即关闭；须重新阅读并同意后才能继续使用本应用（不同意=退出应用，与首次启动完全一致）
   - 数据安全：本机与云端数据均不删除，重新同意并开启云同步后恢复如初
2. 确认后**四连动作**（原子顺序）：
   - ① `revokeAgreement()`（已有——重置 agreed/agreedVersion/hwAgreed 三态）
   - ② 云同步若开着 → `setCloudSyncEnabled(false)`（撤回同意=停一切基于同意的信息处理）
   - ③ 体验改进若开着 → `setTrackingEnabled(context, false)`（级联撤回子同意+清队列）
   - ④ **立即弹首启门禁**：关闭全局设置弹窗 → `agreementBridge.promptVisible = true`（不同意→二次挽留→仍不同意→退出应用，0.264.0 链路天然继承，零新逻辑）
3. 法律条款区提示文案改写（删掉含糊的「协议内容与首次启动的同意弹窗一致」）：
   「撤回同意将同时撤回《用户协议》《隐私政策》《华为账号用户认证协议》的同意并立即关闭云同步；重新同意后方可继续使用本应用；本机与云端数据不会删除。」
4. 隐私政策第 9 条同步改写：「……您也可在 设置 → 关于 → 法律条款 → 撤回同意 一键撤回全部协议同意（撤回后云同步将关闭，重新同意后方可继续使用）；撤回同意不影响此前基于同意开展的信息处理活动的效力。」

**华为审核视角的合规依据**：
- 个保法第 15 条：撤回同意权——处理者须提供**便捷有效的撤回机制**，撤回后**不得继续处理**该个人信息（=云同步必须关，这正是现版矛盾点的法律根治）
- 撤回后「重新征求同意、不同意不得使用」：0.264.0 已定案首启门禁模型（用户协议+隐私政策=服务合同总门槛），撤回回到同一状态=前后一致，华为审核认可该模型
- 「撤回不影响此前处理效力」已写在隐私政策第 9 条，合规闭环

#### 方案 B（不推荐，列出备选）：拆分撤回入口

- 「撤回华为认证协议」单独入口（撤回=关云同步+下次登录重新征求，不弹首启门禁）+「撤回用户协议与隐私政策」入口（=方案 A 全撤）。
- 否决理由：①UI 复杂化（两个撤回按钮+两套确认文案）②与 0.264.0「撤回=重置两段门禁」定案冲突 ③用户实测已表示看不懂现在的单一入口，拆两个更惑 ④华为协议本就是登录前单独征求（撤基础同意后 hwAgreed 一并重置，下次登录自然重新弹——粒度天然分离，无需 UI 上拆）。

## 四、验收标准

1. 云同步开启态：设置→云同步页可见「关闭云同步」按钮；点击后状态卡立即变「未开启」、toast 提示、登录态保持、随时可重开
2. 关于→法律条款→撤回同意：弹确认弹窗（三项范围+后果+数据安全逐项写明）；确认后设置弹窗关闭、云同步已关、首启门禁弹窗立即弹出
3. 门禁弹窗内点不同意→二次挽留→仍不同意→应用退出（与首次启动行为逐字一致）
4. 重新同意后：本地功能立即可用；云同步需手动重开；数据无丢失
5. 隐私政策第 9 条与实际功能一致（撤回入口指引有效）
