## 一、目标

1. **云端唯一真相**：`SpMirror`（余额）+ `SpLedger`（流水/txId 幂等）由云函数事务写；本地三池只作镜像。
2. **系统后台关云空间也扣得到**：消耗走云函数，不再依赖 `cfg:siyi-points` 行上行。
3. **离线不白嫖、不丢账**：无网=SP 功能拦截（中文提示）；已发生的扣/发进持久化队列，前台重试。
4. **发放同样防伪**：礼包/签到/性格测试/新手任务/兑换码/IAP 全部带账号级 txId 走 `sp_grant`。

## 二、病根与本轮实锤

- 病根：SP 账本存云空间行，系统关同步后 cloudSync 静默失败，本地照扣 → 重装恢复云端旧值 = 白嫖。
- **本轮本地直调实锤**：线上 SpMirror 对象类型**没有 `welcomeGranted` 字段** → `sp_init`/`sp_spend`/`sp_grant` 全部报 `3037004 input data field does not match the object type definition`。0.312.0 的写入链其实从未跑通（Phase 1 只验证了 sp_balance/probe 读接口）。
- 修复：云函数不再写 `welcomeGranted`，礼包已发改由 `SpLedger` 幂等键 `welcome:<accountId>` 推导；无需去 AGC 改对象类型。

## 四、关键设计

### 4.1 txId 命名空间（全局唯一）
`SpLedger.objectId` 是全局主键，**所有 txId 必须掺账号**：
- 消耗：`<accountId>:<messageId>:chat|plan|regen`、`<accountId>:<auto>`（word/extract/tts/implicit）
- 发放：`welcome:<accountId>`、`sign:<accountId>:<YYYY-MM-DD>`、`quiz:<accountId>:<节点档>`、`rookie:<accountId>:<taskId>`、`iap:<accountId>:<purchaseToken>`、`redeem:<accountId>:<码>`、`admin:<accountId>:<commandId>`

### 4.2 镜像保护（防丢账/防回填）
- 常规：`sp_balance` 全量覆盖本地三池（云端唯一真相）。
- 保护窗（本地发放后 20s）或队列非空：逐字段取 max（本地刚发/未入云的消耗不能被云端旧值冲掉；队列清空后下一次刷新恢复全量覆盖）。
- spend/grant 响应无四池明细（`hasPools=false`）→ 不覆盖。
- 换号/重置：作废在途响应（`applyCloudBalance` 校验账号）+ 清空队列。

### 4.3 旧账号迁移
`sp_balance=no-account` → 先 `probe(account,'')` 判「账号是否有任何资产史」：
- `no`（真新账号）→ `sp_init(本机快照)` 建账；
- `yes` 且本机快照为空（重装/尚未首拉）→ **拒绝用 0 初始化**，催云空间下行，等本机快照就绪再迁移；
- `err` → 不建账，提示「服务准备中」。

## 六、验收

1. 断网发 AI → 拦截并中文提示；恢复网络后可发。
2. 系统后台关云空间 → 发 AI → 云端余额扣减（另设备/重装后一致），无法白嫖。
3. 同一 txId 重试/杀进程 → `duplicate:true` 不双扣。
4. 余额不足 → 发送前拦截引导充能；并发多端花光 → 云端 insufficient 回滚本地并弹充能。
5. 签到/礼包/性格测试/新手任务/兑换码/IAP 发放：云端 SpLedger 有对应 txId，重复触发不重发。
6. 旧账号升级：余额不丢、不重复发礼包；重装后余额与云端一致。
