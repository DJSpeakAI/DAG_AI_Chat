## 二、任务书勘误（2 处，防后续翻烧饼）

1. **module.json5 configChanges = 伪需求（不实施）**：任务书 5.6 要求 abilities 段配 `"configChanges": ["colorMode"]`——实测（API 26 工具链）module.json5 **不存在该属性**（hvigor/SDK 双 schema 全文无此字段，写入直接编译失败：`property name must be valid`）。此为 Android `android:configChanges="uiMode"` 经验误植；**鸿蒙系统深浅色切换默认走 `onConfigurationUpdate` 不销毁 Ability**（Reader Kit 官方文档佐证）。module.json5 红线文件零改动。
2. **ChatModel.ets 零波及**：任务书风险表第 7 条担心非 UI 模块色值引用——实测仅 import `NODE_W/NODE_H`（尺寸 token），零色值。

## 五、教训

- 外部评审双家一致通过的「硬坑补漏」也可能是平台经验误植（configChanges）——**跨平台机制类配置落地前先查本平台 schema/文档**（编译器是最快验尸官：写入→编译→2 秒出真话）。
- 大规模机械迁移的正确姿势：上下文感知（阴影/遮罩/菜单mask 三语义不能一刀切替换）+ struct 检测正则勿漏 `export struct` + import 行内注释会把非 token 词卷进具名清单（过滤白名单=源文件真实导出）。
