## 一、需求与核心决策（已定案）

用户需求：①跟随系统深浅色；②新用户首次打开弹窗选择；③设置里可改；④主色调暗紫不变。

**核心决策（Q1，双家一致）**：**深色模式 = 现有暗紫原样，不另造第二套深色；浅色 = 新设计一套**。总共两套色表。理由：品牌延续（主紫贯穿深浅两套）、现暗紫经几十版用户验收、华为生态通行做法、工作量减半。

## 二、三态主题模型（定案）

```
themeMode（用户意图，PersistenceV2 key 'theme-mode-v1'）: 'system' | 'dark' | 'light'
effectiveDark（运行时生效态）: system→按系统 colorMode 换算；dark→true；light→false
```

- **存量用户（已同意协议的老用户）**：升级后**静默默认深色并落盘**，不弹窗（Q4 终裁，采纳 DeepSeek；豆包的"默认 system"被否——存量用户若系统为浅色，升级即变浅=惊吓体验）。设置「外观」卡加**「新」角标**引导主动发现。
- **新用户（未同意协议的新装用户）**：首启 → 协议弹窗同意 → **ThemeChooseDialog 三选一**（默认高亮「跟随系统」）→ 落盘进主界面。**新/老用户判定哨兵 = 协议同意状态**（`needsAgreement()`，0.226.0 现成函数）：已同意=老用户不弹；未同意=新用户协议通过后必弹。卸载重装=协议 key 清零=按新用户走（合理）。
- **持久化降级兜底**：theme-mode-v1 读取失败/为空 → 默认 dark（深色兜底，禁止白屏/浅色闪屏）。

## 五、技术施工方案（定案）

### 5.1 AppTheme.ets（新建，唯一色值真相源）

```typescript
// AppTheme.ets — ★ 0.262.0 运行时主题源（唯一色值真相源，取代 DesignTokens 色值段）
import { AppStorageV2 } from '@kit.ArkUI';
import { ConfigurationConstant } from '@kit.AbilityKit';

export type ThemeMode = 'system' | 'dark' | 'light';

const DARK_PALETTE: Record<string, string> = { bgApp: '#120B1F', /* ... */ brandPrimary: '#7C4DFF', /* ... */ };  // 现 DesignTokens 暗紫值原样搬运
const LIGHT_PALETTE: Record<string, string> = { bgApp: '#F7F5FA', /* ... */ brandPrimary: '#6C3EE8', /* ... */ }; // 第六节终值表

@ObservedV2
export class AppTheme {
  @Trace mode: ThemeMode = 'dark';
  @Trace isDark: boolean = true;   // effectiveDark
  // 全色值 @Trace 字段（camelCase 与原 DesignTokens 常量一一对应）：
  @Trace bgApp: string = DARK_PALETTE.bgApp;
  // ...（14 token + edge 两色 + 语义色 + review 三档+_BG + code 五色 + overlay 两档 + shadowColor）
  applyMode(m: ThemeMode, systemDark: boolean): void { /* 落盘 mode + 重算 isDark + 整表赋值 */ }
  refreshFromSystem(systemDark: boolean): void { /* 仅 mode='system' 时生效 */ }
}
export function connectAppTheme(): AppTheme {
  return AppStorageV2.connect(AppTheme, 'app-theme-v1', () => new AppTheme()) as AppTheme;
}
// 持久化独立小类（PersistenceV2 key 'theme-mode-v1'——AppStorageV2 不落盘故分开；新 key 不碰存量）
```

- 运行时态（AppTheme / AppStorageV2 key `app-theme-v1`）与持久态（PersistenceV2 key `theme-mode-v1`）分离。
- 两份 const 色表集中本文件；**DesignTokens.ets 保留字号/圆角/字体/尺寸 token 不动**，页面双 import 并存。
- 字段类型全 string（同型替换，Canvas/工具函数零波及）。

### 5.2 系统深浅色感知 + setColorMode 联动（吸收豆包内核）

- 冷启动 `EntryAbility.onCreate`：读 theme-mode-v1（不存在时按第二节规则分流：老用户落 dark / 新用户暂 dark 待弹窗；降级 dark）→ 读 `this.context.config?.colorMode` → 初始化 AppTheme → **按 effectiveDark 调一次 setColorMode**。
- 运行中重写 `onConfigurationUpdate(config)`：系统深浅变化且 mode='system' → `refreshFromSystem()` + setColorMode 同步。
- **setColorMode 联动规则**：effectiveDark 深 → `setColorMode(COLOR_MODE_DARK)`；浅 → `COLOR_MODE_LIGHT`。作用=让**系统组件**（权限弹窗/输入法候选栏/系统 Toast 等）与 app 主题同色系，避免 app 深色+系统件浅色割裂。本项目页面色全走 AppTheme token，不依赖系统资源。
- **WithTheme 不采用**（Q8 终裁，防后续翻烧饼）。

### 5.3 全量替换模式（19 文件机械改造，string→string）

| 改造前 | 改造后 |
|--------|--------|
| `import { BG_APP, BRAND_PRIMARY } from '../common/DesignTokens'` | 追加 `import { connectAppTheme } from '../common/AppTheme'` + 成员 `theme: AppTheme = connectAppTheme()` |
| `.backgroundColor(BG_APP)` | `.backgroundColor(this.theme.bgApp)` |

- 字号/圆角/字体/尺寸常量（FONT_SIZE_*/RADIUS_*/FONT_INTER*/NODE_W 等）不动，仍从 DesignTokens import。
- **先全局批量替换 import，再逐文件替换引用；每替换 1 个文件立刻编译 1 次**（本地 hvigorw 约 45~60s），不攒堆；报错超 10 条先查标签闭合/孤儿属性/import 顺序，不盯报错行。

### 5.4 @Builder 传色值排雷（头号雷，双家一致强调）

带参 @Builder 按值传 string 色值 → 主题切换**局部不刷新**。必须让 @Builder 体内直接 `this.theme.xxx`。一键扫雷（验收零残留）：

```bash
grep -rn "@Builder.*bg\|@Builder.*color\|@Builder.*stroke" --include="*.ets" entry/src/main/
```

命中的带参调用点全部内联改造。此雷本项目已三踩（0.190.1 / 2026-10-09 / 0.209.1），零容忍。

### 5.5 状态栏文字颜色跟随（新增硬坑）

主题切换时同步 `window.setWindowSystemBarProperties`：深色→状态栏内容白色；浅色→黑色（避免浅色下白字看不清）。施工时先全局 grep `setWindowSystemBarProperties` 核现状再挂联动。

### 5.6 module.json5 追加 configChanges（新增硬坑，红线文件）

`entry/src/main/module.json5` abilities 段追加：

```json
"configChanges": ["colorMode"]
```

不配置则系统切深浅色会触发 Ability **销毁重建**（体验像卡顿 bug）；配置后走 onConfigurationUpdate 无缝切换。
⚠️ **module.json5 属项目红线文件**——本改动经用户委托的总方案授权（仅此一处追加，禁动其他配置），落码后 MEMORY 记档注明。

### 5.7 启动页资源限定词（资源层唯二改动）

`resources/base/element/color.json`：start_window_background 改浅色值 `#F7F5FA`；`dark/`：保持 `#120B1F`。资源限定词免费获得跟随系统。**已知瑕疵（Q6 已裁接受）**：强制深色+系统浅色时冷启动白闪一闪（主流 app 共性）；批 3 可选做 150ms 主界面透明度渐变弱化（P2，非必须）。

### 5.8 ArkTS 雷区清单（施工必避，均项目实战入档）

①带参 @Builder 按值传参丢响应式（5.4）；②@Computed 引用的源状态必须挂 @Local；③一处坏全文件崩族谱（注释吞签名/孤儿属性/闭合错位/import 夹语句→arkts-no-misplaced-imports）；④生命周期钩子禁重复定义；⑤插代码前先查本文件已有标识符（防撞名）；⑥import 连续置顶。

## 八、验收标准

1. 设置切三态：全 UI（边栏/画布/对话/知识库/单词库/复习/统计/账单/全部弹窗）即时变色，无重启、无残留暗色块。
2. 新用户首启链路（卸载重装）：协议 → 主题选择 → 主界面，顺序正确；选择持久化（杀 app 重启保持）。
3. 老用户覆盖升级：无弹窗、默认深色、外观卡带「新」角标；点选后角标消失。
