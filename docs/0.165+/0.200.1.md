## 一、用户业务铁律（原话整理，最高优先级）

1. **「未学习」卡片（新卡）今天点卡片复习就必须被学习**——不管队列怎么算，新卡不允许被任何状态挡住。
2. **永远不可能发生「没有卡片复习」的情况**——系统后台认为「没有知识要学习了」就把「继续复习」按钮隐藏，这是不允许的、永远不可能发生的情况。
3. **「继续复习」的本质**：把后面（未来排期）要复习的卡片拿到前面来学。**代价：提前学习的那张卡，往后推延的时间系数要大幅下降**（提前学=记忆强化打折，排期惩罚加重）。
4. **穿插算法**（用户构想，待讨论）：当日队列最好做穿插，例如 3+1——3 张今天到期该复习的 + 1 张新增未学习的，交替出现（防疲劳、新卡混旧卡记忆效果更好）。
5. **空库引导**：如果知识库一张卡都没有，点「卡片复习」应该**一上来就跳出新建卡片的选项**（引导建卡），而不是显示空完成页或空白。
6. 现状 Bug 现象（用户实测）：手机上知识库有「未学习」卡片，点卡片复习却**直接进完成页，一张都不让背**，也没有「继续复习」按钮——「现在都不学习了」。

## 二、Bug 根因（已定位，待方案确认）

### 根因：`buildQueue()` 的 `isDoneToday` 一刀切

`ReviewPage.ets` buildQueue()（约 99-122 行）：

```typescript
buildQueue(): void {
  const now = Date.now();
  if (this.mode === 'word') {
    const all = pickReviewWords(this.wordBank, this.wordBank.words.length, now);
    this.queue = all.filter((w) => w.reviewCount === 0 || w.nextReviewAt <= now);
  } else {
    const all = pickReviewCards(this.knowledgeBank, this.knowledgeBank.cards.length, now);
    this.queue = all.filter((c) => c.reviewCount === 0 || c.nextReviewAt <= now);
  }
  // ...重置计数器...
  if (this.isDoneToday()) {          // ← 一刀切：今天完成过一次
    this.finished = true;            // ← 无视刚算好的 queue，直接拍进完成页
    this.requestEncourage();
  } else {
    this.finished = false;
  }
}
```

`isDoneToday()`（96 行）：`dailyState.knowledgeDate === todayKey()`——**只看「今天有没有背完过一轮」的落盘标记，不看当前还有没有可学内容**。

**故障链**（用户手机实测路径）：
1. 用户背完当日队列 → `saveTodayDone()` 落盘 `knowledgeDate = 今天`
2. 用户删除旧卡、新增卡（测试用）→ 新卡 `reviewCount=0`（未学习）
3. 再点「卡片复习」→ `buildQueue()` 算出的 queue **包含未学习新卡**（filter 条件正确）
4. **但 `isDoneToday()=true` → `finished=true` → 直接完成页** → 新卡被拍死在门外
5. 完成页「继续复习」按钮显隐 = `hasFutureContent()`（要求 `reviewCount>0 && nextReviewAt>now`）→ 队列里全是新卡（reviewCount=0）→ **false → 按钮不显示**
6. 用户视角：「都不学习了」+「没有继续复习按钮」——两个症状同根

**旁证**：pad 上有「继续复习」按钮 = pad 的知识卡有背过的（存在未来排期卡）→ `hasFutureContent()=true`。两设备代码完全一致，差异纯在数据状态。

### 次要问题：`hasFutureContent()` 的语义缺口

完成页按钮显隐条件（147-165 行）只认「已评分的未来卡」——**未学习新卡存在时返回 false**。若根因修复后仍可能出现「队列空 + 无未来卡 + 有新卡」的状态机死角，需要重新定义完成页按钮语义（见第四节讨论点 ③）。

## 四、待讨论的方案开放点（GLM 5.3 主战场）

① **`isDoneToday` 一刀切怎么改**：
- 方向 A：`isDoneToday` 不再直接跳完成页——改为「重算队列，队列空才进完成页」；当日完成标记只用于统计累计与完成页文案
- 方向 B：保留「当日完成跳完成页」的快捷路径，但**前置条件改为「队列为空」**（当日新卡/到期卡存在时永远给卡）
- 需评估：完成页的「再次进入直接跳完成页重新生成鼓励」体验（0.196.2 拍板）如何与「新卡必须当日学」共存——**比如队列里只剩新卡时，是否提示「今日任务已完成，但有 N 张新卡待学」**

② **「继续复习」的提前学习惩罚系数**：
- 用户定调：提前把未来卡拿到今天学，**顺延系数大幅下降**（相对正常复评）
- 待讨论：惩罚施加在哪——a) 下次间隔乘惩罚因子（如正常间隔 × 0.5？）b) 强度 S 增量打折 c) 单独的 EARLY_MULT 系数表（区分提前 1 天/3 天/7 天梯度？）
- 参数命名建议 `EARLY_REVIEW_PENALTY`，进 33-44 行参数表

③ **完成页「继续复习」按钮显隐新语义**：
- 用户铁律「永远不可能没有卡复习」→ 按钮**是否应该永不隐藏**（知识库非空就常驻）？
- 全部新卡（无已评分未来卡）时点「继续复习」给什么——新卡本来就当日必学（铁律 1），此时按钮意义=？

④ **穿插算法**（用户构想 3+1）：
- 当日队列内：3 张到期卡 + 1 张新卡循环（比例是否可配？）
- 穿插只影响**展示顺序**，不影响队列成员（成员仍是新卡+到期卡全集）
- 注意与 pickReview* 三段排序的协同（排序定优先级、穿插定呈现节奏）

⑤ **空库引导**：知识库 cards.length===0 时进知识库标签 → 弹「新建卡片」引导（跳知识库页 or 直接弹新建面板？）——单词库空库是否同款处理？

⑥ **「以天为单位」与 0.196.2 拍板的兼容**：旧拍板「当天完成后再进直接跳完成页」被本次推翻的部分，需在 MEMORY.md 标注版本演进关系

## 六、排查过程存档（为什么定位到根因）

- 真机（畅享 90 Pro Max，density 3.0）UI 树实锤：完成页「继续复习」按钮节点**不存在**（非被挤出屏幕）→ `hasFutureContent()=false`

- 用户自述「对手机知识库做过删除测试 + 加了新卡（未学习）」→ 锁定 `isDoneToday` 一刀切：当日完成标记把新卡挡在门外
- 排查方法论沉淀：**静态代码对称 ≠ 运行时行为一致，数据状态差异才是变量**（本轮 5 轮 UI 侧排查教训同源）
