## 一、需求背景（用户原话摘要）

用户看到单词库右上角的「网格排列」按钮（点一下卡片变方块网格），非常喜欢；提出知识库要不要也做类似排列。知识库现状是一行一个的通栏卡片，图片少时显得单调。

**已拍板方案：双视图 + 封面卡网格（知识库特化版，非照搬单词库）**

- **列表模式 = 现状完全不动**（阅读模式：标题居中叠层、标签、图片横滑条、描述、状态全保留）；
- **网格模式 = 新增**（图片浏览模式）：卡片改「封面卡」——首图占卡片上半当封面，**无图的知识卡用紫渐变底 + 占位设计**（解决"0 图卡片显得空/单调"），下半放标题+标签，描述不放；
- 顶栏加一个**和单词库同款同位置**的视图切换按钮，交互习惯与单词库完全一致；
- 手机端不渲染切换按钮（与单词库一致，仅宽屏 PC/Pad 可切），手机保持现有列表。

## 三、封面卡设计规格（知识库特化，本改造的核心新设计）

网格模式下每张卡片结构（自上而下）：

```
┌──────────────────┐
│                  │
│    封面区（约卡片高度 55%）   │  ← 有图：getTitleImages 首张，无则 getCardImages 首张
│                  │  ← 无图：深紫渐变底 + 居中占位（标题首字 或 image.svg 图标）
├──────────────────┤
│ 标题（最多 2 行省略）│
│ 标签 pill（有则显示，最多 1-2 个，溢出省略）│
│ 复习状态小字（11 号，复用 nextReviewLabel/Color）│
└──────────────────┘
```

- 卡片容器：`padding(12)` + `borderRadius(RADIUS_CONTROL)` + `backgroundColor(SURFACE_NODE)` + `borderColor(STROKE_CARD)` + `borderWidth(1)`，与单词库网格卡一致；
- 卡片高度：固定值（参照单词库 150vp 的做法，封面卡建议 **180~200vp**，实现时可微调）；
- 图片字段说明（KnowledgeModel.ets）：
  - `getTitleImages(c)`：titleImages JSON 数组，无则 `[]`；
  - `getCardImages(c)`：images JSON 优先、空/损坏回落旧 `imageUri` 单图；
  - 封面图优先级 = `getTitleImages(c)[0]` → `getCardImages(c)[0]` → 无图占位；
- 无图占位设计要求：紫系渐变（用 `BRAND_PRIMARY`/`BRAND_SECONDARY` 或暗紫底），风格克制、与整体深紫主题协调，**不要用彩色 emoji**。

### 网格模式下的交互取舍（对齐单词库先例）

- **滑动删除（swipeAction）在网格模式不挂**——swipeAction 是 ListItem 专属且与网格拖动冲突，单词库网格同样没有滑动删除；
- 保留：单击（打开图片预览/编辑入口与列表模式一致）、长按多选、右键菜单（`bindContextMenuByResponseType`，参照列表模式 3067-3072 行现有实现）。

## 七、ArkTS 雷区清单（本项目实战踩坑沉淀，写码前必读）

1. **状态成员必须挂 `@Local`**：凡被 `@Computed` 引用或驱动 UI 的状态成员（windowMode/gridCols/gridGap/新 store 挂载点），漏挂真机上依赖链不可靠。KnowledgeBankPage 的 `windowMode` 已挂 @Local（116 行），新加的照抄 WordBankPage 77-78 行。
2. **带参 @Builder 按值传参是雷**：网格卡片若抽 @Builder，注意传参方式（这雷反复复发）。
3. **`swipeAction` 只能挂 ListItem**：GridItem 上无效；网格模式干脆不挂（见三节交互取舍）。
4. **import 必须连续置顶**：新增常量/声明一律插在 import 区全部结束之后，插进 import 之间会触发 `arkts-no-misplaced-imports` 编译错。
5. **PC 右键菜单**：用 `bindContextMenuByResponseType`（列表模式 3067-3072 行已有正确实现可参照）；勿用 `bindMenu`（PC 左键就触发）。
6. **CustomBuilder 箭头函数必须显式 `: void` 返回类型**，漏了静默失效。
7. **宽窄屏判定**：用 `connectWindowMode()` 的 `isTablet`（真相源 `common/WindowMode.ets`，Index 根布局写窗口实际宽度，≥600vp=平板布局），**禁止用屏幕宽度判定**；PC 设备另加 `isPcDevice()`（deviceInfo.deviceType 判定，照抄 WordBankPage 149-152 行）。
8. **响应式布局禁写死固定尺寸**：网格列数/间距走 onAreaChange 连续自适应（见 2.3）；PC 窗口缩到手机宽度仍按 PC 布局规则展示（切换按钮不消失）。

## 十、【追加】「+ 菜单」双库 UI 统一（与双视图同版一起实施）

> 2026-10-15 二次拍板追加。与第一~九章的双视图改造**同一版本交付**（版本号见第六章，不重复递增）。

### 10.1 需求背景（用户原话摘要）

- 知识库右上角「+」弹出菜单 **UI 没对齐**（弹层铺满全宽、位置偏右，见用户截图）；
- **单词库「+」菜单的文字大小、间距特别舒服**（用户原话"特别的舒服"），以它为标准；
- 单词库菜单的**颜色不对**（系统默认菜单底色与 app 主题不搭），但**大小间距要保留**；且它**横向阔度（宽度）也要缩小一点**；
- 知识库弹层"**为什么是在右边而不是在左边，弹出来就放到左边去**"；
- 两库菜单 **UI 统一**：以单词库的字体/大小/间距为标准重新设计知识库菜单；规范要成文（用户确认 UI_GUIDELINES 里目前没有）。

### 10.2 现状与根因诊断（已侦察实锤）

| 库 | 实现 | 位置 | 问题 |
|---|---|---|---|
| 单词库 | 系统 `bindMenu` + MenuElement 数组（新建单词/导入 DagPack（单词包）/导出 DagPack（整库单词）三项） | `WordBankPage.ets` 943-953 行 | 字体/行距=系统默认（用户认可的"舒服"基准）；但系统菜单**宽度不可定制**（右侧留白大）、**配色不可换**（"颜色不对"的根源） |
| 知识库 | 自定义 `bindPopup` + `kbPlusMenuBuilder`（三主项 + drill-down 二级：导入 5 项/导出 4 项 + ‹ 返回） | `KnowledgeBankPage.ets` 798-820 行（按钮与弹层配置）+ 1956-2100 行（builder） | **根因①（弹层全宽）**：每个菜单项 Text 都写了 `.width('100%')`，把弹层撑满可用宽度 → 截图中的"全宽面板"观感；**根因②（弹层偏右）**：`placement: Placement.Bottom`（806 行）= 正下方居中锚定，弹层过宽时向两侧展开、视觉重心落在按钮右侧 |

### 10.3 定案：两库统一「+ 菜单」规格（单词库系统菜单观感 + 主题配色 + 宽度收窄）

| 项 | 取值 | 说明 |
|---|---|---|
