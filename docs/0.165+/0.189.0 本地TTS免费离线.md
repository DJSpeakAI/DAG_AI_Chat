## 2. 实施内容（已落地）

**架构（用户拍板：仅本地，云端取消）**：

```
发音/朗读请求 → LocalTtsEngine（CoreSpeechKit 单例）
                 ├─ canIUse 探测 + createEngine 懒创建（失败 → 调用方 toast 提示，不再回退云端）
                 ├─ 单词发音：直接 speak（短文本单段）
                 └─ 消息朗读：splitTextForTts 分段（280字/段，句末标点优先/逗号次之/硬切兜底）
                              → 首段抢占(queueMode 1) + 后续排队(queueMode 0) 无缝连播
```

| 文件 | 变更 |
|------|------|
| utils/LocalTtsEngine.ets（**新建**） | CoreSpeechKit 封装：探测/懒创建（失败可重试）、splitTextForTts（自 ChatPage 迁入，单一真相源）、会话回调（onStart/onComplete/onError，requestId 集合严格限定当前会话——旧会话迟到回调一律忽略）、stop 幂等；单例 `localTts` 供 WordSpeaker/ChatPage 共用（引擎级互斥） |
| utils/WordSpeaker.ets | 本地引擎化：HTTP 合成→base64→临时文件→AVPlayer 链路全删；三态 🔈/⏳/🔊 标志沿用；`speak(word, onUnavailable?)` 签名简化（config/cacheDir 参数移除） |
| components/ChatPage.ets | 消息朗读直连 localTts（云端分段管线 requestNextSegment/tryPlayNextAudio/cleanupSegment/playSegment + 11 个管线状态全删）；stopTTS 简化为停引擎+清状态；3 处发音调用点更新；media/BusinessError import 移除 |
| components/WordBankPage.ets | 发音调用点更新（同款） |
| utils/ApiClient.ets | **synthesizeTTS + openspeech 协议接口整体移除**；util/BusinessError import 清理；配置存档指向本文 §9 |

**保留不动**：设置页音频配置字段（audioEndpoint/audioKey/audioModel/audioVoice，ApiConfig 持久化）——按用户要求留作未来恢复云端的现成配置，当前休眠无害。

## 3. 三态 UI 语义（沿用）

- 🔈 空闲 → 点击开播（本地引擎启动极快，⏳ 一闪而过）
- ⏳ 引擎启动中（ttsLoadingMessageId / loadingWord）
- 🔊 播报中（playingMessageId / speakingWord）→ 点击即停
- 互斥不变：消息朗读 ↔ 单词发音（共用引擎实例，天然互斥；UI 标志由 stopTTS/wordSpeaker.stop 交叉复位）

## 4. 风险与对策

| 风险 | 对策 |
|------|------|
| 纯英文单词发音质量（zh-CN 引擎读英文） | 真机试听验收；不合格 → 升级路径：为单词发音懒创建第二个 en-US 引擎（person 8 Laura，需下载语音包；实例上限 3 个内） |
| 旧固件无引擎（如手机未升级） | canIUse + createEngine 双重探测 → toast「本机语音引擎不可用」，功能不崩 |
| 首次语音包下载弹窗 | 引导允许；createEngine 失败可重试（creating 置 null） |
| queueMode 固件差异（若不被支持→段间互相打断） | 验收项 2 盯长文连播；不合格改链式喂段（onComplete 后发下一段，一行改动） |
| 音色单一（聆小珊女声） | 接受；未来 listVoices + 设置开放 |

## 5. 验收标准（真机）

1. **断网/飞行模式**：单词发音 + 消息朗读均正常（离线实证）
2. 长回复（>500 字）朗读完整、段间无缝、无突兀停顿
3. 播放中点喇叭即停；播新停旧；消息朗读 ↔ 单词发音互斥不变
4. **英文单词发音试听**（Harmony/Serendipity/Operating System）——合格则收工，不合格走 en-US 引擎升级路径
5. 火山费用账单：TTS 调用归零（省钱实证）
6. 首次使用若弹语音包下载 → 允许后功能正常

## 9. 火山云端 TTS 配置存档（恢复时照抄）

> 用户原话：「找这个内容 url 我真的花了好长时间，说不定以后会用到，直接用上就行」。
> 代码级恢复：git 历史 commit `be98570` 的 `ApiClient.ets synthesizeTTS`（0.139 版完整实现）。

| 项 | 值 |
|----|----|
| 端点 | `https://openspeech.bytedance.com/api/v3/tts/unidirectional`（openspeech 2.0 协议，HTTP Chunked 单向流） |
| 鉴权 | Header 三件套：`X-Api-Key`（**豆包语音 Key，与方舟对话 Key 相互独立**）+ `X-Api-Resource-Id`（模型资源 ID）+ `X-Api-Request-Id`（每次唯一 UUID） |
| 模型资源 | `seed-tts-2.0`（存于 App 设置「音频模型」= audioModel） |
| 音色 | `zh_female_vv_uranus_bigtts`（**2.0 专用音色，2.0 模型只能用 2.0 音色，1.0 音色会报错**） |
| 请求体 | `{ req_params: { text, speaker, audio_params: { format: 'mp3', sample_rate: 24000 } } }` |
| 响应 | Chunked 流式 JSON：`data` 字段 = base64 mp3 片段（多段拼接），`code=0` 成功 |
| App 设置项 | audioEndpoint（端点，留空自动用官方端点）/ audioKey（豆包语音 Key）/ audioModel（资源 ID）/ audioVoice（音色，留空用默认）——**字段仍在 ApiConfig 持久化，设置页未动** |
| **历史教训** | ①方舟 `ark…/audio/speech` 端点**不服务**语音合成模型（0.134/0.137 真机两次 HTTP 404 实锤——模型与端点绑定）②豆包语音 Key 与方舟对话 Key 是两套独立 Key ③2.0 音色与 1.0 音色不通用 |
