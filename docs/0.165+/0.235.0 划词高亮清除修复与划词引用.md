## 二、Bug：手机端划词高亮点空白不消失 / 两段同时高亮

### 2.1 现象（用户实机截图 + 口述）

- 设备：**仅手机**复现；Pad 无法复现。
- 场景：在对话页长按 AI 回复中的文字（如"允许"、"声明时"）进入划词态，悬浮工具栏（翻译/入知识库/复制/删除）正常弹出；
- 之后**点击页面空白处**，预期：选中高亮消失、工具栏收起。实际：**高亮像被"标记"了一样滞留不消失，点击无效**；
- 更严重：**两段相距很远的文字同时处于高亮状态**（截图实锤：同一条 AI 回复里"允许"与"声明时"两段同时高亮）——两次独立的长按选择叠加，第一段的选择态从未被清除。

### 2.3 根因分析（四条，按嫌疑权重排序）

**根因 1【主因·两段同时高亮】：系统选择态的取消链路全靠 `onDisappear` 单点，且「取消选择回调」被吞。**
- Text 内部选中高亮由**系统**维护；应用层唯一的撤高亮途径 = `onDisappear` 回调触发 `clearSelectionState`。
- `handleSelectionChange` 对取消选择时的 `(0,0)`/`(-1,-1)` 回调**直接 return**（2284-2286 行）——即系统明确告知"选中已取消"时，应用层什么也不做，全押 onDisappear。
- 手机端 onDisappear 存在**不触发 / 晚触发**的实测迹象（自研菜单滞留是 0.195.0 就修过一次的老毛病，见 4612-4613 注释）。一旦 onDisappear 缺席：selKey 残留非空、系统高亮滞留 → 用户长按第二段 → 两段同时高亮。**这正是截图现象。**

**根因 2【点空白无效】：根容器 onClick 在手机触摸场景下不派发。**
- 4610 行根 onClick 是唯一空白兜底，但 ArkUI 点击不冒泡 + 手机上高频滚动：点击落在 List 滚动手势竞争区间（fling 中、小幅滑动被判定为滚动而非点击）时，**onClick 不触发** → closeActiveSelectionMenu + clearSelectionState 都不执行 → 高亮+工具栏双双滞留。
- Pad 屏幕大、滚动操作少、（可能外接鼠标）点击判定更"干净"，所以不复现——这是"仅手机"的主要解释。

**根因 3【selKey 失配】：closeActiveSelectionMenu 的闭环依赖 selKey，selKey 空则静默失败。**
- 若 onDisappear 先行清空了 selKey 但 Text 系统高亮未退（回调与内部状态不同步），之后用户点空白 → selKey='' → closeSelectionMenu 不被调用 → 无任何代码能撤掉那段高亮。
- 另外 PC 右键路径（3863 行 bindContextMenu RightClick）只靠 bindSelectionMenu 的 onAppear 设 selKey，右键打开时 selKey 可能未设置——同族失配。

**根因 4【全选受控残留】：selectAllKey 命中的 Text 其 `.selection(0, len)` 全选高亮，清除依赖 @Local 变化驱动重渲染。**
- 点「全选」后该 Text 被受控全选高亮；`clearSelectionState` 清 selectAllKey 后属性参数从 (0,len) 变回 (1,0)，**理论**上应触发复位重渲染；但若该 Text 因 ListItem 复用/未重绘而未重应用属性，高亮残留（ForEach 复用场景，手机长列表更常见）。

### 2.4 修复建议（实施方按此方向落码，可组合落地）

**修法 A（必须）——把「取消选择回调」纳入清理链路**：
`handleSelectionChange` 收到 `(start<0 || end<=0)` 的取消回调时，不再直接 return：
- 若 `this.selKey` 非空：执行 `clearSelectionState()`（保留 sticky 副本不动，防表格场景回归 0.191.0 老 bug——sticky 三个变量仍不清）。
- 这样系统态取消时应用层状态同步归零，杜绝"菜单没了、状态还在"。

**修法 B（必须）——lastSelKey 副本兜底 closeSelectionMenu**：
`handleSelectionChange` 与 `onAppear` 里把 key 同时记入 `private lastSelKey`（**不被 clearSelectionState 清理**）；`closeActiveSelectionMenu` 改为优先用 `selKey`、为空时退用 `lastSelKey`。保证点空白时即使 selKey 已被清，仍能对残留菜单的 Text 调 closeSelectionMenu。

**修法 C（必须）——List 空白区加 onTouch 兜底**：
在消息 List（4383 行附近，仅记录阅读位置的那个 Scroll/List）上挂 `.onTouch((event) => { if (event.type === TouchType.Up) { ... } })`，Up 时执行与根 onClick 相同的 `closeActiveSelectionMenu() + clearSelectionState()`。注意：
- 只在 `selKey.length > 0 || selectAllKey.length > 0` 时执行（无选中时不动作，避免干扰正常交互）；
- 不要打断 List 自身滚动（onTouch 只读不拦截，不 return true）。

**修法 D（建议）——全选残留强制复位**：
`clearSelectionState` 清 selectAllKey 时同时 `this.selectAllNonce++` 无效？——不需要，属性参数 (0,len)→(1,0) 本身是变化。若实测仍残留（ForEach 复用不重绘），备选方案：给受全选的 Text 追加一次无效化再恢复（或改用 `selection` 参数绑定 nonce 参与比较）。实施时先真机验证 D 是否必要，**不做过度设计**。

## 三、新功能：划词「引用」

### 3.1 需求描述（用户口述整理，已确认）

在划词悬浮工具栏的**「入知识库」右边**新增「引用」按钮。用途：用户选中一段代码/文字后引用它去提问，发送时把引用内容注入 prompt，让 AI 围绕这段内容讲解、回复更有针对性。

### 3.2 交互设计（用户拍板，逐条落实）

1. **按钮位置**：SelectionToolbar（ChatPage.ets:3213-3284）中「入知识库」按钮右侧、分隔线同款样式，新增 `Text('引用')`，字号/颜色/内边距与「翻译」「入知识库」一致（BRAND_SECONDARY、fontSize 14、padding 14/8）。
2. **点击「引用」→ 弹两个选项**（二选一交互，样式参考应用内现有弹窗/菜单风格，暗紫主题）：
   - **「引用到本聊天」**：引用挂到当前气泡对话的输入区；
   - **「引用为新子气泡」**：创建一个新的子气泡（复用现有"创建子气泡"成熟链路：ID/父子关系/埋点/保存全带，参照 0.214.3 长按菜单「增加子气泡」的实现），并进入该子气泡对话页，引用挂到其输入区。
3. **引用栏（引用生效后的呈现）**：输入框上方出现**一个小行/小栏**（位置参照图片预览栏 pendingImages 的布局层级，输入区 padding 内、输入框之上）：
   - 文案格式：`引用：前5个字...`——**取引用内容前 5 个字符 + 省略号**（不用铺满全文，用户明示）；
   - 栏上带一个 **× 取消按钮**（点击可撤销引用；用户未明说，但撤销是必须的——引错了没法取消会很难受）；
   - **★ 用户明确拍板：点击引用栏不跳转**到原文位置（"创建子气泡后再跳转很傻"），引用栏纯提示，不可点跳转。
4. **发送行为**：点发送后：
   - 组装 prompt 时**注入引用内容**（格式建议见 3.3）；
   - 发送后引用栏清空（引用一次性消费）。
5. **作用范围**：本次只做对话页正文划词（SelectionToolbar）；复习区工具栏（ReviewSelectionToolbar）与放大弹窗内划词**不加**引用按钮（非消息文本，无挂靠对象）。

### 3.3 技术方案建议

**新增状态（ChatPage.ets state 区，@Local）**：
```typescript
@Local quoteText: string = '';      // 完整引用内容（''=无引用）
@Local quoteSourceLabel: string = ''; // 引用栏显示标签（前5字...）
@Local quotePendingTarget: string = ''; // ''=引用到本聊天；'new-child'=待创建的子气泡引用
```

**关键落点**：
- **工具栏按钮**：SelectionToolbar 插入「引用」（见 3.2 第 1 条）；点击后先取 `selText`（同 onToolbarTranslate 的"先取值再 close"模式，2344 行注释——closeSelectionMenu 可能同步触发 onDisappear 清状态），再弹二选一。
- **二选一弹窗**：应用内已有同款风格弹窗可参照（知识库移动/复制选择弹窗、加词目标文件夹选择弹窗 wordFolderPickerVisible，575 行）——建议复用其视觉规格（暗紫卡片、按钮列表）。
- **「引用到本聊天」**：填 quoteText/quoteSourceLabel → 渲染引用栏 → 发送时注入。
- **「引用为新子气泡」**：调用现有"创建子气泡"链路（0.214.3 落码于 BBTreeCanvas.ets 长按菜单，ChatPage 内对话页也有同款链路——**先搜 `createChild` / `增加子气泡` 找到现有函数复用，勿重造**）→ 拿到新气泡 nodeId → 导航进入 → 填 quoteText → 引用栏出现。
- **发送注入（prompt 组装处）**：搜 `sendMessage` / ApiClient 调用点，在 user 消息文本前拼接引用块：
  ```
  【用户引用了以下内容，请重点围绕这段内容回答】
  ${quoteText}
  【引用内容结束】

  ${用户输入的问题}
  ```
  ★ Prompt 写法遵守 project_rule.md §8 军规：边界标记明确（首尾都有【】边界）、指令具体（"围绕这段内容回答"）、无歧义。
- **发送后清理**：quoteText=''; quoteSourceLabel=''; quotePendingTarget=''。
- **草稿交互提醒**：输入框已有气泡独立草稿机制（0.214.2，draftText 挂 BubbleNode）。引用栏状态**不进草稿**（一次性会话态，切走即失），避免动 Schema（Schema 铁律：字段只增不删，能不动就不动）。
