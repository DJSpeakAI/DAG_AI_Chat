# 0.312.0 SP 云函数权威记账（B 方案·根除云空间白嫖）

> 用户拍板（2026-10-24）：「b 必须这样，而且一开始就得这样，再困难也得干。现在还没上新无所谓，
> 要是以后真有用户了，那才是灾难级别的。」——这是架构级修正，优先级最高。

## 一、病根（已实锤）

SP 账本存放在华为云空间（cloudSync）的行 `cfg:siyi-points` 里：
1. 系统后台关闭「云空间 → DAG AI Chat 数据同步」后，cloudSync 静默不报错、上行失败；
2. 客户端仍按本地账本扣 SP（`consumeSiyiSp`），AI 功能照常可用；
3. 用户卸载重装 / 换设备后，云端旧值（未扣）下行恢复 = **白嫖**。

平台限制（官方文档实锤）：
- 华为**没有**「系统云空间应用同步开关」查询 API（`@ohos.data.cloudData` 仅有策略设置/触发监听）；
- `queryAllRows` 读的是**本地 RDB**，系统开关关闭后本地缓存行仍在 → 现有假开启探针在「曾开启后关闭」场景假阴性。

结论：只要消费记账依赖云空间通路，就永远堵不住。**记账必须走独立于云空间的权威通道。**

## 二、目标架构

- **云端唯一真相**：Cloud DB `SpMirror`（objectId=accountId）升级为权威余额账本；`SpLedger`（objectId=txId）为流水+幂等键。
- **云函数事务**：一切 SP 消耗/发放必须云函数成功后才在客户端生效（扣不动/加不上 = 功能不可用）。
- **客户端**：本地 SP 仅为云端返回的只读镜像（展示）；门卫 `siyiGateReady` 改为「登录 ∧ 云函数账本通道可用」。
- **云空间**：仍负责对话/词库/知识库等内容同步，**不再承载 SP 账本**。

## 三、云函数接口（sp-admin 扩展）

| action | 入参 | 出参 | 语义 |
|---|---|---|---|
| `sp_balance` | accountId | ok/bal/四池/welcomeGranted/updatedAt 或 err=no-account | 查权威余额 |
| `sp_spend` | accountId, txId, cost, scene, note | ok/cost/bal（幂等重复返回 duplicate:true） | 事务扣点：gift→bonus→perm 顺序；不足返回 err=insufficient |
| `sp_grant` | accountId, txId, src, amount, pool, note | ok/bal | 事务加池（签到/礼包/任务/完赛奖） |
| `sp_init` | accountId, 四池/welcomeGranted, txId | ok/bal | 仅云端无记录时写入（旧账号本地值迁移一次；已有记录忽略，绝不覆盖云端） |

铁律：
- 幂等：客户端每笔事务带唯一 `txId`（= messageId/任务 id/日期），重复请求返回首次结果，防重试双扣。
- 并发：读-改-写 + `version` 递增；多端同时扣的极小概率丢更新=少扣（对用户有利、不产生负余额）——与现有 SP 铁律口径一致。
- 金额一律 Integer（Cloud DB 32 位，禁毫秒戳）。

## 四、客户端改造（分阶段）

**Phase 1（本轮）**：云函数四接口 + `SpAdminUtil` 客户端封装 + 方案文档 + 本地直调冒烟。
**Phase 2**：`consumeSiyiSp` 切云扣（流式完成后带 messageId 事务扣；失败进幂等重试队列）；门卫/余额展示改为云端镜像；5 个消费入口（发送/重生成/划词/圈注/朗读）统一走门卫。
**Phase 3**：发放类（签到/礼包/新手任务/完赛奖）迁 `sp_grant`（云端防伪）；旧账号迁移（`sp_init` 只写空账）；云空间 SP 行退役（Schema 保留不删，停止读写）。

## 五、风险与约束

- **数据安全**：迁移只走 `sp_init`「云端无记录才写」，绝不覆盖已有云端余额；本地账本不删除（降级可回退）。
- **离线**：无网络 = 云函数不可用 = SP 功能不可用（符合 SP 铁律「无网络不能用 SP」）；内容浏览不受影响。
- **红线**：`CloudSyncUtil.ets` 不改；SP 相关持久化 key 不改。
- **外部依赖**：云函数更新需用户在 AGC 控制台「提交」生效（10~20s 滚动更新）——按小白步骤输出。

## 六、验收

1. 本地直调：`sp_init`→`sp_balance`→`sp_spend`（重复 txId 不双扣）→`sp_spend` 超额返回 insufficient。
2. 真机：系统后台关云空间 → 发送 AI → 余额云端仍正确扣减；再换设备/重装 → 余额与云端一致（无法白嫖）。
3. 离线：断网发送 → 拦截并提示（不再本地扣）。
