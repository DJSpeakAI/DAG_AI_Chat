## 四、技术方案

### 4.1 新建 `entry/src/main/ets/utils/IapUtil.ets`（唯一新文件）

```
常量：
  PRODUCT_SP_200W = 'dagai_sp200w'  → SP_AMOUNT: 2_000_000
  PRODUCT_SP_400W = 'dagai_sp400w'  → SP_AMOUNT: 4_000_000
  （用 Record/Map 维护 productId → SP 额度映射，未知商品拒到账）

函数（全部 async，错误全捕获、返回结构化结果而非 throw）：
  ensureIapReady(): 协议与环境准备
    - IAP.applyIapAgreement()（首次拉签约弹窗，用户签过则静默通过）
    - IAP.queryEnvironment()（环境检查；返回结构以 SDK d.ts 为准）
  querySpProducts(): IAP.queryProducts（skuList=两个商品ID，消耗型）
    - 返回商品信息+展示价；失败返回 null（UI 用保底价 ¥9.9/¥19）
  purchaseSp(productId): 完整购买流（核心）
    1. ensureIapReady
    2. IAP.purchaseProduct（拉起收银台，系统托管 UI）
    3. 成功回调后校验：productID 匹配 + purchaseState=已购买（枚举以 d.ts 为准）
    4. 幂等到账：查本地已消耗记录，未消耗过才 grantSiyiSpFromIap()
    5. IAP.consumePurchase(purchaseToken)（消耗型商品发货后必须消耗，
       漏消耗=二次购买报「已拥有」）
    6. 消耗成功后 purchaseToken 记入已消耗集合（防重复回调双入账）
  错误分类：用户取消（静默/轻提示「已取消」）；其余 → 友好中文提示（铁律：禁原始英文报错）
```

**⚠️ API 细节三条铁则**：
- IAP Kit API 的**函数名/参数/枚举/返回字段一律以本机 SDK d.ts 实测为准**（搜 `@kit.IAPKit` 或 iap 的 .d.ts 文件），禁止凭记忆或网文写（本项目「键码凭印象写翻车」前科：Enter 写成 2016，实际 2040）。
- **ArkTS 雷（项目两次实踩入档）：namespace 类型经 kit（@kit.XxxKit）re-export 后，类型标注/推断会解析失败**——若 `import { IAP } from '@kit.IAPKit'` 后 Product/Purchase 等类型报错，修法=类型改从原始模块源（@hms 层）import，值可从 kit 拿。
- purchaseProduct 的回调/返回结构（purchaseToken、productID、purchaseState、orderTrailingInfo 等字段名）编译期逐一对 d.ts，勿猜。

### 8.1 与原方案的偏差（全部以实测为准）

| # | 原方案 | 实际落地 | 原因 |
