> 用户裁决记录（2026-10-12，123.txt + 会话原话）：
> 「如果说需要我 Ctrl+C Ctrl+V 到终端里面去配置的话，那你就是弱智」
> 「自动化自动化自动化」「你凭什么让我来做事情」
> 「你可以让我来做，但你要告诉我为什么这个东西你做不进去、为什么必须我来做」

## 一、需求本质

**测试台从「半自动+人工配合」升级为「双击即用全自动」**。用户手动白名单只允许一件事：华为账号授权弹窗（系统级安全红线，任何自动化进不去——这是唯一合法的「必须你来做」）。

## 二、手动场景清杀清单（逐条自动化）

| # | 原手动场景（用户痛点来源） | 自动化方案 |
|---|---|---|
| 1 | 服务没起 → 页面引导「复制命令到终端跑」（123.txt 豆包方案，用户怒点） | **桌面唯一入口=启动器**：双击自动检测服务→不在线自动拉起→自动开浏览器（http://127.0.0.1:8766，绝不 file://） |
| 2 | EADDRINUSE 端口占用 → 手动 `lsof`/`kill -9` | **server.js 启动自愈**：bind 前健康探测 8766——健康=复用直接退出（幂等）；被占不健康=自动杀占用进程再 bind。EADDRINUSE 崩溃栈永不再现 |
| 3 | 终端窗口不能关（关=服务停） | 服务**后台常驻**：nohup setsid 脱离终端，窗口可关；日志落 server.log |
| 4 | 页面里「办法一：去 AI 对话说起一下测试台」引导文案 | **删除**。页面=用户自用入口，AI 驱动是对话侧的事，页面上不出现 |
| 5 | 换环境要改代码改端口 | **右上角「本地/服务器」环境切换**（默认本地——鸿蒙 PC 快；服务器 192.168.2.15 备用），服务器 IP 可编辑、localStorage 记忆 |
| 6 | 手机 WiFi 注册要改 config.json | 设备卡**串号/IP 可编辑**，服务端热更新设备表 |
| 7 | 跑完不知道哪里坏、要自己翻日志 | 结果页红绿汇总 + **「复制问题报告给 AI」按钮**：一键复制失败用例+步骤+细节，粘到对话里 AI 直接接管排查 |
| 8 | 双击 html（file://）跨域失效 | 入口统一走 http；html 直接双击打开时给一句话「请双击桌面『测试台』图标」（不再教命令） |

## 三、技术方案

### 3.1 server.js 自愈启动（改动 ~40 行）
```
启动流程：
1. GET /api/health（自探测 8766）
   ├─ 200 → 已有健康实例 → 打印「服务已在线」退出（幂等）
   └─ 失败/超时 → 继续
2. 尝试 listen
   ├─ 成功 → 正常启动
   └─ EADDRINUSE → 僵尸进程 → lsof -t -i:8766 逐个 kill -9 → 重试 listen（最多 3 轮）
```

### 3.2 桌面启动器（唯一入口）
`启动测试台.sh`（桌面「DAG AI Chat/测试台」图标）：
- 健康探测 → 不在线 nohup 拉起（后台，窗口可关）→ sleep 等监听 → 调起系统浏览器开 http://127.0.0.1:8766/测试台.html
- 服务启动时自动同步桌面副本（沿用 0.229.1 syncDesktop 机制）
- 电脑重启后服务停 → 双击一次即恢复（全自动，零命令）

### 3.3 前端改造（index.html）
1. header 右上角环境切换 pill：`本地 | 服务器`，默认本地；服务器模式下 IP 输入框（默认 192.168.2.15:8765，可改可存 localStorage），所有 api() 走所选 base
2. 删 guide 页「办法一 AI 对话」引导；保留一句话 + 桌面图标指引
3. 设备卡：手机/自定义设备可编辑 serial（点「编辑」弹行内输入，保存 POST /api/devices/update → 服务端写 config.json 热生效）
4. 跑完（run-end）：底部出汇总卡「✗ N 项失败 · [复制问题报告]」——复制内容=失败用例名+步骤+detail 摘要（用户粘贴给 AI 即接管）
5. 小白引导首条：页面顶部一行灰字「①勾用例 ②勾设备 ③开始测试——授权弹窗时需要在设备上点一下（华为安全红线）」

### 3.4 新增 API
- `GET /api/health`（无鉴权轻量探活，供启动器/server 自愈/前端探测三用）
- `POST /api/devices/update`（编辑设备 serial/IP，热更新）

## 四、必须用户做的唯一一件事（含理由）

**华为账号授权弹窗**：系统级安全设计，授权绑定用户真实华为账号+设备指纹，任何自动化框架（含 ArkUI test/uitest 注入）都会被系统拒绝。这不是技术做不到省事，是华为安全红线，绕过=违反平台规则。
除此之外一切环节（起服务/杀僵尸/装机/跑用例/出报告）全部自动化。

## 五、改动文件
- `testing/console/server.js`：健康探测+自愈 bind+设备热更新 API+（AI 驱动侧不变）
- `testing/console/public/index.html`：环境切换/删 AI 引导/设备编辑/报告复制/小白引导
- 桌面：启动器图标 + html 副本（自动同步）

## 六、风险
1. 鸿蒙 PC 双击 .sh 的执行行为需实测（若系统不执行，改 .hlink 或其他桌面入口形态，实测后定）
2. 自愈 kill 有误杀风险：仅杀「占用 8766 且健康探测不通」的进程，杀前二次确认端口归属
3. 服务器模式（老机器 8765）跨机 hdc 不可达时用例自动降级跳过（提示原因，不报错）

## 七、验收标准
1. 双击桌面入口 → 浏览器自动打开页面且服务在线，全程零终端、零命令、零复制
2. 重复双击入口/重复 node server.js → 幂等，无 EADDRINUSE 崩溃
3. 僵尸进程占端口 → 双击入口自动清障恢复
4. 关掉服务窗口/重启电脑 → 双击入口一键恢复
5. 跑完测试 → 一键复制失败报告，粘贴到 AI 对话可直接排查
6. 页面全文搜不到「去 AI 对话里说」「复制命令」类文案

## 八、实施结果（2026-10-12 当晚完成，全链路实测通过）
- ✅ 验收 1~6 全过：僵尸占端口→自愈 12 秒接管；幂等双启动 exit 0；VERSION 用例双端真跑 pass×2 落盘 results.json；桌面副本自动同步含启动器
- **实施中破的三层坑（入档防复发）**：
  1. probeSelf 只看 HTTP 200 会被僵尸骗（任意 200 文本）——必须校验 body JSON `ok:true+version`
  2. 本机 lsof 三重坑：`/system/bin/lsof` 是阉割版（无 -i）；`/usr/bin/lsof` 完整版但 `-t` 输出空、`-p` 直接卡死——**端口→PID 改走 inode 双通道**：pid 文件 + hdc shell 读 `/proc/net/tcp`（用户态 Permission denied，shell uid 可读）拿 inode → 本机扫 `/proc/*/fd` 匹配 `socket:[inode]`
  3. 浏览器唤起通道：`hdc -t <本机调试口动态探测> shell "aa start -a MainAbility -b com.huawei.hmos.browser -U http://…"`（com.huawei.browser 不存在，实名 hmos.browser）
- 服务器模式为前端骨架（切换+IP 可编辑+可达性探测）；老机器侧部署同款服务属后续事项（把 testing/console/ 拷过去即可，CORS 天然通）
