## 二、切库 pill「点不回来」根因（已侦察实锤）

### 根因 1：pill 点击事件冒泡 → 一次点击双发两个 call

`ReviewWidgetCard.ets` 结构：切库 pill 是卡身 Column 的**子组件**，ArkUI 点击事件默认冒泡：

```
点击「单词库」pill
  ├─ pill.onClick → sendSwitch('word')     ← 想要的
  └─ 冒泡到卡身 Column.onClick → sendFlip() ← 意外的（双面模式且未翻面时条件命中）
```

一次点击同时发出 `widgetSwitch` + `widgetFlip` 两个 `postCardAction call`。系统对卡片 call 请求有节流，第二个请求可能被丢弃：

- **丢 switch** → 只剩 flip 生效 → 用户看到的是「翻面了」而不是「切库了」→ 体感=切库没反应；
- flip 先处理 + switch 后处理 → 切到新库但 flipped 状态被翻转污染。

翻面后（flipped='y'）卡身点击不再响应（0.209.3 终态规则），此后点 pill 只发 switch 单请求——但状态已被污染/节流窗口已消耗，表现就是「切不过去、点不回来」。

### 根因 2：call 主链路切库不重置翻面态（两链路不一致）

- `WidgetReviewUtil.processWidgetCommand`（message 备用链路）switch 分支：有 `s.flipped = 'n'`（372 行）✓
- `WidgetHostBridge.handleWidgetSwitch`（call 主链路，EntryAbility 实际走的）：**只切 mode，不重置 flipped**（159-169 行）✗

切库后可能停留在「反面已翻」态，与新库「先看题面」语义矛盾。

### 修法（两处）

1. `switchPill` 的 onClick 加 `event.stopPropagation()`——pill 点击不再冒泡触发翻面，单发 call 稳定到达；
2. `handleWidgetSwitch` 补 `s.flipped = 'n'`——切库一律回正面，对齐 message 链路语义。

## 三、三种形态统一排版（固定双面后）

三形态统一「题面/答案面」双态语言，弱化装饰、强化背诵聚焦：

| 形态 | 正面（题面） | 反面（答案面） |
|------|-------------|---------------|
| 2×2 紧凑 | 进度行 + 标题 1 行（居中放大）+「点击查看答案」提示 | 释义 2 行（紧跟）+ 三档小按钮 |
| 2×4 标准 | 切库 pill + 进度 + 标题 2 行（居中放大）+「点击查看答案」提示 | 标题缩小置顶 + 释义 4 行 + 三按钮 |
| 4×4 大卡 | 切库 pill + 进度 + 统计行 + 标题 3 行（24fp 居中）+「点击查看答案」提示 | 标题置顶 + 释义 8 行 + 三大按钮（带副标题）|

设计要点（消化截图分析问题点）：
- 正面大留白居中=背诵聚焦设计（一次只看题面）；反面释义紧跟标题（间距收敛），答案与题面视觉强关联；
- 评分按钮只在反面出现=先回忆后自评，语义更清晰；
- 「点击查看答案」提示文字代替原「点击卡片翻面查看」，动作指令更直白；
- 左下角 siyiLine 行删除后，底部空间还给内容区。

## 六、司忆区数字校验误报 Bug

### 现象

全局设置 → 司忆区 Tab → 单词库词条数 / 知识库卡片数，输入 12 点「确定」，报红字「请输入 0~20 的整数」。

### 根因分析

四处校验代码静态逻辑（`parseInt + 0~20` 区间判断）对 "12" **均应通过**（已逐处核对：GSD 2241/2327、WordBankPage 1454、KnowledgeBankPage 1090）。真凶锁定为**运行时输入值污染**：

- `InputType.Number` 在第三方输入法（composition 合成期间）过滤不严，可能上送**全角数字（１２）/ 空格 / 零宽字符**混入的字符串；
- `parseInt("１２") = NaN` → 走报错分支 → 合法意图被误报。

### 修法（双防线，四处统一）

1. **onChange 即时清洗**：输入时直接剥掉一切非半角数字字符 `v.replace(/[^0-9]/g, '')`（全角/空格/不可见字符进不了状态）；
2. **提交时兜底清洗**：「确定」回调里先清洗再 parseInt，双保险。

落点：GlobalSettingsDialog.ets ×2 + WordBankPage.ets ×1 + KnowledgeBankPage.ets ×1。
