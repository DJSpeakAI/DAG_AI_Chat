## 一、交互定案（方案一，用户已拍板）

- 点 + 直接拉起**文件选择器**（DocumentViewPicker 混选），图片/文档随便选，不加分菜单
- 代价（已知情接受）：选图界面从「相册九宫格」变为「文件管理器视角」（内有图片分类 tab）
- **上限：图片+文档合计 9 个**（沿用现有 9 上限，只是口径变为合并计数）
- 文档在待发区显示为文件条（文件名+类型图标+大小），图片照旧缩略图

## 二、解析架构（格式 → 路由表）

| 格式 | 走哪 | 理由 |
|---|---|---|
| txt / md | **本地直读** | 零成本 |
| xlsx | **本地 ExcelJS** | 项目已有依赖（ImportUtil 先例），转 Markdown 表格 |
| docx / pdf | **腾讯云端**（多模态文档解析） | 本地解析 PDF 不可行（华为 PDF Kit 无全文抽取 API 实锤）；docx 云端表格/排版质量高，不写本地解压代码 |

未配置腾讯 key 或断网时：选 docx/pdf → 友好提示「需配置文档解析服务」，txt/md/xlsx 不受影响。

## 三、云端链路（腾讯·异步接口定稿，客服答复已实锤）

```
读文件 → base64 → SubmitMultimodalDocParseJob(FileBase64) → 轮询 DescribeMultimodalDocParseJob
→ 拿结果ZIP下载链接 → 下载解压(@ohos.zlib) → 读 .md → 字数钳制 → 注入
```

- **走异步接口**（Submit + Describe 配套）：入参 `FileBase64` 直传 base64，JSON 请求体，无 multipart；TaskId 30 天内可查
- **同步接口弃用**（只收 FileUrl，纯客户端无公网 URL 不可用）；旧 lkeap 接口 12-31 下线也弃
- **客户端硬上限 6MB**（官方 8M 口径未明确是否含 base64 膨胀，按 1.33 倍膨胀倒推 6M 安全线，常量可调）；>6MB → 拦截提示「请拆分文件」
- 输出只要 Markdown（ResultType）；结果 ZIP 链接 30 分钟有效，立即下载
- 扫描件 OCR 原生支持；大文件分段参数（FileStartPageNumber/EndPageNumber）留二期
- >6MB 大文件 COS 中转（FileUrl 路径）= 二期升级项，MVP 不做
- 计费嫁接 SP（★ 用户拍板）：解析成功后 `页数 × 0.04 元` 按 DeepSeek 输入价折算等效 input token（0.04 元 ≈ 2 万 token @ 2 元/百万，系数做常量可调）→ 并入本次请求 input token 总账，走 spCostOf 同源公式**一次实扣+明细展示**；**解析失败/返回错误 = 免费，零扣费**
- 双提醒（★ 用户拍板）：
  - 文件档位：≤2MB 正常走；2~6MB 强确认弹窗「文件较大，页数多则解析费用高（0.04 元/页），是否继续」；>6MB 拦截提示拆分
  - 计费透明：感叹号信息卡（TokenInfoChip 先例）逐项列明「文档解析 N 页 + 折合 SP」；首次带文档发送弹一次计费告知（此后发送即视为同意）
- 鉴权：TC3-HMAC-SHA256 签名，鸿蒙 @kit.CryptoArchitectureKit 自实现（一次性工具函数）
- 密钥走用户个人 CAM SecretId/Key；DocParseUtil 做成**通用文档解析地基**——未来「批量上传 PDF 制作知识卡片」直接复用（用户定的前瞻）

**⚠️ 唯一未决（架构分支）**：入参是否支持 base64 直传？
- 支持 → 上面链路成立（简单）
- 只支持 URL → 中间还要加「上传 COS 拿 URL」一段（复杂度上升，届时回来重审）
- **确认方式**：API Explorer 看 866/133224 入参有无 FileBase64/FileContent 字段，或问腾讯客服

## 四、注入链路（零 Schema 改动，避开红线）

复刻 0.286「AI 读网页」成熟先例：发送时把解析出的文档文本拼成 **system 一次性副本注入**本次请求。
- 不改 ChatMessage Schema、不碰持久化 key、不碰 CloudSyncUtil（全部红线绕行）
- 限制与读网页相同：**重生成/翻历史不重复带文档内容**（先例已被接受）
- 字数钳制：单文档 3 万字、合计 6 万字，超限截断+提示
- SP：文档字数计入本次 input token，按既有公式实扣实展（军令天然满足）

## 五、密钥模式（A 模式，用户已拍板）

用户在全局设置里填**自己的**腾讯 SecretId/SecretKey（与现有 DeepSeek/火山 key 完全同构，风险自担，零后端）。
客服警告的"密钥下发"风险仅适用于 B 模式（开发者统一 key 分发），留作上架后升级路径（AGC 云函数有 trackEvents 先例）。
