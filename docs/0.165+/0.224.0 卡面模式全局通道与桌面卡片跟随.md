# 0.224.0 卡面模式全局通道（司忆区+桌面卡片跟随）

> 2026-10-12 立项。用户需求：卡面模式（单面/正反两面）从「两库独立」升级为**全局单通道**——一处设置处处生效：卡片复习页、司忆区两处（AI 聊天下方复习区+屏幕圈选提炼弹窗复习区）、桌面卡片全部跟随；全局设置与复习页 ⚙ 两处入口同一真相源互相同步（不要两头选）。桌面卡片先做手机+Pad（PC 有「点桌面卡片跳不出来」bug，用户拍板后话）。

## 一、设计

### 1.1 存储层（Schema 铁律：尾部追加）
- FaceModeStore（key 'review-face-mode-v1' 不变）**尾加 `@Trace mode: string = 'single'`**——统一通道唯一真相源；旧 wordFace/knowledgeFace 字段保留休眠（兼容旧落盘）。

### 1.2 消费端（全部读 mode）
- **ReviewPage**：isDoubleFace 改读 mode；⚙ 弹窗「单词库/知识库」两卡片区**合并为一区一分段控件**（单面|正反两面）写 mode——与全局设置同一 store，双端即时同步（@ObservedV2 @Trace 共享实例，0.221.4 铁律：两端都 @Local 接管）。
- **ChatPage 司忆区 ×2**：双面模式下释义/定义行隐藏，点词条/卡片展开（复用 reviewExpandKey 展开态=翻面态——展开即出答案+评分按钮，紧凑列表一步到位）；单词全称行保留正面（词条身份+喇叭读全称）；单面模式现状零改动。
- **桌面卡片**：WidgetState 尾加 `face?/flipped?`；卡片 UI 双面模式=只显题面+评分按钮隐藏，点卡身翻面（call 通道 widgetFlip→主进程切 flipped→updateForm）；评分/切库/换卡重置 flipped=反面。快照构建（buildWidgetState）注入 face（主进程读 FaceModeStore——卡片进程禁入 @ObservedV2，0.204.1 铁律）。

### 1.3 设置入口（两处同一真相源）
- **全局设置→司忆区 Tab**：顶部新增「卡面模式」卡片区（即时生效控件——不走该 Tab 的编辑副本+保存流程，与复习页 ⚙ 同款即时写 store+推桌面卡片）。
- **复习页 ⚙**：既有两库分段合并为统一分段（同上）。
- 两处任一变更：另一处打开即同步（同一 @Trace 实例）+桌面卡片即时刷新（setWidgetFace 推快照）。

## 三、风险点
1. 桌面卡片翻面走 call 通道（拉起主进程）——与评分同款机制已验证；冻结态自动 Thaw（0.204.1 实证）。
2. 卡片进程禁 import FaceModeStore（@ObservedV2 崩溃雷）——face 一律经快照 binding 注入。
3. 司忆区展开态=翻面态：已评分过的词条释义保持显示（评分后展开态语义不变）。
4. PC 不装机（用户办公+已知桌面卡片点击 bug 后话）——build 全量编译覆盖。

## 四、验收标准
1. 全局设置切「正反两面」→ 复习页 ⚙ 打开即显示双面（反向亦然，无需保存按钮）。
2. 双面模式下：司忆区词条只显词+音标，点开展开=释义+评分按钮齐出；单面=现状。
3. 双面模式下：桌面卡片只显题面、评分按钮隐藏，点卡身翻面出答案+按钮；评分后下一张回题面。
4. 单面模式一切现状零回归。
5. 手机+Pad bm dump 实锤 1000229。

- ✅ 评分/切库/换卡/新快照全部重置 flipped=正面

**0.224.1 Bug 修复（FaceModeStore 持久化失效）**：
- 症状：Pad 上切「正反两面」→ UI 即时高亮 ✓ 但 persistent_storage 文件 mtime 纹丝不动 → 重启回单面。
- 根因：**PersistenceV2 根类新字段挂旧 key 不入持久化 track 集**——水合时只 track 已载入字段，`mode` 赋值不触发任何写盘（@Trace 内存刷新正常但持久化观察器零响应）。0.185 铁律「新字段必须全新 key」的更深层形态：不止「读取 undefined」，写也静默丢失。
- 修复：connect 换全新 key `review-face-mode-v2`（旧 v1 两库字段休眠不迁移——用户个人偏好单面，双面用户重拨一次即可）。修复后 mode=double 落盘+重启保留实锤。
- **连带发现（latent，未修）**：CloudSyncArbiter 0.223.x 尾追字段在「升级设备的旧 arbiter key」上同样不会持久化（今晚全新鲜安装=新 key 首写全字段所以无恙）；升级用户会遇 arbiter 水位/墓碑重启丢失→墓碑失效删除可复活。若未来发版给升级用户，arbiter 应同样换新 key。

**验收结果**：手机+Pad bm dump 实锤 1000230（0.224.1）；桌面卡片 UI 视觉与司忆区聊天页双面渲染留用户真机验收（逻辑与已验证的复习页同构）。

## 六、0.224.2 词条四行制+双面正面泄露根治（用户报 bug 后续迭代）

**用户报的 bug**：双面模式下词条「机器学习 + 音标 + Machine Learning」——英文答案从 fullName 行直出，双面等于没双面。

**用户定稿四行制规格**（词条四行各司其职）：
- 第一行 word=词条标题；第二行 fullName=**缩写全称专用**（非缩写必须空）；第三行=音标；第四行 explain=翻译/答案
- 英译中：英文 / 空 / 音标 / 中文；缩写：缩写 / 全称 / 全称音标 / 中文；中译英：中文 / 空 / 英文音标 / 英文
- 双面正面=只显第一行+第三行（词+音标）；反面=第二行+第四行（全称+答案）

**侦察结论（反转）**：划词 prompt **本就合规**（0.222.21 中译英 prompt 已是 word=原文/fullName=固定空串/explain=英文）——**真凶=预置种子数据**：4 条中译英（智慧/韧性/人工智能/机器学习）全部错位（英文塞 fullName、中文重复进 explain），用户看到的正是 preset-ml。

**修复**：①司忆区两处 fullName 行改反面内容（与释义同藏到展开）；②复习卡补 fullName 行渲染（四行制第二行——此前卡片从不渲染全称，缩写卡复习时全称信息丢失，单面/翻面后显示）；③种子 v3 同 id 修正 4 条（内容四字段更新、记忆/归档字段保留、已删 id 不复活——0.202.2 知识卡 v3 同款）。

**Pad 验证**：正面=「机器学习+音标+点击卡片查看答案」（无英文无评分按钮）→ 点卡翻面=「Machine Learning+评分按钮」✓；preset-ml 落盘 `fullName=""/explain="Machine Learning"` ✓；重启 mode=double 保持 ✓。

**⚠️ 观察存档（未复现）**：0.224.2 装机后首启 faceMode 曾被重置 single 一次（03:47，疑装机杀旧进程时的写盘竞态）；后续多轮冷启动持久化正常。若用户再遇「重启丢卡面模式」→ 可复现 bug 回炉排查。
