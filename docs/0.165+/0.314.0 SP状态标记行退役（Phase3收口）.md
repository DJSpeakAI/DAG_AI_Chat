# 0.314.0 SP 状态标记行退役（Phase 3 收口）

> 版本：v0.314.0 / versionCode 1000476
> 前置：0.313.0（Phase 1 云函数 + Phase 2 客户端接入）已完成并线上验收
> 任务书：桌面 `Phase3-SP发放迁移与退役-待实施.md`（收尾已删，内容沉淀于本文）

## 一、需求与口径（用户 2026-10-24 拍板 A 方案）

Phase 3 只剩 `cfg:siyi-points` 云空间行退役。用户选择 **A「改成状态标记行」**：

- SP 三池余额/消耗 = 云函数 `SpMirror` 唯一权威账本（0.313.0 已落地），本行**不再承载账本**。
- `cfg:siyi-points` 保留为**跨端状态标记行**，只同步：签到日期并集、里程碑档、新手任务 done/granted 两集合、充能包账本。
- 旧行残留的三池字段（permanentSp/bonusSp/giftSp/consumed*/welcomeGranted/giftSpExpireAt）**一律不读、不写、不合并**。

选择理由：彻底停写整行需新增 `sp_state` 云函数接口并重新部署、且充能包账本属资金链路（Phase 3 文档要求转人工）；
状态标记行方案不动资金链路、不丢跨端状态、不需要重新部署云函数，风险最低。

## 三、行为影响

1. 多端余额只由 `sp_balance` 镜像刷新，旧端上行的高值不再通过 max 合并复活本地镜像（0.290.2 旧测试账复活隐患根除）。
2. 签到/新手任务跨端状态、充能包账本照旧随行同步（行为零变化）。
3. 假开启证据链依赖「本机收到过 `cfg:siyi-points` 行」——状态行仍上行，链路不变。
4. `welcomeGranted` 改由云函数 `welcome:<账号>` 流水判定（0.313.0 已如此），本地字段仅作镜像；礼包防重仍由「giftSp>0 / 影子标记」双保险兜底。

## 四、风险与回滚

- 风险：旧版客户端（0.313.x）仍把三池字段写进该行——新版忽略这些字段，不会复活，仅冗余。
- 数据安全：PersistenceV2 key / Schema 未改；三池字段保留在本地 store。
- 回滚：恢复 `siyiStateToJson` 中三池字段 + `mergeSiyiStateRow` 的 pool 合并即可（云端旧值仍在行内）。

## 五、验收

1. 升级后老账号：余额与云端 `sp_balance` 一致，不因旧行高值被抬高。
2. 签到/新手任务/礼包在两端显示一致、不重复发放。
3. 充能包账本换设备后仍可见。
4. 编译绿（`devecocli build`）。
