## 一、任务背景（用户需求原话要点）

用户在云同步 Tab 实测两个问题（附截图）：

1. **授权被拒后的提示「未授权：请在系统『设置→应用→DAG AI Chat→权限』允许『跨设备同步』」是一条 toast，显示时间太短**，看不清就没了——要求显示时间长一点。
2. **跳转不够深**：现在被拒后跳的是系统设置的「应用详情页」，还要用户手动再点一下「权限」；用户要求像其他 APP 一样**直接跳到权限开启的地方**。用户担心手机/Pad/PC 三端跳转步骤不一样——方案必须交给系统 API 统一处理，不手写分端逻辑。

**用户拍板：方案 A（完整版）** = toast 加长到 10 秒 + `requestPermissionOnSetting` 直达权限面板 + 授权结果即时刷新面板状态。

## 三、改动方案（共 4 处）

### 改动 1：showToastSafe 支持自定义时长（GlobalSettingsDialog.ets:851-853）

签名加可选参数，**默认 1500 不变**（其余全部调用点零影响）：

```ts
showToastSafe(msg: string, duration: number = 1500): void {
  try {
    this.getUIContext().getPromptAction().showToast({ message: msg, duration });
  } catch (_e) {
  }
}
```

> promptAction.showToast 的 duration 只有两档有效值：1500 / 10000（上限 10 秒），传 10000 即顶格。

### 改动 2：「未授权」提示加长到 10 秒（GlobalSettingsDialog.ets:2407）

```ts
this.showToastSafe('未授权：请在系统「设置→应用→DAG AI Chat→权限」允许「跨设备同步」', 10000);
```

### 改动 3：被拒后直达权限面板（替换 2408-2416 的手拼 want）

用官方 API `requestPermissionOnSetting`（API 12+）替代手拼 want。它的设计场景就是「用户拒绝过、系统不再弹授权窗」——直接拉起该应用的权限设置面板：

- **手机/Pad**：半屏权限面板，「跨设备同步」开关就在那一屏，一开即回；
- **PC**：拉起系统设置里该应用的权限页；
- **三端行为全部由系统 API 处理，不写任何分端代码**（这正是用户担心的三端差异的官方解法）。

改后 2407 行之后的逻辑：

```ts
// toast 提示保留（10 秒，兜底说明手动路径）
this.showToastSafe('未授权：请在系统「设置→应用→DAG AI Chat→权限」允许「跨设备同步」', 10000);
try {
  const atm = abilityAccessCtrl.createAtManager();
  const result = await atm.requestPermissionOnSetting(context,
    ['ohos.permission.DISTRIBUTED_DATASYNC']);
  if (result.length > 0 && result[0] === abilityAccessCtrl.GrantStatus.PERMISSION_GRANTED) {
    // 用户在面板上开了权限：当场激活云同步 + 刷新面板状态
    this.permGranted = true;
    connectCloudSync().enabled = true;
    activateCloudSync();
    this.showToastSafe('云同步已开启');
  }
} catch (_e) {
  // 兜底：直达面板失败（异常/机型不支持）→ 保留原跳应用详情页逻辑
  const want: Want = {
    bundleName: 'com.huawei.hmos.settings',
    abilityName: 'com.huawei.hmos.settings.MainAbility',
    uri: 'application_info',
    parameters: { pushParams: 'com.dagaichat.app' }
  };
  context.startAbility(want).catch(() => { /* 静默，toast 手动路径已兜底 */ });
}
```

注意事项：
- onClick 回调内需要 async：用 `(async () => { ... })()` 包裹或改 Promise 链，遵守 ArkTS 写法。
- `abilityAccessCtrl` 若该文件尚未 import 则补（从 `@kit.AbilityKit`）；`activateCloudSync` 需在文件头部从 CloudSyncUtil import（见改动 4）。
- **不再先调 `requestPermissionsFromUser` 再调 `requestPermissionOnSetting` 的额外封装**——现有 2399 行 `requestSyncPermission(context)` 保留原样：它内部先弹系统授权窗（首次体验不变），返回 false（被拒/不再弹窗）时才走上面直达面板逻辑，避免一次点击连弹两层。

## 四、红线与约束（执行 AI 必读）

1. **Schema 红线**：本任务不涉及任何数据模型/持久化 key，禁顺手改动。
2. **CloudSyncUtil.ets 红线最小例外**：仅改动 4 的 `export` 一个关键字，其余禁碰（用户已拍板授权此一处）。
3. **版本号**：定版后三处同步（AppScope/app.json5 versionCode +1、Index.ets、GlobalSettingsDialog.ets APP_VERSION），注意 Index.ets 显示文本是历史三度漏改点、必须反查。
4. **ArkTS 已知雷区**（本项目踩坑史，写码时主动规避）：
   - import 必须连续置顶，新声明一律插 import 区全部结束之后（`arkts-no-misplaced-imports`）；
   - `@Computed` 引用的状态成员必须挂 `@Local`；
   - 对象方法签名禁混写（`cancel(): void => {` 类非法）；
   - 照搬代码须核对 import（abilityAccessCtrl/Want 等外部符号是否已声明）。
5. **禁止扩大改动范围**：除上述 4 处 + 可选兜底，其他区域（备份、同步逻辑、UI 布局）一律不动。止损熔断规则照常生效（AGENTS.md）。

## 五、验收标准（三端真机）

| # | 场景 | 预期 |
|---|---|---|
| 1 | 未授权状态点「开启云同步」→ 系统授权窗点「拒绝」 | toast 显示 10 秒（不再是 1.5 秒一闪）；随后自动拉起**权限面板/权限页**（手机/Pad 半屏面板、PC 系统设置权限页），**停在应用详情页视为不达标** |
| 2 | 在权限面板打开「跨设备同步」→ 返回 app | 面板状态卡变绿「已开启」、toast「云同步已开启」、云同步真实激活（建气泡可跨端同步） |
| 3 | 已授权状态点按钮 / 状态卡 | 与改前一致（无回归） |
| 4 | 直达面板 API 异常的机型 | 兜底跳应用详情页（原行为），不崩溃 |
| 5 | 其他 toast（备份成功等） | 仍为 1.5 秒，无回归 |
| 6 | 三端各验 1~2（手机 / Pad / Matebook PC） | 面板形态允许三端不同（系统 API 决定），但都必须「一步到权限开关处」 |
