## 一、三个实测 Bug 的根因（代码实锤）

### Bug A【资损级】冷安装重发 200w SP ——「先发后拉」时序洞
**复现**：181 账号卸载重装 → 登录 → SP 又变 200w 可用。

链路：
1. 卸载清 PersistenceV2 沙箱 → `siyi-points-v1` 全新（`welcomeGranted=false`、`giftSp=0`、`consumedGiftSp=0`）；
2. 登录四入口任一 → `stampFreeTrialOnLogin`（ChatModel.ets:1024）→ **同步立即**调 `grantSiyiWelcomeBonus`（:1504）→ 本地标记为假 → 当场 `giftSp += 2000000`；
3. 云下行 reconcile 是**异步晚到**；`mergeSiyiPointsRow`（:3909）的 max/或合并理论上能事后收敛（giftSp 云端 200w vs 本地 200w 持平、consumedGiftSp 云端大值顶回）——**但这依赖云同步链路全程畅通**；
4. **洞**：①手机未开系统云空间权限/未开 app 云同步 → 云端永远拉不下来 → 本地 200w 全额可用（token 已真实消耗，SP 账本纯摆设）；②云同步开着也有窗口期：礼包发放与用户花 SP 先于下行到达，多端对账口径乱；③**任何设备每次「卸载重装+重登」= 再领一次 200w**（未开同步的设备无限白嫖）。

结论：`welcomeGranted` 的幂等只在本地；云端行「取或」合并（:3937）救不了「发放动作发生在云下行之前」这个时序。

### Bug B 手机「显示可签到，点击没反应」—— UI 与执行口径分裂
- UI 判定：SignInDialog.ets:46 `isSignedToday(this.signIn)` → **只查本地** `SignInStore.signDates`（key `sign-in-v1`，本地不上云）；
- 执行幂等：SignInDialog.ets:58 `doSignIn`（ChatModel.ets:1670）→ 查**本地 ∪ 云端**（`siyi.signedDates`，cfg:siyi-points 行）。

手机冷装后本地空 → UI 显示「可签到」；云端（Pad 已签）有今天 → `doSignIn` 返回 0 → **无发放也无提示 = 点击没反应**。Pad 显示已签 = Pad 本地 signDates 有今天。两台设备同一账号表现相反，完全吻合实测。

### Bug C 云同步引导缺失「系统云空间」一步
现状三层开关：①app 内云同步开关（cloudSwitch.enabled）②app 权限（requestSyncPermission/isCloudSyncGranted，0.165.2 已有）③**系统设置→华为账号→云空间→应用数据同步→本 app 开关（无检测引导、无跳转，完全缺失）**。用户 app 内全开了，系统层没开 → 同步链路仍断（= Bug A 白嫖通道）。
附带已知 bug：0.229.24 permGranted 开弹窗快照不刷新（MEMORY PENDING，面板滞留「未开启」）。

## 二、正确冷启动应该是什么样（用户问的原题，修复后目标流程）

1. 冷安装 → 首启协议/主题选择；
2. 登录 181 → **引导开启云同步三件套**（app 开关→权限→系统云空间跳转指引）；
3. SiyiGate 等待「首拉完成」（rowInitDone 闸门已有，ChatModel.ets:3141）；
4. cfg:siyi-points 下行到达：
   - **老账号（云端行 welcomeGranted=true）**：直接置位，**不重发**；账本=云端值（余额含已消耗）；
   - **真新用户（云端无此行/标记假）**：此刻才发 200w 礼包 + 上行；
5. 签到/AI 发送/一切 SP 消耗动作全部在 Gate ready 之后 → 三端账本单一真相源=云端。

## 三、方案四件

### 1）SiyiGate：SP 账本云端就绪门卫（新增 utils/SiyiGate.ets，不碰 CloudSyncUtil 红线）
- 状态机 `locked → ready`；ready = 已登录 && app 开关开 && 权限 granted && `rowInitDone`（首拉完成）&& 云端 cfg:siyi-points 行已处理（含「行不存在=真新账号」分支）。
- **★ 用户 2026-10-22 二次拍板：gate 收口 SP 双向变动——「消耗 SP」（AI 发送/重生成/划词圈注/**IAP 充值购买**）与「增加 SP」（签到、新用户礼包、未来的做题奖励等一切发放口）全走同一 gate**。工程落法：`consumeSiyiSp` / `doSignIn` / `grantBonusSp` / `grantSiyiWelcomeBonus` 四收口函数头部统一 gate 检查（新增发放口天然继承军令），BillingPage 购买按钮 locked 态置灰+引导，UI 层引导弹窗兜底。**未同步=SP 恒 0+一切 SP 动作不可用（用户原话级硬规则）**。
- 消费点：ChatPage sendMessage/regenerate 守卫（:2044 登录守卫后追加）、签到弹窗打开与点击、划词/圈注 AI 守卫（requireLoginForCloud 同族位置）。
- locked 时弹引导（三分支）：未登录→登录；无权限→权限弹窗；系统云空间未开→跳转指引。
- 用户决策理由（规模化论证）：一人两人的小数据 bug 无感，用户量到 1000/10000 时账本口径分裂必然系统性爆发——宁可体验硬一点，数据一致性优先。

### 2）礼包发放改「云下行后发放 + 弹窗仪式感」（治 Bug A 本体）
- `grantSiyiWelcomeBonus` 不再挂 stamp 同步直发；改挂 `mergeSiyiPointsRow`/首拉完成回调尾部：
  - 云行有 welcomeGranted=true → 置位不发（老账号重装根治）；
  - 云行无标记/无行 → 真新用户 → **弹窗明示「您是新用户，免费赠送 200 万 SP」后发放**+上行（用户拍板：不做后台默默到账）；
- Gate 未 ready（链路断）→ 礼包挂起，SP 显示恒 0，UI 显示「开启云同步后领取 200w 新人礼包」——**把 Bug C 的引导变成正向激励钩子**。

### 3）签到口径统一（治 Bug B）
- `isSignedToday` 改双查：本地 signDates ∪ 云端 siyi.signedDates；
- `doSignIn` 返回 0 时 UI toast「今日已在其他设备签到」；
- 连击展示沿用 streakFromSignedDates（云端并集推导，已有）。

### 4）云空间引导跳转（治 Bug C）
- 需查证能力：系统能否 startAbility 直达「云空间→应用数据同步」页（待查文档/问华为客服，见 §五）；
- 顺带修 0.229.24（permGranted @Monitor 重查权限，方案已在 MEMORY PENDING 定方向）。

### 5）★ 多账号切换：内容默认合并 + 资产行账号隔离（华为实锤 6 后升级定案）
- 场景：设备登出账号 A（本地数据保留）→ 登录账号 B → 云下拉。
- 华为实锤：云端按账号隔离，但**本地 RDB 不清空，本地遗留会作为基础与新账号云端合并上行带入**（系统不替你隔离）。
- **用户拍板（内容数据）**：气泡树/词库/知识库/布局**默认合并不询问**——开云同步即视为同意；id 全局唯一无撞车，最坏=「更多的气泡」。
- **★ 资产行必须隔离（待用户最终确认，推荐方案 A）**：`cfg:siyi-points`（SP 三池/签到标记/充能包——记账语义+真金白银）与 `cfg:stat-days`（等级数据源）若同样默认合并，账号 A 的 200w SP/充值包/学习天数会**永久污染**账号 B 云端（max 合并不可逆）。
  - **方案 A（推荐）**：HuaweiAccountUtil 本地记上次登录账号标识；检测到账号变化时，本地 SiyiPointStore/StatisticsStore 字段重置为新装状态（写回默认值——不改 key 不碰 Schema，红线合规），随后走「云下行合并」= 以账号 B 云端为唯一真相；内容数据照旧合并。
  - 方案 B：全部默认合并（用户已默许内容，但 SP/充值包污染不可接受，不推荐）。
  - 方案 C：账号切换弹窗让用户选（用户已明确否决「不需要同意不同意」，不推荐）。

## 四、用户拍板记录（2026-10-22 全部定稿，原「商业冲突」消解）

1. **资产行账号隔离（方案 A 确认）**：SP/充值包/等级跟着**账号**走，绝不跟设备走。检测到华为账号变化 → 本地 SiyiPointStore/StatisticsStore 重置新装状态（写默认值，不改 key 不碰 Schema）→ 以新账号云端为唯一真相。内容数据（气泡树/词库/知识库/布局）默认合并不询问（前拍板不变）。

## 五、云空间满/同步失败兜底 + 华为客服答复实锤（2026-10-22 已答复，全案定稿依据）

**四条实锤**：
1. **云空间满不丢数据**：本地 RDB 完整保留，云端写入失败=同步暂停；用户清理后系统自动续传，应用可 `cloudSync` 手动加速。
2. **失败可感知（官方 API）**：`store.on('autoSyncProgress')`（API 11+）常驻监听 `ProgressDetails.code`；手动 `store.cloudSync(mode, tables, progress)` + Promise catch。关键码：`SUCCESS(0)`/`NETWORK_ERROR(2)`/`CLOUD_DISABLED(3)`/`NO_SPACE_FOR_ASSET(6 云空间满)`/`RECORD_LIMIT_EXCEEDED(5)`；错误码 22400001（云端未 ready=未登录/云开关未开/应用开关未开）、22400002（网络不可用）。
3. **系统级云同步开关无查询 API、无推送**——0.229.24「检测不准」的病理实锤：官方推荐=onForeground 时主动 `cloudSync` 轻量探测，22400001/CLOUD_DISABLED → 未开（无法区分三种子因，只能引导去设置页）。
4. **跳转云空间有 Deeplink**：`hicloud://cloudDrive/getInfo?path=MainActivity`（云空间首页，**不能**精确到本 app 开关页）；官方体验建议=跳转前弹窗引导用户找「应用数据同步」下本应用名开开关。
5. **无云空间剩余容量查询 API**：只能事后感知（NO_SPACE_FOR_ASSET 到达时引导清理+告知「数据已在本机安全」）。
6. **多账号切换系统不做隔离（重大实锤）**：云端按华为账号隔离，但本地 RDB 不清空——登录新账号后本地遗留数据会作为基础与新账号云端合并**上行带入**（跨账号污染确认存在）；官方建议记账类应用自行检测账号切换清本地。

**本地兜底设计（定稿）**：
- CloudSyncUtil 属红线禁改——探测/监听由 SiyiGate 消费 CloudSyncUtil 已暴露的连接与 `forceCloudSyncNow` 能力，或经行桥回调实现（开工时按红线边界定挂点，必要时列人工审批单）；
- `autoSyncProgress` 常驻监听：NO_SPACE_FOR_ASSET → Gate locked + 弹窗「数据已保存在本机，云空间已满」+ Deeplink 跳云空间清理；NETWORK_ERROR → 轻提示系统自动重试；
- onForeground 重探（cloudSync 轻量探测）刷新 Gate——顺带根治 0.229.24（permGranted 快照不刷新）。
