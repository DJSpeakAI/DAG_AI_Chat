# 司枢模式 2.0 整体方案（外部 AI 审批稿）

> 2026-10-22 起草。本文档交外部 AI 审批，审批通过后再排期落码，**当前未动任何代码**。
> 背景：司枢模式=本项目长回复深度模式（0.269.0 落地，名称含义：司=掌管、枢=中枢，指在深度思考之上再加钩子编排层）。用户实测约 66% 场景体验不佳，本轮为整体重构方案。

---

## 一、问题诊断（为什么要重构）

### 1.1 现状架构（0.269.0 两段式）

```
用户提问（司枢模式开=长回复档）
  → ①段：深度思考模型直出长文（LONG_REPLY_PROMPT：详细完整、分点展开、深度讲解）
  → ②段：伴读编排师（轻模型读①段全文，按块编号输出钩子 JSON）
  → 本地合成器插入钩子标记 → 渲染
```

### 1.2 病根：长度由档位强制，不由内容决定

- LONG_REPLY_PROMPT 硬性要求"详细完整、讲透彻"，问题本身信息量不足时，模型为凑长度**一本正经注水**（重复、绕圈、凑字数）。
- 用户实测规律：**问题长=回复质量高；问题短=注水严重**。这与机制完全吻合——长问题素材充足无需注水，短问题被档位逼着扩写。
- ②段编排师只加钩子、不改内容，救不了①段的水分。
- 结论：**内容长度没有经过规划，是被档位逼出来的**。这是结构性缺陷，修补 prompt 无解。

### 1.3 性格画像现状：只影响语气，不影响结构

0.288.0 性格测试已落地（15 题三选一 → 12 维画像行 → 注入消息数组最前部）。但画像在现架构里只被模型"自由发挥"地用于语气层面，没有任何结构性约束——画像数据已就位，缺的是消费它的架构。

## 二、改造一：性格测试 2.0（封闭题 → 开放题）

### 2.1 为什么必须开放题（用户拍板）

未来用户成千上万、水平跨度极大。封闭选择题（A/B/C）有两个不可解的问题：

- 对大神：题目太简单，测试本身显得幼稚；
- 对新手：被"考"的感觉差，且选项可能都不贴切，等于被迫选一个错误答案。

**开放问题没有这种问题**——每个人都能按自己的真实状态作答，测的是"这个人实际是什么样的"，而不是"这个人最接近哪个预设模板"。

### 2.2 开放题库（15 题，题干沿用现有情境、去掉选项，每题仍拧一个 AI 旋钮）

| # | 题型 | 开放题干 | 拧的旋钮 |
|---|------|---------|---------|
| 1 | 情境题 | 刚学完一个新概念，你接下来通常会做什么？ | 应用/原理/兴趣导向 |
| 2 | 自评题 | 看长文章或长视频时，你的习惯是什么？ | 求知深度 |
| 3 | 二选一→开放 | 如果只能跟一个老师学，你希望 TA 怎么讲课？ | 例子驱动/原理驱动 |
| 4 | 情境题 | 一道题做错了，你心里第一反应是什么？ | 抗压（自评） |
| 5 | 频率题 | 定了学习计划之后，你一般执行得怎样？为什么？ | 自律程度 |
| 6 | 反应题 | 读长文时中途插入一个"考考你"小问题，你的真实感受是？ | 互动偏好 |
| 7 | 自评题 | 刷到反常识的说法（比如"努力反而有害"），你通常会怎么做？ | 好奇心 |
| 8 | 情境题 | 同样 3000 字的长文，什么样的写法最让你受不了？ | 节奏口味 |
| 9 | 情境题 | 面对完全陌生的硬核领域，你觉得自己能学到什么程度？ | 学习自信 |
| 10 | 反应题 | 文中出现"简单说：响应式=看到你走近，我换一套站姿"这种大白话翻译，你什么感受？ | 互动偏好 |
| 11 | 自评题 | 学有所成的时候，你最想干什么？ | 分享/内敛 |
| 12 | 追问题 | AI 给了你一个能用但"知其然"的答案，你会怎么办？ | 追问深度（行为题） |
| 13 | 情境题 | 深夜独自学习卡壳了，你更希望听到什么话？为什么？ | 口吻偏好 |
| 14 | 追问题 | 连续三次复习都记不住同一个知识点，你会怎么想？ | 抗压（行为题优先） |
| 15 | 场景题 | 描述一下你理想中一次高质量学习的过程。 | 时段形态（沉浸/分段/碎片） |

保留的设计纪律：相邻两题永不同型穿插；行为题优先于自评题（心理学定论，q12/q14 权重高于 q2/q4 的精神在 AI 评阅 prompt 中延续）；每题答案必须能拧动至少一个 AI 输出旋钮。

作答形式：自由文本输入框（建议 1~3 句），不做字数硬性要求。

### 2.3 评分机制：AI 一次评阅出 12 维画像

```
15 题答完 → 全部答案文本一次性送轻模型评阅（隐式调用 implicit，不扣用户 SP）
  → QUIZ_REVIEW_PROMPT 输出 12 维画像行（kind+content，直接对齐既有 ProfileObservation 格式）
  → 复用现有 appendObservation 管道写入画像（画像卡注入消息数组最前部）
```

评阅 prompt 要点（按项目 Prompt 十军规起草，落码时放 Prompts.ts 单一真相源）：
- 逐题读答案文本找证据，每维输出一句话画像（8~30 字，无主语风格，与隐式观察行同款）；
- kind 只用既有四枚举（identity/goal/preference/emotion），禁止扩枚举（Schema 铁律）；
- 答案含糊/拒答的维度输出空标记跳过，禁止臆测；
- 输出严格 JSON 数组。

降级：AI 评阅失败 → 本地关键词规则兜底（如 q3 答案含"例子/故事/类比"→例子驱动型）→ 仍失败则写默认画像（适度互动/均衡口味），不阻塞测试完成。

### 2.4 存储兼容（红线区，需审批重点看）

- key `personality-quiz-v1` **禁改**（持久化 key 红线）。
- answers 字段现为 `'a'|'b'|'c'` JSON 字符串数组；开放化后元素变为答案文本（string[] 结构不变，元素变长，JSON.parse 兼容）。
- 旧数据混读处理：未完成的老用户（answers 里是 a/b/c 字母）续答时，评阅 prompt 兼容字母答案（映射回原选项文案参与评阅）；done=true 的老用户零影响（不再写入）。
- ⚠️ 此点字段语义有漂移风险，列为审批问题 #2。

### 2.5 不变项

SP 激励不变（每答 5 题发 2000 司忆点，共 3 节点，claimed 幂等）；断点续做不变；入口（气泡树左下角信号灯，做完消失）不变；画像写入幂等（done 只写一次）不变。

## 三、改造二：司枢模式 2.0（框架先行两段式）

### 3.1 新架构

```
用户提问（司枢模式开）
  → ①段【规划器】：输入=性格画像 12 维 + 记忆引擎画像卡 + 分支摘要头 + 对话上下文 + 本轮问题
      输出=结构化框架 JSON（见 3.2）——长度裁定、章节要点、每章深度、钩子位+类型+文案、语气旋钮
      （流式可展示"正在搭建回答框架…"；轻模型即可，输出几百 token）
  → ②段【执笔】：深度思考模型按框架写正文（框架作为 system 指令注入，深度思考能力保留在此段）
  → 本地合成器：按框架的 hooks 字段插入钩子标记（复用现有 mergeHooksIntoContent）
  → 渲染
```

原②段"伴读编排师"（HOOK_SYSTEM_PROMPT）的职责被①段规划器吸收——钩子的位置、类型、文案在规划期就定好，钩子长在结构里而不是事后贴上去。**总段数仍为两段，不增时延档位**。

### 3.2 框架 JSON schema（草案）

```json
{
  "lengthTier": "brief | medium | long",
  "targetChars": 600,
  "reason": "问题为单一事实型，无需展开",
  "sections": [
    { "title": "…", "points": ["要点1", "要点2"], "depth": "plain | deep" }
  ],
  "hooks": [
    { "afterSection": 2, "type": "digest | breath | quiz | bait", "text": "…" }
  ],
  "tone": { "voice": "senior | coach | tool", "encourage": "high | low", "analogy": "more | less" }
}
```

- `lengthTier`/`targetChars` = **长度裁定权前移**，根治注水的核心：小问题框架就是 2~3 个要点，②段照写 3 段，天然自适应。brief 档是否跳过②段深度思考直接走中回复链路（省 SP+时延）→ 列为审批问题 #5。
- `hooks.type` 四选一：digest=简单说 / breath=歇口气 / quiz=考考你 / bait=延伸。**progress 类（"到这里了：读到这里你已经走完这一节"）整类砍除**（用户拍板：该文案弱智）。
- `tone` 由性格画像直接驱动：例子驱动型→analogy=more；互动型→quiz 钩子配额高；极简口味→targetChars 压低、hooks≤2；学长/教练/工具口吻三选一。

### 3.3 性格画像的结构性落点（本方案核心收益）

| 画像维度 | 框架段消费方式 |
|---------|--------------|
| 例子驱动/原理驱动 | sections 要点的组织方式（类比先行 vs 推导先行） |
| 求知深度 | lengthTier 与 depth 取值 |
| 互动型/低互动 | hooks 数量与 quiz 配额 |
| 节奏口味（极简/喘息位） | targetChars 与 breath 配额 |
| 抗压（可直言/需鼓励） | tone.encourage |
| 口吻（学长/教练/工具） | tone.voice |
| 时段形态（沉浸/分段/碎片） | sections 切分粒度 |
| 自律程度 | 提醒类结尾的取舍 |

画像从"背景信息"升级为"规划输入"——这同时回答了性格测试的投资回报问题：**帮在框架层，不在文笔层**。

### 3.4 SP 与时序

- SP 军令延续：①+②段 token 累加实扣、一次性 consumeSiyiSp、必有消耗展示（对外禁 token 字样）。
- 成本对比：规划段输出短（约 500 token），②段因不注水总输出预计持平或略降——总成本预计与现状相当。
- 保活：0.251.0 后台保活对每段自动生效，无需额外处理。

### 3.5 失败降级链

- ①段（规划）失败/超时/JSON 解析失败 → **直接回退现状①段直写长文**（现有链路整体保留作 fallback），钩子走本地 breath 保底——规划失败不毁回答。
- ②段失败 → 与现状语义一致（报错、不扣或只扣①段）。
- 性格测试未完成的用户 → 框架段降级用隐式画像/默认画像（方案前置条件是测试完成，但架构上不硬依赖）。

## 四、改造三：设置简化（用户拍板，隐藏不删除）

### 4.1 设计理念（用户原话精神）

"我自己作为开发者都读不懂这些选项，让用户选更不可能懂。**能做进自动回复的，就不要做成设置**——AI 自己根据性格测试、上下文判断需不需要。设置里显示 ≠ 功能存在：原理全部保留，只是不给用户看不懂的开关。"

### 4.2 隐藏清单与默认值表（全局设置弹窗 → AI 偏好区）

| 现设置项 | 处置 | 内置默认值（恒定） |
|---------|------|------------------|
| 锚点与伴读（off/智能锚点/伴读 三态+密度档） | UI 隐藏 | 恒"伴读"（钩子改由框架段编排后此设置自然消亡） |
| 深度思考三态（auto/always/off） | UI 隐藏 | 恒 auto（司枢模式开=长回复恒思考，沿 0.282 定案） |
| 分章折叠开关 | UI 隐藏 | 恒开 |
| 深度记忆开关 | UI 隐藏 | 恒开（已是默认开） |
| 清空画像入口 | **删除**（非隐藏） | — |

AI 偏好区保留项：AI 称呼/昵称等用户一眼能懂的内容项。

### 4.3 清空画像入口删除的合规说明（请审批 AI 复核）

用户问：华为官方有规定一定要提供"清空画像数据"入口吗？

我方结论：**未查到华为应用市场强制要求应用内提供本地画像单独清空入口的规定**。依据：
1. 画像数据纯本地存储（PersistenceV2 沙箱）、不上云（画像云同步未做），卸载应用即彻底清除——《个人信息保护法》删除权通过卸载/系统清除数据满足；
2. 华为 AGC 审核关注点为：隐私政策披露收集目的与方式、账号注销、权限申请——本地处理数据不触发应用内删除入口硬性要求；
3. 隐私政策中已/将披露画像本地处理逻辑。

风险提示：若未来画像上云，则需重评估。此结论请外部 AI 按华为最新审核政策复核（审批问题 #4）。

## 五、改造四：钩子 UI 简化（用户拍板）

### 5.1 砍 progress 类

"到这里了：读到这里，你已经走完这一节"整类删除（用户原话：谁要看你这句话，弱智）。涉及：anchorBadge 映射、本地保底模板、编排 prompt 类型清单、渲染分支，全链清除。钩子类型收敛为四类：digest / breath / quiz / bait。

### 5.2 单一视觉元素原则（禁止 icon 叠加）

现状锚点卡=左侧 2.5vp 紫竖线 + 紫底白字胶囊徽标（歇口气）+ 右侧钩子描述文案 + 8% 紫底背景——**四层装饰叠加，用户判定"为了放 icon 而 icon"**。

用户拍板二选一（待外部 AI 从可读性角度给出倾向后用户终裁）：
- **形态 A（纯标签）**：只留紫底白字胶囊（用户明确表示喜欢这种"标签页"样式），钩子文案放胶囊内或点击展开；
- **形态 B（纯文字）**：无胶囊，仅左竖线+一行钩子文案。

禁止形态：胶囊徽标+描述文案同屏双行叠加。

### 5.3 保留项

bait（延伸）尾部"→ 拉分支深挖"可点（点击=创建子气泡预填问题）；锚点浮现动画保留；TTS 朗读跳过钩子块保留。

## 六、给审批 AI 的问题清单

1. **开放题评阅质量**：自由文本噪声大（用户敷衍/跑题/极短答案），AI 评阅出 12 维画像的稳定性是否可靠？是否需要在评阅 prompt 中加"证据引用"字段（每维画像必须引用对应题号答案原文片段）来提升可信度？
2. **存储兼容**：answers 字段元素从单字符（'a'）变答案文本（长 string），key 不变、结构不变（string[]），此字段语义漂移是否有更稳妥的兼容方案？
3. **框架 JSON 稳定性**：①段规划器输出 JSON 的 schema 漂移/字段缺失风险，除了 few-shot+严格 JSON 指令+本地校验兜底外，还有什么业界成熟做法？
4. **合规复核**：清空画像入口删除，按华为应用市场现行审核政策是否有风险？
5. **brief 档路由**：框架裁定为 brief 的小问题，是否应跳过②段深度思考直接走中回复链路（省 SP 与时延），还是保持两段恒定（架构简单）？
6. **单点故障**：框架先行=框架差则全文差（错误放大）。除了 3.5 的失败降级，是否需要对框架本身做质量校验（如 sections 为空/钩子越界时的本地修正）？
