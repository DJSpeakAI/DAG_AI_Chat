# 0.231.0 AI 回复 Markdown 行内格式渲染

## 需求分析
用户需求（原话要点）：AI 对话回复是 MD 格式，要把它变成「非常好看的文本格式」——格式转换必须加。
现状实锤：`ChatPage.parseMarkdown` 只识别三种段——代码块/表格/普通文本（+LaTeX 数学），**行内与块级 Markdown 全部按纯文本渲染**：`# 标题`、`**加粗**`、`*斜体*`、`~~删除线~~`、`- 列表`、`1. 列表`、`> 引用`、`---` 分割线、`[链接](url)` 全部显示原始符号。

## 设计思路
1. **纯函数解析器独立成模块** `utils/MdInline.ets`（供 ChatPage 渲染 + ohosTest hypium 单元断言双消费——§12.13 测试覆盖军令）
   - 块级：`parseBlockMd(lines)` → `MdBlock[]`（kind: p/h1~h6/li/oli/quote/hr；li 含 depth 缩进层级与序号文本）
   - 行内：`parseInlineMd(text)` → `MdSpan[]`（bold/italic/strike/code/link 标志 + url）
2. **保守流式安全**：只认成对标记（未闭合 `**` 按字面量），打字机流式中间态不会闪乱
3. **渲染**（ChatPage AI 消息 type=0 段升级）：Column 逐块渲染——
   - h1~h6 递减字号加粗；p 常规（多行并入单 Text，Span 换行符分隔）
   - li/oli：缩进 + •/序号 前缀行；quote：左侧品牌紫竖条 + 浅色字；hr：Divider
   - 行内：粗体 600、斜体 italic、删除线 lineThrough、行内代码 CODE_TEXT 色+浅底、链接品牌紫+下划线
4. **划词翻译/复制保持**：逐块 Text 挂同款选择工具栏（key 加块后缀防 controller 撞车），选中内容=所见干净文本（不再带 `**` 符号）
5. **书签兼容**：命中书签的段回落纯文本渲染（保偏移语义——书签是临时态，稀有路径）
6. **范围**：仅 AI 消息；用户消息纯文本不变；代码块/表格/数学公式渲染链路零改动
7. **AI 鼓励语（复习完成页/统计页）**：prompt 已数字锚定 1~2 句，非 markdown 场景，不扩

## 改动文件
- `entry/src/main/ets/utils/MdInline.ets`（新增，纯函数）
- `entry/src/main/ets/components/ChatPage.ets`（type=0 段渲染升级 + @Builder）
- `entry/src/ohosTest/`（hypium 单元断言：标记配对/块级分类/流式未闭合字面量）
- 测试台 `testing/console/`：ARKUI-TEST 内置用例自动带上新断言（0.231.0 测试台版本一并记录）

## 风险点
- Span 拆分后划词选择粒度=单块（原=单段）——工具栏翻译/复制语义不变
- 极端嵌套标记（**`code`**）不递归解析——code 内不认其他标记（AI 输出主流形态够用）
- 数学公式（renderMathText）在 parse 前转换，行内解析只处理转换后纯文本——零冲突

## 验收标准
1. AI 回复含 标题/加粗/斜体/删除线/行内代码/两级列表/引用/分割线/链接 → 渲染无原始 MD 符号
2. 划词翻译/复制在富文本段照常工作，取值不含 `**` 等标记
3. ohosTest 断言全绿（测试台 ARKUI-TEST 内置跑）
4. 代码块/表格/数学公式渲染无回归
