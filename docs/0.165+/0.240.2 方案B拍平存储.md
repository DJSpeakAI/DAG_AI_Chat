## 〇、破案全程（六轮真机调试，两个隐藏真凶——后来者必读）

方案 B 落地后 ⑤ 重启存活仍连红三轮，逐轮挖出两个 0.240.1 时代完全没识别的真凶：

1. **真凶一（框架级·总根因）：PersistenceV2.connect 必须在 loadContent 之后**（官方 FAQ-1084 场景一原文：connect 在 loadContent 之前执行 →「再次进入应用持久化数据读取失败，每次都会重新创建新的数据」）。EntryAbility.onWindowStageCreate 里 loadBuiltinApiConfig 原放在 loadContent **之前**（0.161.3 设计「早于组件 connect」——好心办坏事），api-config 系 key 冷启恒 factory 值、盘值被无视。**0.240.1 全天 B1「盘值被冷启工厂值回滚」的真身即此**；model-alias-v1 可靠正因只在组件内 connect（loadContent 后）。修复=loadBuiltinApiConfig 挪进 loadContent 回调。
2. **真凶二（业务级·回滚第二凶）：云同步下行 cfg:api-config 行**——0.240.1 五版曾把华为+KTAG77 旧配置上行到云端；0.240.2 首版在 cfgApiApply 尾部加 snapshotApiConfig（本想落盘云下发配置），结果**云端旧值经下行 apply 被固化到 v5 盘上**（⑤ 回显旧档后拉盘实锤 v5=华为+KTAG77AKATAG），叠加「保存后 cfg 行上行不及时（只在 flush）」→ 保存→重启必被云端旧值顶回。修复双管：①cfgApiApply 禁 snapshot（云下行只改内存，每次冷启云同步重放，无需落盘）②snapshotApiConfig 内及时上行 cfg 行（保存即写 RDB 行→autoSync 推云，云端不再滞留旧值；rowInitDone 闸门内才写）。
3. 配套修复：迁移链**只灌内存不落盘**（防与水合互踩把迁移值写盘覆盖真值）；v5 三层转义（XML 实体+双层 stringify）膨胀后 BusyBox grep 240 窗口到不了 provider——测试台改 `pullPrefCfg`（file recv 拉盘本地 node 全量解析，全字段断言一次到位）。

## 一、需求分析

0.240.1 五版（快照自愈）真机仍暴露：F10 保存 deepseek→重启回显华为（再回滚一次）+ backup 快照疑似不落盘（待查点#1）。方案 A 继续与 PersistenceV2 落盘时机黑盒纠缠，两家评审共同结论=**方案 B（拍平存储）**：

放弃用 13 个 @Trace 字段的 @ObservedV2 类（ApiConfig）直接做 PersistenceV2 key，把 api-config 整体改为「**单 string 存 JSON**」模式——与 `model-alias-v1`（ModelAliasStore）完全同构，**全天唯一 100% 可靠的实证模式**（纯 new factory + 顶层 connect + key 由本结构一次性首创 + 永不嵌套 + 永不换 key + 类结构永不加字段）。B1（盘值被冷启工厂值回滚）/B2（嵌套 connect 毒害水合）/B3（行为自相矛盾）一键绕开。

## 二、设计思路（终版）

- **ApiConfig 类保留为运行时视图**：@ObservedV2 @Trace 响应式照常驱动 UI；持久化不再走实例字段，改为进程级单例 `runtimeApiCfg` + 启动读 JSON 全量灌入（connectApiConfig）+ 保存全量写 JSON（snapshotApiConfig）。
- **新 key `api-config-v5`**：新类 `ApiCfgStore`（单 @Trace cfgJson: string + @Monitor 水合补灌回调），纯 new factory 顶层 connect，由本结构一次性首创。
- **读**（connectApiConfig 首次调用，必然发生在 loadContent 之后的组件构造）：v5 有值→JSON.parse 灌 13 字段；v5 空→一次性迁移，源优先级 **backup 快照（0.240.1 五版用户）> v4 实例 > v3 实例**（顶层 connect 非嵌套；**仅灌内存不落盘**——转正交给下次保存，防与水合互踩）。三重补灌保险：@Monitor('cfgJson') 响应式 + setTimeout 1.5s 复核 + GSD 开弹窗 refreshApiCfg()。
- **写**（snapshotApiConfig）：saveAll 尾部调用，双写 v5（主真相源）+ 'api-cfg-backup-v1'（二级兜底）+ **cfg:api-config 行上行**（rowInitDone 闸门内）。
- **云下行（cfgApiApply）只改内存**：禁 snapshot（云端旧值固化到盘=回滚帮凶，真机实锤）；每次冷启云同步重放 apply，无需落盘；盘=v5 本地保存真值，断网兜底。
- **其它写入点**：GSD aboutToAppear 搭救回灌后 snapshotApiConfig()；loadBuiltinApiConfig 填空位维持纯内存（每次启动重填，幂等等价）。

## 四、风险点（终版）

1. 迁移读 v4/v3 仍尽力而为（最坏=回默认），一旦新版保存过一次即 100% 固化。
2. 内置 Key 不再随实例落盘（启动重填，等价）；盘上 apiKey 空=内置通道，非 bug。
3. 「保存→上行完成前 force-stop」极端窗口内冷启，云端旧行可能短暂顶回内存（本地 RDB 行已在，LWW 时间戳保护；窗口秒级）。
4. 云端 cfg 行只带 8 字段（历史设计），apply `?? cur` 补齐，无回退风险。
