## 三、ArkUI 测试体系 +「PC 到底能不能测」原理答疑（用户疑问正面回答）

官方四路线：① @ohos/hypium 单元测试（IDE 部署到设备跑逻辑用例）② @ohos/UiTest API（IDE 测试工程内 UI 用例）③ DevEco Testing Hypium Python 版（多设备并行，重、绑客户端）④ **hdc + uitest CLI（本项目路线，脱离 IDE，任何 hdc 目标可测）**。

**两条通道原理差别（答疑）**：
- DevEco IDE 测试 = 把测试包**部署进设备里**跑——IDE 能部署到哪就能测哪；本机是鸿蒙 PC、DevEco 可直接部署本机 → IDE 测试能测 PC。
- 我们走 hdc CLI = 调试桥**直发命令**——本机 PC 自己就是一个 hdc 目标（`127.0.0.1:35247`），shell 命令直达。
- 「PC 不让测/权限没放开」的印象来源：DevEco Testing 等专项工具的官方设备矩阵只有手机/平板/模拟器，**不含 PC**——是那类工具的支持范围问题，不是系统禁止 PC 被测。
- 本路线唯一 PC 风险：dumpLayout/uiInput 依赖应用**窗口前置**（PC 焦点机制不同），是稳定性风险非权限墙 → §十能力矩阵自动降级纯数据断言。
- 一期「PC bm dump 失败」非通道不通（交互直跑曾通）——exec 拼接 bug，本次 spawn 数组根治。

**两条硬约束（决定测试形态，维持原稿）**：Button 注入限制（0.200.0）→ 导航优先容器坐标，分级策略：**组件定位→坐标→人工兜底**（豆包）；Account Kit 系统授权页不可注入 → 登录链路**半自动**（人工授权检查点）——豆包/DeepSeek 一致结论：当前约束下最优解，无官方测试桩。

## 四、总体架构 + 安全模型（DeepSeek P0-1）

```
桌面「DAG AI Chat」收纳夹
 ├─ 启动测试台.bat  ←── 一键启动（检测 8766 占用→起服务→开测试台.html）
 └─ 测试台.html      ←── 完整控制台（file:// 直开，CORS 受限放行+Token）
        │ http://127.0.0.1:8766/api/*（X-Test-Token 校验）
        ▼
 鸿蒙 PC 本机 Node 服务（项目 testing/console/，git 管理，spawn 数组执行）
        │ hdc -t <target> shell "..."（命令白名单）
        ├─ Pad（USB）      100% 可控
        ├─ 鸿蒙 PC 本机    hdc list targets 自动识别（不硬编码 35247）
        └─ 手机（WiFi）    注册后入列；占线自动跳过 ⚠️
```

安全模型：**只监听 127.0.0.1**（绝不上 0.0.0.0）；CORS 仅 `Origin: null`（file://）+ `http://localhost:8766`；所有 `/api/*` 校验 `X-Test-Token`（启动随机生成注入桌面 HTML）；**spawn(cmd, args[]) 数组参数禁 exec 拼接**（根治遗留#1）+ 命令白名单（hdc/uitest/bm/aa/sqlite3/hilog/cat/grep）；设备 serial/IP/包名/超时/TAG/沙箱路径全外置 `config.json`。

## 五、HTML 控制台交互（矩阵 + 豆包体验增强）

- **左栏用例树**：按套件分组勾选+组勾选+顶部全选；**右栏设备**：多选+类型/连接方式/在线状态点+跑前预检（离线置灰）。
- **执行区**：选中用例×选中设备矩阵，串行执行；顶部总进度条+实时统计（✓/✗/进行中/待人工）；单用例可展开详情（步骤流/耗时/dumpLayout 摘要/sqlite 结果/hilog 片段）。
- **人工检查点卡**：设备名+操作指引+倒计时（180s 默认，可延长）+「我已完成，继续」主动按钮+「跳过本设备后续」；多设备检查点**排队不并发**。
- **SSE 实时推送**（EventSource，替代轮询）+ 刷新/服务重启后等待状态可恢复。
- **暗紫主题**（#160D26 / #7C5CFF）与装机台/埋点看板家族统一；引导页带「一键复制启动命令」。
- 桌面 HTML 与项目 `public/index.html` **同源生成**（构建脚本复制+页脚版本哈希）。

### 功能① 账号登录（从零开始·三入口）

| 用例 | 流程 | 断言（登录成功后全查） | 类型 |
|---|---|---|---|
| LOGIN-STATE | 冷启→dump | 三入口均呈「未登录」基线 | 全自动 |
| LOGIN-AGREE | 未勾协议点登录 | 三入口均拦截+提示（0.226.0 合规门禁） | 半自动 |
| LOGIN-HOME | 首页入口登录→**人工授权** | 登录态落盘；边栏账号行已登录（**bug 红灯位：仍灰**）；首页已登录态；设置区已登录态；云同步询问弹窗出现；hilog 无 ERROR | 半自动 |
| LOGIN-SIDEBAR | 边栏底部入口→**人工授权** | 同上矩阵，重点：**边栏自身按钮转已登录**（0.217.2 同族 bug 位） | 半自动 |
| LOGIN-SYNC | 设置→云同步入口（fromSyncEntry，登录成功直接开同步）→**人工授权** | 同上矩阵 + **cloud-sync-switch 落盘=true（bug 红灯位）** + RDB 同步启动（hilog） | 半自动 |
| LOGIN-LOGOUT | 已登录点头像→退出确认 | 三入口复位；cloud-sync-switch 强制 false（0.196.8）；登录态清盘——**兼作用例间隔离器** | 半自动 |

**用例隔离策略（DeepSeek P0-2）**：首轮全新安装（复现 bug 场景）；后续用例复用系统级授权+应用内登出复位基线（华为授权首次完整授权后，后续登录为系统层一键确认，人工成本可控，避免 9 次完整授权）；每用例前置「冷启→确认未登录基线」+后置「登出/抓日志」。

### 功能② 云同步四域数据链（本次核心扩展·分域断言）

cloud_data 表 key 前缀分域（CloudSyncUtil.ets 实核）：

| 用户测试对象 | key 前缀 |
|---|---|
| 单词库 | `word:` / `wfolder:` |
| 知识库 | `card:` / `kfolder:` |
| 气泡树+聊天内容 | `node:`（消息内嵌节点行）/ `tab:` / `layout:` |
| 删除墓碑 | `del:` |

| 用例 | 流程 | 断言 | 类型 |
|---|---|---|---|
| SYNC-SWITCH | 读沙箱 | cloud-sync-switch 落盘与 UI 一致 | 全自动 |
| SYNC-DOMAIN | 双端 sqlite3 分域查询 | 各域**行数+主键集合+内容哈希三级比对**（行数同内容异=红灯）；轮询至一致或超时（60s/5s 间隔），记录收敛耗时 | 全自动 |
| SYNC-DELETE | A 端删一个气泡→轮询→B 端 | B 端 node 行消失或 `del:` 墓碑到位（0.228.0 未验项①：删除传播，**杜绝删卡复活**） | 半自动 |
| SYNC-PULL-ZERO | B 端卸载重装→登录→全量下拉 | 分域核验 + **已删气泡不复活**（从零全量下拉=僵尸气泡复现场景，用户「乱的要死」最可能根因正面测试） | 半自动 |
| VERSION | bm dump | versionCode=config 值（从零装机假成功防线，沿用一期） | 全自动 |

造数据：优先容器坐标注入，受阻转人工检查点（「请新增一个气泡」）。
**预留扩展池**（框架留位，本次不做）：离线修改联网补同步 / LWW 双端冲突收敛 / 设备级开关独立 / 报告导出 Markdown。

## 十三、测试账号策略（★ 2026-10-12 用户拍板：主力账号全跑）

三案对比留档：

| 方案 | 优点 | 风险 |

| A 专用测试华为账号 | 零污染，删/造随便跑 | 需注册；测不到真实云端乱象 |

- **跑前基线快照**：每轮开跑前对四域做只读分域快照（行数/键集/哈希）存 artifacts——出问题可回溯对比定位；
- **测试标记**：造数据用例一律「TEST-」前缀（气泡标题/词条），事后可识别可清理；
- **本轮动行清单**：每轮结束输出删除/新增/修改的行 key 清单，供人工核对；
- 登录 bug 与账号无关（纯应用状态逻辑），主力账号零额外风险。
