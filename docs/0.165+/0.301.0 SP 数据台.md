# 0.301.0 SP 数据台（方案 A：账本镜像+运营指令）

## 一、需求（用户 2026-10-23 拍板）

运营侧（开发者）需要：
1. **查**：输入华为账号 ID → 看到该账号 SP 全貌（可用余额/冻结额/三池/充能包明细/最后上报时间与设备）
2. **改**：对指定账号（或已知账号批量）发 SP 指令（发放/扣减），app 拉取后端侧执行并回报实发/实扣额
3. 入口合并进**测试台**（本机 node 服务）加「📊 SP 数据」tab——不另起服务

背景：现有 SP 走 RDB cloudSync（用户私有云空间），AGC 不给开发者后台视图——**方案 A 在不动 cloudSync 主链的前提下加"镜像上报+指令下行"旁路**（refund-events pullRefundMarks 已验证模式）。

## 二、架构

```
app 端侧（ChatModel SP 收口五函数）
  │ ①SP 变更 → markSpAdminDirty() debounce 8s → buildSnapshot
  ▼
SpAdminUtil（纯传输层，零依赖） ──callFunction──▶ 云函数 sp-admin ──▶ Cloud DB
                                                  ▲   │
测试台 server.js /api/sp/* ──HTTP+X-Admin-Token───┘   │（原子 claim 指令）
  ▲                                                    ▼
测试台 index.html「📊 SP 数据」tab ◀──查询/下指令── app 三时机拉取执行回 confirm
```

**依赖方向（防环军令）**：ChatModel → SpAdminUtil 单向；SpAdminUtil 零 import ChatModel（参数全基础类型 Record/number/string）。

## 三、Cloud DB 对象类型（AGC 控制台建，Zone=default）

**SpMirror**（每账号一行快照，主键 objectId=lastAccountMark）：
`objectId`(String 主键) `availableSp`(Int) `frozenSp`(Int) `permSp` `permCons` `bonusSp` `bonusCons` `giftSp` `giftCons`(Int×6) `pkgJson`(String 包明细 JSON) `deviceModel`(String) `appVer`(String) `reportedAt`(Int ms)

**SpCommand**（指令，主键 commandId=`c${Date.now()}${rand}`）：
`objectId`(String 主键=commandId) `target`(String accountId；批量=每账号一条) `type`(String grant/deduct) `amount`(Int) `note`(String) `status`(String pending/claimed/done) `claimedBy`(String) `claimedAt`(Int) `confirmedAt`(Int) `resultAmount`(Int 实发/实扣) `createdAt`(Int)

## 四、云函数 sp-admin（docs/cloud/sp-admin/，复刻 refund-events 双入口）

- **callFunction 入口（app）**：
  - `report`：镜像 upsert SpMirror（同主键覆盖=天然幂等）
  - `fetch`：{accountId} → query SpCommand status=pending 且 target=accountId → 逐条置 claimed+claimedBy+claimedAt（竞态窗口：毫秒级，双设备同秒拉取理论双领——**一期已知边界**，数据台指令流水可发现双发，人工下 deduct 修正）→ 返回指令 JSON
  - `confirm`：{commandId, accountId, resultAmount} → status=done+confirmedAt+resultAmount
- **HTTP 入口（测试台，X-Admin-Token 校验）**：
  - `query`：{accountId}→SpMirror 单行；{accountId:'__recent__'}→最近 50 行（按 reportedAt 倒序）
  - `command`：{targets:[id...], type, amount, note}→批量建 pending 指令（全员活动=先 query 拿账号列表再勾选批量，不做 '__all__' 通配——晚激活账号拿不到通配指令是暗坑，per-account 精确无边界）
  - `commands`：最近 20 条指令+状态（盯执行结果）

部署形态：与 track-events/refund-events 同项目（老机器 E:\track-events 依赖层+agc-credential.json）；**部署前 app 侧全静默降级**（云函数 404=fetch 返回空、report 失败丢弃下轮重报）。

## 五、端侧改动

1. **新 utils/SpAdminUtil.ets**（~90 行）：`spAdminReport(payload)` / `spAdminFetch(accountId): Promise<string>` / `spAdminConfirm(commandId, accountId, resultAmount): Promise<boolean>`——全 callFunction，stringify 双路径读（IapUtil 308 定式）
2. **ChatModel.ets 尾部区块**（~110 行）：
   - `markSpAdminDirty()`：置标志+8s debounce → `reportSpAdminMirror()`（读 HuaweiAccountStore.lastAccountMark，空=未登录跳过；快照=siyiTotalSp/frozenAvailableSp/三池/pkgJson）
   - `pullSpAdminCommands()`：fetch→逐条执行（grant=grantBonusSp(siyi, n, 'admin')；deduct=consumeSiyiSp 到 0 为止）→confirm 回实发/实扣
   - 五收口函数尾部挂钩：consumeSiyiSp / grantBonusSp / doSignIn / grantSiyiWelcomeBonus / grantSiyiSpFromIap
3. **挂点**：EntryAbility.onForeground（pullRefundMarks 旁，指令拉取主时机）+onBackground（镜像 flush 碰运气——退后台网络受限已知，失败静默下轮补）+BillingPage.aboutToAppear（账单页进场即查）

## 六、测试台改动（用户明确指派迭代，正本 testing/console/）

- public/index.html：tabs 行加「📊 SP 数据」+paneSp（查询框+181/180 快捷钮+余额卡+包明细+指令下发表+指令流水表）

## 七、已知边界与风险

1. 快照滞后：设备不开 app 不刷新（数据台显示 reportedAt，非实时）
2. claim 竞态窗口（毫秒级双领）——一期接受，流水可查可补偿
3. 云函数未部署=全链静默零影响（app 零报错零阻塞）
4. 扣减只针对嘉奖口径建议（IAP 充能扣减有消费纠纷风险——运营侧人为注意）
5. **红线零触碰**：CloudSyncUtil/BackupUtil/持久化 key 均不动；指令执行走既有收口函数（grantBonusSp/consumeSiyiSp），SP 铁律 gate 防御照常生效

## 八、验收标准

1. `devecocli build` 绿 + 三台装机 VERSION=1000440
2. 测试台 SP tab：输 181 账号 ID → 显示余额卡（云函数部署前显示"未部署"友好提示，不报错）
3. 云函数部署后：app 发一条 AI 消息（SP 变更）→ ≤10s 数据台余额刷新；数据台下 1 万发放指令 → app 回前台/进账单页拉取执行 → SP+1 万 → 数据台指令变 done+余额再刷新
4. 测试台新增用例（军令）：SP-ADMIN 查询/指令主路径用例
