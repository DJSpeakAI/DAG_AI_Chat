## 二、图2：AI token 优化 — 分层按需加载

### 四层加载模型（写入 project_rule.md §5）

| 层级 | 内容 | Token 消耗 | 加载时机 |
|------|------|-----------|---------|
| **L1 索引层** | `docs/index.md`（总索引，~1KB） | 极低 | 每次必读，定位目标段 |
| **L2 段索引层** | `段/index.md`（如 0.165+/index.md，~0.5KB） | 低 | 定位到段后按需读 |
| **L3 详情层** | 具体需求文档（单篇 5~10KB） | 中 | 按需读，不预读 |
| **L4 归档层** | 历史段（0.140-0.152/、0.160-0.164/） | 高 | 仅当需查历史时按需读 |

**规范**：
- 索引文件只放「一句话描述+路径」，**不展开子内容**
- 单篇文档精简线 10~15KB，超长文档需拆分或精简
- 历史段默认不加载，AI 需查历史时按需读段索引
