# 0.248.4 账号级资产多端同步（等级头衔/学习统计/司忆点 SP）

## 一、需求背景（用户原话）

「同样的账号登录，手机上面是 Level 1 的好奇宝宝，Pad 上面是 Level 6 的领域先哲——不一样啊。」

## 二、根因（代码实锤）

- 等级头衔 = `siyiLevelTitle(累计学习天数)`，天数 = StatisticsStore days 行数（ChatModel.ets:865 / BillingPage.ets:37 / AppSideBar.ets:56）
- StatisticsStore（key `statistics-v1`）与 SiyiPointStore（key `siyi-points-v1`）均为**本地 PersistenceV2**——只记本设备使用
- 云同步行模式（0.228.0）只同步词库/知识库/气泡树/cfg 三枚——**统计与 SP 从未上云**
- 结论：每台设备各自数各自的，同账号 ≠ 同数据。连带雷：将来 SP 充值/消耗上线后多端余额不一致（钱的口径）

## 三、方案（用户拍板 A：统计+SP 双行上云）

复用现有 `cfg:` 行域（账号级数据通道，传输层零改动——**CloudSyncUtil.ets 红线文件不动**）：

| 新行 | payload | 合并语义 |
|---|---|---|
| `cfg:stat-days` | StatisticsStore.raw 原文（{"days":[...]}） | **并集**：本地∪云端按 date 键；同日各数值（userMsgs/aiMsgs/bubbles/inputTokens/outputTokens/siyi）**取 max** |
| `cfg:siyi-points` | {permanentSp, bonusSp, giftSp, giftSpExpireAt, welcomeGranted} | 三池+到期戳**各自取 max**、welcomeGranted 取或 |

### 合并语义为什么绝不做 LWW 整行覆盖（防毁灭）

新装机本地空态 vs 云端全量（或反之）若走 LWW 整行覆盖=一方资产被另一方旧值清空。统计「只增不减」（0.192.0 定案）与 SP 当前「只发放无消耗」（0.247.7 消耗链路待开发）语义下，**max/并集合并数学上保证单调收敛、幂等、无乒乓**。

### 数据流

- 上行：recordStat（统计落盘）/ grantSiyiWelcomeBonus / redeemCode（SP 变动）尾部挂 `scheduleRowFlush()`（3s 防抖）；flush 首拉播种、diff-cache、首拉闸门、墓碑压制全部复用现有机制
- 下行：reconcile → mergeCfgs 尾部新增 mergeStatDaysRow/mergeSiyiPointsRow（专用合并，不走 apply/cloudWins LWW 通道）；合并写回 @Trace 字段 → 等级头衔/统计页/SP 余额 UI 自动刷新；变化则 scheduleRowFlush 把并集推回云端（全端收敛）
- 稳态：两端收敛后 diff 全等零写行（零 churn）

### 收敛示例（本 bug 场景）

Pad 300 天 / 手机 1 天 → 任一端下行合并 → 两端均 300 天 → 手机显示 Lv6 领域先哲 ✓

## 五、风险点

1. 行大小：一年 ~365 天 ×~90B ≈ 33KB，远低于 512KB 分块线 ✓
2. 老版本 app（无此功能）共存：未知 cfg 行被旧版 mergeCfgs 忽略，无害滞留 ✓
3. 序列化稳定性：merge 输出按 date 升序、entry 字段序与 recordStat 字面量一致，稳态 diff 全等 ✓
4. 云同步关闭/未登录：闸门（rowInitDone）天然拦截上行，reconcile 不跑合并不触发 ✓
5. **将来 SP 消耗链路上线时 max 合并语义失效**（扣减会被另一端 max 回填）——届时须改服务端权威或 Last-Writer-Wins per-field，此处留档预警
6. Lv7「连续 365 天」口径：当前等级表按累计天数判（连续性收紧待签到引擎，0.247.7 已档），本修复不改变口径

## 六、验收标准

1. 三端登录同账号开云同步 → 收敛后（前台各拉一轮）边栏账户区/账单页等级头衔三端一致
2. 统计页三端数据一致（天数并集、数值 max）
3. SP 余额三端一致（兑换码在一端兑，他端可见）
4. 云同步关闭时统计/SP 照常本地工作（零回归）
5. 编译零错误 + versionCode 1000298 三处同步
