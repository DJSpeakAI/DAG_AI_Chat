## 一、项目背景（评审 AI 必读）

**DAG AI Chat**：鸿蒙 ArkUI V2 应用（纯 ArkTS），AI 学习工具——气泡树对话为核心，带单词库/知识库/复习系统/云同步（华为 RDB cloudSync）/华为账号登录/订阅。**三端形态**：鸿蒙 PC（鼠标+键盘+多窗口）、Pad（触控+Pencil）、手机（触控+抽屉边栏）。

**测试台现状**（已运行 25 个工具版本的成熟基建）：
- Node 本地服务（127.0.0.1:8766）+ HTML 控制台 + hdc 驱动真机（PC/Pad/手机）
- 已有 5 套件：版本核验 / 账号登录矩阵（7 用例全绿）/ 云同步静态比对（SYNC-DOMAIN）/ 云同步数据链跨端编排（SYNC-FLOW）/ ArkUI hypium（设备内断言 2 条）
- **核心能力**：UI 自动化原语（dumpLayout 定位控件→坐标注入点击/长按/文本输入，支持多屏 displayId）、sqlite 直读断言、SSE 实时流、人工检查点状态机、artifacts 证据留存、用例级超时、假绿根治断言纪律（报错/非数值=红灯）
- **纪律基线**：每条用例复刻真实用户路径【前置状态→真实步骤→预期表现】三要素；唯一人工=华为授权页

**UI 规范现状**：`UI_GUIDELINES.md`（251 行项目级真相源）——14 色值 Token / 5 档圆角 / 8 文字样式 / 语义间距 4 档 / 13+ 组件规格 / 弹窗宽度断点制 / 图标两档制 / 顶栏统一规范（显式 height 56 等）；`DesignTokens.ets` 落地 43 个导出常量（唯一来源）。

**用户核心诉求**：全盘 APP 全自动化测试规划；**重点=UI 测试**（用户原话点名：弹窗、按钮大小、提示框按钮"都有不一样的"问题）；基于 UI_GUIDELINES 已有"对准的基调"。

## 三、UI 测试六大类（分类框架 + 条目清单）

### A 类：UI 规范合规审计（UI_GUIDELINES 对标）★ 一期重心

**思路**：把 UI_GUIDELINES 从"人读文档"升级为"机器可断言"——`uitest dumpLayout -a` 可导出控件全属性（含 fontSize/fontWeight 字体属性、backgroundColor、bounds 宽高），与 DesignTokens 期望值表逐项比对。

**断言能力分级**（技术现实）：
- **L1 直接断言**：颜色（backgroundColor vs token 值）、字号/字重、控件尺寸（bounds 宽高——"按钮大小不一样"直接可测）
- **L2 几何推导**：间距（相邻控件 bounds 差值）、等宽（双按钮 width 差≤1px——历史 bug 0.197.3 直接抓）、对齐（中心轴一致性）、顶栏高度（bounds 高=56vp 定式）
- **L3 dump 不可达**（圆角/阴影/渐变/图标风格）→ 二期截图视觉回归兜底，一期标注"暂不覆盖"

### 8.3 首份审计报告·发现清单（7 fail + 代表性 warn）
**硬违规（fail，修复走 app 迭代）**：
1. **词库编辑器宽 905vp=裸 86%**（WordBankPage.ets:1045，0.201.2 断点制改造漏网——应 520）
2. **词库编辑器双按钮不等宽**（差 29px——无 layoutWeight(1)，0.197.3 等宽规范只改了设置弹窗）
