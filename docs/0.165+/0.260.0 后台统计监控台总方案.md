## 一、V1.1 架构大改（华为核实引发的三个翻案）

| # | V1.0 假设 | 华为核实结果（官方文档背书） | 架构动作 |
|---|---|---|---|
| 1 | ❌「个人开发者无数据 API，只能手动导出 CSV」 | ✅ **有 Reports API**：下载安装报表（GET 返回 CSV/Excel 下载地址）、用户分析/留存分析指标数据（POST）、安装失败报表；调用者角色=账号持有者即可（个人开发者本人满足） | 看板改「**Reports API 定时自动拉取**」，CSV 手动导入降级为兜底 |
| 2 | ❌「DAU/时长/留存要集成 Analytics Kit 才有」 | ✅ 开发者中心「用户看板」=**系统侧打点，不集成 SDK 也有**（新增/活跃/平均使用时长/次日三日七日留存）；仅行为分析/自定义事件/用户分群需 SDK。分析数据留存最长 14 个月（默认），超期自动删 | **自建埋点大幅收窄**：明细只存 SP 相关事件（平台已有 DAU/时长/留存，不重复建设、省 Cloud DB 写配额）；Cloud DB 长期存储反而是我们的独特价值（平台 14 个月就删） |
| 3 | ❌「收入要自建兑码登记+报表导入为主」 | ✅ 开发者中心有**「财务分析」内置报表**（概览/流水/购买者/转化量/订阅五页，含 ARPPU）+「数字商品服务分析」；IAP 有**服务端验签（官方推荐）+ 订单状态查询接口 + 订阅关键事件通知（webhook，v3）**；个人开发者可开 IAP | 收入块主体**用平台报表**；看板只做录入/展示（Reports API 能力清单未含 IAP 收入——收入数据仍需人工导出录入，上架后实测有无更优出口）；上架后 IAP 接服务端验签+关键事件通知 |

**其余关键核实**：崩溃服务已合入 APMS、HarmonyOS **免集成自动采集**（AGC 开通即可看）、有崩溃指标 OpenAPI（v1/v2）、**APMS 告警支持短信/邮件/Webhook**（可白嫖做质量告警通道）；Cloud DB 免费配额=**存储 1GB / 读 5 万次/天 / 写 2 万次/天 / 每秒 10 操作**（写入是埋点链路真瓶颈）；云函数 100 万次/月免费（充裕）、同步调用最长 55s（埋点函数无压力）；随机 UUID 属「应用内设备标识符」**须隐私政策披露+同意后收集**；华为账号只能拿 OpenID/UnionID 不能拿 UID（路径=客户端授权码→云函数→华为服务端解析→hash 入库）；Publishing API 确认不含数据报告。

## 二、需求定位与平台/自建分工（华为 Q11 官方推荐背书）

| 板块 | 分工 | 数据来源 |
|---|---|---|
| ① 行为埋点 | 自建（已有 22 事件，保留） | events 表 |
| ② SP 消耗与成本 | **自建（唯一必须自建的核心）** | sp_consume 事件 |
| ③ 收入 | 平台为主 + 看板展示 | AGC 财务分析报表（人工导出/录入）+ 兑码记录（现阶段） |
| ④ 下载/用户规模 | **平台** | Reports API 自动拉取（下载安装+用户分析） |
| ⑤ 停留时长/留存 | **平台**（系统侧打点已有） | Reports API / 控制台；app_session 事件降为可选 |
| ⑥ 告警红线 | 自建规则 + 平台辅助 | 看板规则引擎（成本红线）；APMS Webhook（崩溃告警白嫖） |

**定位一句话：自建部分收窄为「SP 消耗统计 + 聚合看板」两件，其余全接华为平台数据——省配额、省开发、数据更权威。**

## 三、总体架构（V1.1）

```
[端侧] TrackUtil（收窄）
   ├─ sp_consume ★新：SP 实扣时上报（唯一强制新增明细）
   ├─ app_first  ★新：协议同意后一次性上报（装机激活）
   ├─ app_session ▽降级可选：平台已有时长数据，仅按需保留
   └─ p 内嵌 u:匿名uid（合规：隐私政策披露+同意后才收集）
        ↓ 云函数 track-events → Cloud DB events（明细只存 SP 类，量小配额安）
[平台侧] 华为 AGC（免建设）
   ├─ Reports API ★：下载安装/用户分析/留存（看板定时拉取）
   ├─ 财务分析报表：收入/流水/ARPPU（人工导出→看板录入）
   ├─ APMS：崩溃自动采集+崩溃指标 API+Webhook 告警
   └─ 项目配额页：官方自动提醒（互动中心/邮件/短信）
[看板] 老机器 dashboard 升级五 Tab
   ├─ Tab1 行为埋点（现有平移）
   ├─ Tab2 SP 消耗★（日曲线/模型分布/用户TOP/成本¥换算——调参核心）
   ├─ Tab3 收入（财务报表数据录入+兑码登记）
   ├─ Tab4 规模与质量（Reports API 拉的下载/用户/留存+崩溃指标）
   ├─ Tab5 告警（成本红线规则引擎；APMS Webhook 接收端）
   └─ 数据治理：日汇总+过期明细清理（对齐 1GB/写2万次/天红线）
```

## 四、端侧埋点设计（收窄版）

| 事件 | 触发 | p 参数 | 备注 |
|---|---|---|---|
| `sp_consume` | `consumeSiyiSp()` 收口旁（与 0.259.0 本地统计同点双写） | `{u, sp:本次扣点, m:模型, sc:场景chat/regen, f:免扣y/n}` | **全 AI 调用都埋**（含 Lv8 免扣标 f:y——成本监控要真实成本）。量级：日活 1 千×日均 20 次 AI 调用=2 万行/天=恰好贴 Cloud DB 写配额上限→用户量大前须切「云函数内聚合落库」（见 Q3） |
| `app_first` | 协议同意门禁通过后（一次性） | `{u}` | 合规定案：明示同意后收集，符合华为审核口径；隐私政策补「应用内设备标识符（随机生成）用于统计」条款 |
| `app_session` | onBackground 上报前台秒数 | `{u, secs}` | **降级可选**：平台用户看板已有时长（系统侧打点）；仅当需「按场景/页面细分时长」才值得花写配额——默认砍掉（Q2） |

**uid**：端侧首启随机 UUID（12 位截断）存 preferences，塞 p 的 JSON（events 表零结构变更）。**同意前不收集**（挂协议同意门禁后）；行为埋点继续随「体验改进计划」开关。上架后若需账户维度去重，升级 OpenID hash（Account Kit 授权码→云函数解析→hash 入库，不存明文）。

**口径纪律**：埋点字典同步登记；SP 事件名对用户不可见（防反推铁律只约束 app 界面）。

## 五、看板设计（老机器 dashboard 扩展）

1. **Tab2 SP 消耗**（调参核心）：日/周/月消耗曲线、按模型分布、匿名 uid TOP、**成本 ¥ 换算**（系数放 config.json，调算法改配置不改码；app 内禁 ¥-SP 换算，看板内部工具不受限）。
2. **Tab3 收入**：兑码记录登记（现阶段）+ AGC 财务分析报表数据录入（上架后）；毛利视图=收入对冲 SP 成本。
3. **Tab4 规模与质量**：**Reports API 定时拉取**（下载安装+用户分析指标）自动画趋势；崩溃指标 API 接入；**Cloud DB/云函数配额余量展示**（距红线 20% 预警——写 2 万/天、存 1GB）。
4. **Tab5 告警**：成本红线规则引擎（V5.0：9.9 档月均真实成本>5 元；可扩 DAU 连跌、免扣账号成本异常）看板红条；**APMS Webhook 接收端**（华为推崩溃告警进看板）。
5. **Reports API 接入**（看板服务端）：账号持有者授权→client_id/access_token→定时 GET/POST 拉报表→解析入看板本地库。授权流程细节实施时向华为 AI 索取（其答复已表示可展开）。
6. **安全**：8766 加访问口令（上成本/收入数据后局域网裸奔不妥）。
7. **数据治理**（对齐 Cloud DB 配额）：看板端日终聚合 SP 明细→汇总指标行；明细滚动清理（删除额度 2 万/天够用）；查询走汇总不走明细。

## 六、合规要点（Q8 核实后收紧）

- 随机 UUID=应用内设备标识符：**隐私政策必须披露**（类型/目的「统计应用使用情况」/方式）+**同意前不收集**（埋点初始化挂协议同意门禁之后）。
- APMS 崩溃采集为系统默认行为（免集成也采），隐私政策建议一并披露。
- 华为 AI 声明其答复不构成法律意见；上架前合规复审对齐《个保法》。
- 看板含成本/收入数据：仅内网+口令，绝不公网。

## 八、验收标准（V1.1）

1. AI 对话一次 → events 出现 sp_consume 行（p 含 u/sp/m/sc/f，数值=实扣）；Lv8 免扣账号 f:y。
2. 全新安装+同意协议 → app_first 恰 1 行；**未同意协议前零埋点**（合规红线）。
3. 看板 Reports API 拉取：下载安装/用户分析数据落地 Tab4 并画趋势。
4. 看板 Tab2 日消耗与端内统计页（0.259.0 第五卡）当日值一致（双口径互验）。
5. 配额余量展示：Cloud DB 写次数/存储量可见，距红线 20% 预警。
6. 无口令访问看板被拒。
7. 成本红线触发 → 看板红条+记录。

## 十、发散种子（跨领域对照，供联想）
