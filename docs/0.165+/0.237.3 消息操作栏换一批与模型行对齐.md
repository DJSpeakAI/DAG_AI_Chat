## 三、改动方案

### A. 新增「换一批」按钮 + 重抽功能（核心新功能）

**A1 图标**：新增 `entry/src/main/resources/base/media/shuffle.svg`——交叉双箭头（shuffle/随机）语义，24×24 viewBox、单色细线（stroke 1.5~2、fill 白，透明度对齐 4567 行 copy 图标的现有写法，保持按钮亮度一致——历史定式：图标白 65% 透明度统一口径）。禁止复用 `refresh.svg`（用户红线）。备选 `undo.svg`（已有）语义偏「撤销」，不推荐。

**A2 交互逻辑**（onClick 新方法建议名 `shuffleReviewBatch(msg.messageId)`）：
1. `this.reviewCache.delete(msg.messageId)`（生词缓存失效）
2. 知识卡缓存同款失效（先读 3385 行 `getKnowledgeCards` 确认其缓存条目 key 与删除方式，与生词同构处理）
3. 触发两区重渲染 + 重新抽取（见 A3）
4. **重抽路径不得重复计「展示即复习」学习数**——施工时先读 2868-2887 行，把「抽取」与「计数」分离：仅首次展示计数，shuffle 重抽跳过计数（防刷学习统计）。

**A3 重渲染触发（关键实现点）**：`reviewCache` 是普通 Map（非状态），删除缓存后 `ForEach(this.getReviewWords(...))` 不会自动重算。推荐做法：
- 组件内新增 `@Local rerollSeq: number = 0`；
- 点击换一批：失效缓存 + `this.rerollSeq++`；
- 词区/知识卡区 `ForEach` 数据源改为 `this.getReviewWords(msg.messageId, this.rerollSeq)`（方法加第二参数仅为让渲染闭包读到 `rerollSeq` 建立依赖；`rerollSeq` 必须挂 **`@Local`**，否则真机依赖链不可靠——历史雷：状态成员未挂 @Local 致 @Computed/依赖链真机取值漂移）。
- 若施工时发现 `getKnowledgeCards` 走独立状态源，则两区各自建依赖，同一个 `rerollSeq` 可共用。

**A4 按钮规格**：与现有按钮完全同款（图标 14、padding 4、Row 间隙 space 8），插在刷新块（4589-4600）与复制块（4567）之间的目标位置（见 B 项重排后）。

### B. AI 回复行按钮重排

目标顺序（从左到右）：**喇叭 → 刷新 → 换一批 → 复制 → 删除 → (弹性 Blank) → 模型名 → token 统计**。

操作：在 4566-4635 的 `Row({ space: 8 })` 内移动现有块即可（喇叭块 4622-4633 挪到最前，新增换一批块插在刷新后复制前）。「换一批」恰在复制左边，与用户「在复制按钮左边加」口径一致。

> ⚠️ 用户口述末尾的「然后再是刷新」判为口语重复（刷新已在第二位），最终顺序以上表为准；若用户有异议以对话记录修正。

### C. 用户消息行加喇叭

4125-4149 行改为三按钮：**喇叭 → 复制 → 删除**。
- 喇叭块从 AI 行（4622-4633）**复制一份**到用户行最前，onClick 同样 `this.startTTS(msg)`，三态图标逻辑原样（`ttsLoadingMessageId`/`playingMessageId` 状态机对 user 消息同样生效）。
- **施工前核对**：读 `startTTS`（1925 行）确认对 `role === 'user'` 消息无 role 限制、朗读内容字段取 `msg.content` 正常；若内部只对 assistant 生效须放行 user 分支。
- 用户行**不加**换一批、刷新（用户明确「他不需要」）。

### D. 模型信息行对齐 + 自适应滑动

**D1 结构调整**（同一 `Row({ space: 8 })` 内）：
```
Row({ space: 8 }) {
  [按钮组: 喇叭/刷新/换一批/复制/删除]
  Blank()                    // 弹性占位，把右侧信息组推到行尾
  Row({ space: 6 }) {        // 右侧信息组
    Scroll { Text(模型名) }.scrollable(Horizontal).scrollBar(Off).constraintSize({ maxWidth: '35%' })
    Scroll { Text(输入 X · 输出 Y) }.scrollable(Horizontal).scrollBar(Off).constraintSize({ maxWidth: '50%' })
  }.alignItems(VerticalAlign.Center)
}
.margin({ top: 4, left: 10, right: 10 })   // ★ 右 10 补齐，与左 10 对称
```

**D2 关键点**：
- **右对齐**：`Blank()` 撑开中段，模型名+token 贴行尾（满足需求 5）。
- **边距对称**：现状 `.margin({ top: 4, left: 10 })` 补 `right: 10`——左 10（喇叭左缘离气泡内容左缘）=右 10（输出数字右缘离气泡内容右缘）（满足需求 6）。施工时核对气泡实际 padding（侦察：left 10 = 气泡 padding 10，两侧对称成立）。
- **模型名间距缩小 + 自适应**：`constraintSize({ maxWidth: 100 })` 写死值改为**百分比 `'35%'`**（随气泡宽度自适应，符合「禁止写死固定尺寸」UI 规范；宽屏自然多给空间，窄屏自动收窄=「间距缩小」）。
- **token 大数字保护**：token Text 包 `Scroll` 横向 + `scrollBar(BarState.Off)` + `maxWidth: '50%'`——5~6 位数（十几万）时可手指横滑看全、无滚动条横杠（满足需求 7/8）。两比例合计 ≤85%，给按钮组留余量；施工时按窄屏实测微调。
- **平台策略（设计取舍说明）**：采用「统一 Scroll、溢出才可滑」——宽屏（PC/Pad）内容放得下时 Scroll 表现为静态、无滑动条，等效「不需要滑动」；窄屏（手机）自动可滑。零平台分支代码、自适应，等效满足「只在手机上滑动」的诉求且不违反布局自适应规范。
- 模型名已有 Scroll+Off（4604-4615）仅改 maxWidth，token 是新增 Scroll。

## 五、风险点与 ArkTS 雷区提示

1. **带参 @Builder 按值传参雷**：若把按钮抽成 @Builder 复用（AI 行/用户行同款），禁按值传参（历史反复复发雷）——建议直接内联 Row 块复制，不抽 Builder。
2. **状态成员必须挂 `@Local`**：新增 `rerollSeq` 等 any 状态成员漏挂 @Local 会导致真机依赖链不可靠（历史雷三度复发）。
3. **ForEach Key**：词区重抽后词条集合变化，确认 ForEach key 生成含词条唯一标识（word/id），防 key 碰撞复用错乱（历史有 ForEach Key 碰撞修复史，MEMORY 已记）。
4. **学习计数副作用**：换一批重抽**不得**重复计「展示即复习」数（A2 第 4 条），施工时读 2868-2887 分离计数与抽取。
5. **「历史消息稳定」语义变化**：reviewCache 为内存 Map——换一批结果**仅当前会话内生效**，重启 app 后回到遗忘曲线默认首批。此为可接受行为（写在此处备案，不额外做持久化）。
6. **用户行喇叭的状态互斥**：`ttsLoadingMessageId`/`playingMessageId` 为消息级单值，AI 行与用户行按钮共用同一状态机，天然互斥（同一时间只读一条），无需额外处理；核对三态图标在用户行的取值分支即可。
7. **Scroll 嵌套手势**：模型名 4604-4615 已有横向 Scroll 在同结构中运行正常，token 新增 Scroll 属同款复制，无新增风险；勿给 token Scroll 加 `edgeEffect` 弹簧以外多余效果。
8. **图标亮度和尺寸**：shuffle.svg 视觉规格必须与 copy/trash 完全一致（图标 14、同透明度），防「纯白太亮」类历史 UI 反馈复发。
