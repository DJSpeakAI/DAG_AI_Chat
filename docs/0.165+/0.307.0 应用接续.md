# 0.307.0 应用接续（Continuation）

## 一、需求（用户口述）
手机与 AI 对话到一半（含输入框打字到一半）→ 回到 PC 一键接续，直接落到同一气泡对话页并回填草稿——免"打开 app→找对话框"两步。参照哔哩哔哩跨设备接续体验。

## 二、官方文档核实结论（bpta-continue-cast / bpta-continue-data）
1. **无需 AGC 申请**：接续服务申请仅限"不同开发者不同 AppID"场景；我们同 bundle（com.dagaichat.app）跨自己设备=纯客户端能力。
2. 前置条件：双端登录同一华为账号；开 WLAN+蓝牙（或"多设备协同增强服务"）；系统设置"多设备协同 > 接续"开启；双端都装应用。
3. API12 起 DISTRIBUTED_DATASYNC 权限都无需申请（我们已声明，无碍）。
4. 机制：源端 `onContinue(wantParam)` 存数据（<100KB 走 wantParam）→ 系统迁移 → 目标端 `onCreate/onNewWant`（launchReason=CONTINUATION）恢复；**迁移启动走 onWindowStageRestore 不走 onWindowStageCreate**，须复刻初始化。
5. wantParam 系统预置 key：version/targetDevice——自定义 key 禁撞。

## 三、方案（最小闭环）
- **payload**：`dagNode`（当前气泡 ID，空=落画布）+ `dagDraft`（实时草稿文本）——远小于 100KB；对话数据本体走云同步，接续只传"指针+草稿"。
- **桥**（新 utils/ContinueBridge.ets，AppStorageV2 'continue-bridge' 不落盘）：
  - 源端实时态：`inChat`（ChatPage 前后台）+ `nodeId` + `draft`（saveDraft 每键顺带写）
  - 目标端待恢复：`pendingNodeId` + `pendingDraft`（onCreate/onNewWant 写，BBTreeCanvas/ChatPage 一次性消费）
- **源端**（EntryAbility.onContinue）：读桥 → wantParam 双字段 → AGREE。
- **目标端**（EntryAbility）：
  - onCreate/onNewWant：CONTINUATION 分支 → 解析 want.parameters → 写桥 pending* → `restoreWindowStage(new LocalStorage())`
  - onWindowStageCreate 逻辑提取 `setupMainWindow()` 共用；新增 `onWindowStageRestore` 同调（官方：迁移启动不走 onWindowStageCreate）
- **恢复链**：Index 启动链照常直达 BBTreeCanvas → BBTreeCanvas `consumeContinuePayload()`（aboutToAppear+onShown 双保险，幂等）：nodeList 找到节点 → currentBubble 交棒三连（nodeID/x/y）→ pushPath ChatPage；找不到（云下行未达/已删）→ 静默落画布+清 pending。
- **草稿回填**：ChatPage aboutToAppear 原有 `inputText = draftBubble.draftText` 后追加——pendingNodeId 匹配当前气泡且 pending 存在 → `inputText = pendingDraft` 覆盖（源端最后一刻草稿新鲜度 ≥ 云端版本），随即清 pending。
- **module.json5**（红线文件、用户指派知情）：EntryAbility 加 `"continuable": true` 一行，其余零动。

## 四、改动文件
module.json5（1 行）/ utils/ContinueBridge.ets（新）/ EntryAbility.ets（onContinue+CONTINUATION 分支+onWindowStageRestore+setupMainWindow 提取）/ ChatPage.ets（桥写三处+pendingDraft 回填）/ BBTreeCanvas.ets（consumeContinuePayload）/ 版本三处。

## 五、边界与风险
- 节点刚建几秒即接续：云端未下行目标端 → 落画布（草稿经 wantParam 已达但无宿主气泡，弃置；概率极低，后续可做"等下行重试"）。
- 热启动迁移：restoreWindowStage → loadContent 重载 → 页面栈重建为恢复态（官方预期行为）。
- 快速启动（_ContinueQuickStart 后缀）第一版不配（双次启动回调复杂度不值当，待用户试用后按需）。
- 四端设备系统设置"多设备协同>接续"需开启——交付 TXT 指引。

## 六、验收标准
1. 手机 ChatPage 打字到一半 → 系统接续到 PC → PC 落同一气泡对话页+草稿回填。
2. 手机在画布（非对话页）接续 → PC 落画布。
3. 未开系统接续开关时无任何影响（continuable 仅声明能力）。
