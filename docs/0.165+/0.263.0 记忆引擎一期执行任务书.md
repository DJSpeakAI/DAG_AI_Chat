## 一、背景（一段话，知道在做什么即可）

产品北极星：**同一个模型（如 DeepSeek flash 档），用户聊得越久越觉得"这个 AI 更懂我"**。本次实现两个速赢信号：**S1 跨会话连续性**（AI 记得用户是谁、在学什么、偏好什么）+ **S2 跨分支情境感知**（在分支 B 提问，AI 知道兄弟分支 A 聊过什么）。现状基线：上下文组装在 `ChatPage.ets` 的 `buildBranchMessageList`（约 1563 行起）——沿 parentID 回溯父链全量组装，48K token 触发线 + 8K 近期保留窗口 + LLM 结构化摘要（该机制**本次一行不动**）。

## 二、项目铁律（执行 AI 必读必守，违反=废稿）

1. **ArkUI V2**：@ObservedV2 + @Trace，禁 V1 语法；@ObservedV2 对象序列化必须手写 plain 字段映射（参考 ChatModel.ets 现有 serialize/revive 模式），JSON.stringify 直接序列化会输出 `{}` 空对象。
2. **Schema 铁律**：数据类字段只许**尾部追加+默认值**，禁改名/改类型/删除（尾部追加是合规操作，有 0.202/0.214.2 先例）。
3. **持久化 key**：新 key 一律首版带版本号，本文档已指定，发布后禁改。
4. **红线文件禁改**：CloudSyncUtil.ets / BackupUtil.ets / 数据模型既有字段 / signing / module.json5。涉及处见第六节"转人工"标注。
5. **摘要/记忆类 LLM 调用失败一律静默降级**（沿用旧数据），绝不阻断对话、绝不弹报错。
6. **多提供商约束**：不依赖任何单一模型专有能力（无 function calling 依赖、无 embedding 依赖）。
7. ArkTS 禁 `delete` 运算符；带参 @Builder 按值传参是雷；import 必须连续置顶。
8. 全程简体中文；UI 遵循 UI_GUIDELINES.md。

## 四、数据模型定案（照此实现，字段名一字不差）

### 4.1 ProfileObservation（新文件 `entry/src/main/ets/common/ProfileModel.ets`）

```
@ObservedV2
class ProfileObservation {
  @Trace observationID: string = '';   // 唯一ID（generateMessageId 同款规则），未来云同步行级仲裁主键
  @Trace kind: string = 'preference'; // identity / goal / preference / emotion 四枚举
  @Trace content: string = '';        // 一句话观察（如"偏好简洁的推导步骤"）
  @Trace sourceNodeID: string = '';   // ★必填：来源气泡节点ID（画像↔树溯源桥梁，"AI 为什么觉得我喜欢X"全靠它）
  @Trace supersededBy: string = '';   // 被哪条观察取代（空=生效中）；偏好演变轨迹=S4 的数据链
  @Trace createdAt: number = 0;
  @Trace updatedAt: number = 0;
}
```

- 持久化：PersistenceV2，key = **`profile-observations-v1`**（发布后禁改）。
- 同文件实现 plain 映射 serialize/revive（参考 ChatModel.ets 的 SerializedMessage 模式）。
- **只追加、不删除**：画像更新 = 旧偏好行打 `supersededBy` 标记（禁 delete），新观察 push 追加。
- 聚合视图 `buildCardView(): string`：过滤 `supersededBy === ''` 的生效行，按 kind 分组、按 createdAt 稳定排序（**稳定排序保证前缀缓存命中**），拼装为：

```
[用户画像]
- identity: 用户是高三学生，正在备考数学
- goal: 目标是掌握导数的应用题
- preference: 偏好分步骤推导，不喜欢直接给答案
- preference: 2026-10-19 起偏好改为先看结论再展开（演变前项已取代）
```

### 4.2 BubbleNode 尾部追加（`common/ChatModel.ets`，@Trace + 序列化 plain 同步补两处）

```
@Trace topicTags: string[] = [];   // 话题词 0~5 个，随节点行持久化（云同步自然携带）
@Trace summaryHead: string = '';   // 分支摘要头（一行：节点标题+一句话摘要+话题词），失活时生成
```

默认值空，旧数据零迁移。SerializedBubbleNode 同步尾部追加两字段（revive 缺省容错）。

## 五、五个工作包（P0 全量）

### WP1 画像观察行系统
1. 新建 ProfileModel.ets（上节定案）。
2. **画像更新触发**：会话每 8 轮（用户消息计数）或会话结束（aboutToDisappear）触发一次隐式 LLM 调用：输入=旧画像卡 + 本段新增对话，输出=新观察行（JSON 格式约束：只输出 JSON 数组，每项 {kind, content, sourceNodeID}；沿用 AiClient 容错解析模式）。识别到偏好变化时：新增新行 + 对旧行调 supersede()。
3. 注入：`buildBranchMessageList` 返回前，在消息数组**最前部**（现有人格 system 之后）插入画像卡 system 消息。画像卡为空（新用户）时跳过注入。
4. 失败降级：解析失败/调用失败 → 静默沿用旧画像，下轮重试。

### WP2 分支摘要卡 + 摘要头注入（树距离衰减版）
1. **失活触发**：切换活跃气泡节点时，旧节点若 `summaryHead` 为空或内容新增 ≥10 条，入 pending 队列。
2. **闲时 flush**：批量处理 pending（合并为一次 LLM 调用，输入=各分支最近对话，输出=每分支 {summaryHead, topicTags}）；应用退后台瞬间申请 **Background Tasks Kit 短时任务**续跑本轮（防切后台被杀导致下次无摘要头）；写回节点字段 + saveTree()。
3. **注入规则（树距离衰减，总预算 ≤3000 token 超则裁远端）**：
   - 同父兄弟分支（距离 1）：完整摘要头行（标题+一句话摘要+话题词）
   - 距离 2（叔伯辈）：仅"标题+话题词"一行
   - 距离 ≥3：不注入
   - 格式：一条 system 消息 `[相关分支背景]\n- 分支A（导数技巧）：讨论了换元法… [数学/导数]\n- 分支B：…`，插在历史摘要消息之后、当前路径消息之前
4. 失败降级：摘要头为空的分支直接跳过（不阻塞）。

### WP3 摘要 prompt 问题感知升级（common/Prompts.ets）
- SUMMARY_PROMPT 五部分清单保留，新增第六部分要求："结合本轮用户问题视角：与本问题相关的信息优先保留"。摘要调用入参带上当前 pending 问题（generateSummaryWithLLM 增加可选参数）。改动极小，遵守 Prompt 10 条军规。

### WP4 token 埋点（Q6 定案）
- `buildBranchMessageList` 内分段统计：画像段 / 路径段 / 摘要头段 / 历史摘要段各自估算 token，落本地统计（PersistenceV2 key `memory-inject-stats-v1`，保留 14 天滚动）。不走埋点上报、零 LLM 成本。两周后用户按 P90 决策（>5K 裁摘要头，禁调 48K）。

### WP5 「深度记忆」总开关（降级兜底）
- 全局设置弹窗 AI 偏好区新增开关（默认开）。关闭后：不注入画像卡+摘要头、不触发画像更新与失活摘要（回到纯父链模式），数据保留。这是记忆系统出 bug 时的用户自救开关。
