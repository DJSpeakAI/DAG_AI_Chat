# 0.136 TTS 修复（第三轮）：换回 HTTP 语音合成接口 + 调试消息显示（用户方案）

> 状态：**待用户审批**——批准后才动代码。
> 前置：0.135 播客 WebSocket 路径真机卡连接阶段（toast「语音合成失败：WebSocket 错误: undefined」），用户拍板换方案（「换方案吧，你自己看」），并亲自提出「调试信息以对话消息显示」方案（本文件第二节）。

## 一、背景与路径决策

- **WebSocket 播客路径正式终结**（用户决定，不再重试）：0.135 真机 404 已消失但卡在 WebSocket 连接阶段，错误信息只有 undefined（日志只取了 err.message），继续深挖成本高、用户已失去耐心。
- **替代路线选定**：HTTP `https://ark.cn-beijing.volces.com/api/v3/audio/speech` + `doubao-tts` + `zh_female_cancan`——clipforge/Mora 等多个开源仓库直连方舟该端点的实证组合，用户 Key 已授权「Doubao-语音合成」。
- **诚实记录疑点**：0.134 真机 POST 该端点曾返回 404 无 body（180ms）。当时定论「端点不存在」，但开源多仓配置又指向它。**本次不预判，靠调试消息实测定位**：若再 404，调试消息会显示完整响应，能区分「路径不存在 / 账号未开通该模型 / 参数错误」三种情况，一次实测出真相。

## 二、用户方案：调试消息显示（核心创新）

**用户原话**：「把 bug 以对话 message 的方式打印出来，这样我就可以把后台的内容截图或者复制给你看，如果找到原因了，你更新的时候再把这个功能剔除」

**实现**：TTS 请求失败时，把完整调试信息作为一条 AI 消息插入当前气泡的对话列表（复用现有气泡渲染 + 长按复制/删除，零新组件）：

```
[TTS调试] 语音合成失败
URL: https://ark.cn-beijing.volces.com/api/v3/audio/speech
model: doubao-tts | voice: zh_female_cancan
文本长度: 155
HTTP 404
响应体: （空）
```

- **仅失败时插入**（成功不打扰）；持久化保存（重启不丢，用户可从容截图/复制）
- 信息全量：请求参数 + 状态码 + 响应体前 300 字符 + 失败阶段
- **定位修复后剔除**：代码统一标 ★ 0.136-DEBUG 注释，验证通过后下一版删除

**价值**：绕开「AI 抓真机日志通道不稳」的痛点（本会话多次抓日志中断），调试信息直达用户眼前，用户截图 = 我看到日志。

## 三、改动点明细（4 文件）

### ① ChatModel.ets（ApiConfig）

- `audioModel` 默认值：`'doubao-tts-anchor-65-241005'` → `'doubao-tts'`
- **恢复 `audioVoice` 字段**（默认 `'zh_female_cancan'`）——HTTP 协议需要 voice 参数；但**设置页不显示音色输入框**（用户明确不要音色配置，代码内默认值即可）
- `audioEndpoint` 默认值：`wss://openspeech.bytedance.com/...` → `'https://ark.cn-beijing.volces.com/api/v3/audio/speech'`

### ② ApiClient.ets

- 删 `synthesizePodcastTTS`（WebSocket 路径终结，git 历史可查）
- 恢复 `synthesizeTTS`（HTTP POST，0.134 已编译验证的实现：单段请求 + base64/二进制双兼容响应解析）
- **增强**：错误回调携带结构化调试信息（URL / model / voice / 文本长度 / HTTP 码 / 响应体前 300 字符），供调试消息使用

### ③ ChatPage.ets

- 恢复 0.134 分段流水线（分段合成顺序播放：requestNextSegment + playSegment「base64 → 临时文件 → AVPlayer」）——0.135 的「播 URL」链路不适用 HTTP 响应（HTTP 返回音频数据本体，不是 URL）
- **新增 `addTTSDebugMessage(debugInfo: string)`**（★ 0.136-DEBUG）：生成带 `[TTS调试]` 前缀的 AI 消息插入当前气泡并持久化
- TTS 失败回调：toast 保留 + **插入调试消息**
- 分段上限 280 保留（HTTP 单次请求同样有长度限制）

### ④ SettingsPage.ets

- `AUDIO_MODEL_LIST` 只留一项：`{ id: 'doubao-tts', name: 'Doubao-语音合成', type: '通用语音合成', price: 'HTTP 接口，开源实证' }`（界面显示名字不显示 ID）
- **音色输入框不恢复**（用户不要；voice 用代码默认值）
- 旧值迁移反转：`doubao-tts-anchor-65-241005`（播客 ID）→ `doubao-tts`；`wss://` 端点 → HTTP 端点
- 未保存提醒（onBackPressed，0.135 已实现）保留不动

## 四、验证计划（调试消息驱动）

1. **编译验收**：clean release 构建，0 条新增 ArkTS 警告 + BUILD SUCCESSFUL（media SysCap 按既定例外口径）
2. **装真机 → 用户点喇叭 → 看对话里出现的 [TTS调试] 消息 → 用户截图/复制给我**
3. **按调试消息定位**：

   - 404 + 响应体空 → 端点确实不存在 → 下一步：用户提供控制台「语音合成-2.0」的真实模型 ID / TTS V3 协议文档，换模型再测

   - 账号未开通类错误 → 用户去方舟控制台开通对应模型
4. **定位修复并验证出声后**：剔除调试功能（删 addTTSDebugMessage 及其调用点），更新文档收尾
