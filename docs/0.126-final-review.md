# 0.126 最终审查 — 补充点问题与修正

## 审查结论：方案逻辑正确，补充 1（Pan Y 限制）有 2 个具体 Bug

---

### Bug 1：`topSafePadding` 作用域错误 ❌

**AI 方案**：`topSafePadding` 是 `fitViewport()` 内的局部变量，Pan 手势 `onActionUpdate` 中直接引用 `topSafePadding` → **编译报错，未定义**。

**修正**：提升为类级常量。

```typescript
// 类顶部，与 canvasOffsetX 等字段同级
static readonly TOP_SAFE_PADDING: number = 120;
```

`fitViewport` 和 Pan 手势统一引用 `BBTreeCanvas.TOP_SAFE_PADDING`（或实例 `this.TOP_SAFE_PADDING`）。

---

### Bug 2：Pan Y 限制导致画布跳变 ❌

**场景**：树较高时 `fitViewport` 计算出 `canvasOffsetY = 90`（< 120）。用户触控 Pan 手势瞬间：

```
canvasPanStartY = 90  // onActionStart 保存
event.offsetY = 0     // 手指刚按下未移动
canvasOffsetY = Math.max(120, 90 + 0) = 120  // ← 瞬间跳变 90→120
```

画布在手指触控瞬间向上跳动 30vp，体验割裂。

**根因**：`fitViewport` 可以合法地设 `canvasOffsetY < TOP_SAFE_PADDING`（树高缩放后居中），硬限制 `≥ 120` 与之冲突。

**修正**：动态下限，取 `canvasPanStartY` 和 `TOP_SAFE_PADDING` 的较小值：

```typescript
.onActionUpdate((event: GestureEvent) => {
  this.canvasOffsetX = this.canvasPanStartX + event.offsetX;
  const newOffsetY = this.canvasPanStartY + event.offsetY;
  // ★ 动态下限：若起始位置已 < TOP_SAFE_PADDING（fitViewport 设的），不强制跳变
  const lowerLimit = Math.min(this.canvasPanStartY, this.TOP_SAFE_PADDING);
  this.canvasOffsetY = Math.max(lowerLimit, newOffsetY);
})
```

**行为验证**：

| canvasPanStartY | lowerLimit | 手指按下(offsetY=0) | 向上拖(offsetY=-10) | 向下拖(offsetY=+10) |
|-----------------|------------|---------------------|---------------------|---------------------|
| 200（正常） | 120 | 200（无跳变） | max(120,190)=190 | max(120,210)=210 |
| 90（fitViewport 高树） | 90 | 90（无跳变 ✅） | max(90,80)=90（锁死） | max(90,100)=100 |

- 正常情况：限制 120，不能把画布拖进标题栏
- 高树情况：限制 90，不跳变，但不能继续向上拖（双重防护仍生效）
