## 一、合规总览与核心策略

### 1.1 对标 Cube Agent 的核心思路：分层授权、按需触发

Cube Agent 把「同意」拆成了三层，越往后越重，每一层都**在用户真正用到时才触发**：

| 层级 | 触发时机 | 内容 | 不可跳过性 |
|---|---|---|---|
| L1 基础协议 | 首次启动 | 用户协议 + 隐私政策 | 必须同意才能进入 APP |
| L2 账号连接 | 想用在线服务时（免费模型/会员/分享） | 华为账号登录 + 华为账号用户认证协议 | 可选，「暂不连接」可跳过 |
| L3 AI 实名 | **首次发送 AI 生成请求时** | 华为账号身份核验（验证实名状态） | 拒绝则不能发 AI 请求 |

**关键洞察**：Cube 不在启动时强制登录华为账号，而是把「AI 实名」推迟到第一次按发送键的那一刻。用户先逛逛、先配置、先体验，需要 AI 时才完成身份闭环。合规覆盖面 100%（用 AI 必过实名），但劝退感最低。

### 1.2 DAG 产品的合规总原则（三条）

1. **本地数据优先**：气泡树、司忆卡片、单词库、知识库、API Key 全部本地存储，不上传开发者服务器（无开发者服务器，隐私政策已有此口径✅）。
2. **AI 功能按需实名**：AI 生成是全 APP 唯一需要「实名」的能力，用华为账号登录=实名核验（华为账号本身已实名，无需收集身份证），**在首次 AI 请求时触发，不提前**。
3. **最小权限**：仅相册（选图）+ 华为账号（登录/云同步/AI实名）两项授权，无定位、无通讯录、无后台权限。

## 二、首次启动与协议流程设计

### 2.1 启动页协议分层方案（两步法）

```
首次启动 APP
   │
   ▼
【第一步 L1】首启自动弹 AgreementDialog（✅ 已落码）
   - 勾选框默认不勾选（PIPL 红线）
   - 「我已阅读并同意《用户协议》《隐私政策》《华为账号用户认证协议》」
   - 点「同意并继续」→ 进入 APP 全功能浏览
   - 点「不同意」→ 关闭弹窗回原页，可浏览本地功能（AI/云同步后续再 gate）
   │
   ▼
正常使用：气泡树、司忆卡片、单词库、知识库、复习、设置——全部可用（游客模式）
   │
   ├─ 点「华为账号登录」（边栏/首页）→ 弹同一套同意弹窗 → 登录 → 云同步+30天试用 ✅ 已落码
   │
   ▼
【第二步 L2】首次发送 AI 对话请求 🚧（本方案新增，见 §3）
   - 未登录华为账号 → 弹「身份核验」弹窗 → 登录华为账号（登录即实名核验）
   - 已登录 → 直接放行
   - 拒绝核验 → 请求不发出，气泡保留草稿，友好提示
```

**与 Cube 的差异说明**：Cube 的 L1 是独立启动页，DAG 复用已落码的首启弹窗，效果等价且少一个页面。Cube 的 L2（连接在线服务）在 DAG 中不需要独立页——DAG 无内置免费模型，API 提供商配置已在全局设置，AI 请求的实名核验并入 L2 即可（华为账号登录一次同时完成「连接服务」+「实名核验」两件事）。

## 三、华为账号身份核验方案（重点）

### 3.1 核验触发时机：首次发起 AI 对话请求时

- **不在启动 APP 时强制登录**（Cube 同款策略，避免劝退）。
- 用户在对话页按下「发送」→ 检查华为账号登录态：
  - **已登录** → 直接放行（登录态即已实名）。
  - **未登录** → 弹「身份核验」弹窗 → 用户点击「华为账号登录」→ 走既有 Account Kit 登录链路（✅ 复用 0.164 落码）→ 登录成功自动继续发送原请求（不丢草稿）。
  - **拒绝** → 请求不发出；气泡文字保留在草稿（✅ 0.214.2 草稿机制现成）；Toast 友好提示「AI 生成需完成华为账号核验，可稍后在设置中完成」。
- **触发面**：所有 AI 请求统一 gate——气泡对话、问AI、划词翻译(若走AI)、图片提炼、摘要等。实现上在 ApiClient/请求出口处加统一前置检查，避免逐页面补丁。

### 3.2 核验页面文案规范（照 Cube 模板，直译到 DAG）

弹窗结构（复用 AgreementDialog 卡片风格）：

```
[图标]  华为账号身份核验
        发送 AI 生成请求前需要完成账号验证

┌─────────────────────────────────┐
│ 用途    AI 生成服务身份核验                    │
│ 不会获取 API Key / 聊天内容                   │
│ 本地服务  核验不影响离线使用本地功能           │
└─────────────────────────────────┘

☐ 我已阅读并同意《华为账号用户认证协议》   ← 首次核验时；0.226.0 已同意过则不重复
[华为账号登录]  [稍后]
```

**要点**：
- 「用途 / 不会获取」两行是审核员盯的重点，措辞照抄 Cube 成功案例。
- 「稍后」按钮必须存在（可关闭弹窗，不得卡死）。
- 华为账号用户认证协议：外链华为官方（⚠️ Agreement.ets:28 目前是占位 URL，**上架前必须核实替换为官方真实地址**，勿杜撰）。

### 3.3 技术实现路径

1. **不新建实名系统**：华为账号注册时已完成实名（年满 18 实名制），APP 侧只需「验证用户已登录华为账号」即视为完成实名核验。调 Account Kit `createLoginWithHuaweiIDRequest`（已有登录链路），**不收集、不存储任何身份证/人脸信息**。
2. **登录态判定**：复用 `HuaweiAccountStore`（PersistenceV2 key='huawei-account'，✅ 已有）。
3. **核验通过后**：本地打标 `aiVerified=true`（可挂在 AgreementStore 或 AccountStore，仅本地持久化），后续请求不再弹。
4. **AGC 侧**：Account Kit 已在新应用 DAGAI（6917618685526149144）下重配✅（0.217.1 client_id 已修复并三台实装验证）。
5. **审核材料**：AGC 提交时勾选「生成式AI应用」，填写 AI 功能说明+实名机制说明（引用本方案 §3.1/§3.3 文案）。

### 3.4 未实名用户的降级处理

| 场景 | 行为 |
|---|---|
| 华为账号存在但账号本身未实名（罕见） | 登录成功即放行（APP 侧无法也无需二次验证）；华为账号体系自身保证实名率 |
| 用户点「稍后/拒绝」 | 请求挂起草稿；同会话内不重复弹（防骚扰）；下次点发送再弹一次 |
| 游客本地功能 | 全部不受影响（对齐「同意只 gate 登录/云同步」的 0.226.0 边界哲学） |

## 四、数据合规与隐私设计

### 4.1 本地数据（气泡树、司忆卡片、知识库、单词库）

- 默认本地存储（PersistenceV2/RDB），**开发者无服务器、无后端存储**，天然合规。
- 隐私政策已声明「卸载即清除」✅。
- 无需任何动作。

### 4.2 ArkData 云同步

- 数据存用户自己的华为云空间，同步走系统 cloudData 通道，**开发者侧不可见**（AGC 调测页仅开发者自有账号数据）✅。
- 隐私政策第 3 条已声明「经华为云空间加密，仅同步于登录设备之间」✅。
- ⚠️ **上架 checklist 必查**：发布前 AGC 云同步服务须「实施变更到生产环境」（调试包连开发环境、发布证书连生产环境；忘做=正式用户云同步全断且无报错）。

### 4.3 API Key 安全

- ✅ 已落码：API Key 仅存设备本地（PersistenceV2），不上传服务器；对话内容直连用户配置的服务商，本应用不经手留存（隐私政策第 1/2 条）。
- 传输加密：所有 AI 请求走 HTTPS（服务商侧 TLS）✅。
- 无需新增动作；审核问答中如实说明「APP 为连接器角色，不存储转发用户密钥与内容」。

### 4.4 审计日志方案（🚧 新增，生成式 AI 专项要求）

《生成式人工智能服务管理暂行办法》要求生成式 AI 服务留存日志。DAG 架构下内容不经手，**仅留存最小元数据**即可覆盖审核要求：

| 字段 | 说明 |
|---|---|
| 请求时间 | 时间戳 |
| 功能类型 | 气泡对话/问AI/划词/提炼/摘要 |
| 服务商 | DeepSeek/方舟/MaaS/自定义（不存 Key、不存 URL 参数） |
| 结果状态 | 成功/失败（不存内容） |

- **留存**：本地 RDB 独立表（与业务数据分离），留存 ≥6 个月，仅本地不上传。
- **与用户业务数据分离**：独立表+独立清理逻辑，用户删除气泡不影响审计行；卸载即清（与现有卸载口径一致）。
- **用户知情**：隐私政策补一条（§2.2 表 #2）。
- ✅ **拍板（2026-10-16）**：本地先行 + 预留云端上报接口（数据结构按可上云设计）；阿里云服务器（99元包年）+域名 ICP 备案（约10天）就绪后可选上云，届时**隐私政策须同步改版**（披露服务器与日志上传口径）。详见 §八 决策 4。

## 八、决策拍板结果（2026-10-16 深夜与产品对齐）

> 六题已当面过完，拍板结果如下；★=与 agent 初始推荐不同，已按产品意志定案。

### 决策 1：AI 实名 gate —— ✅ 拍板选 A「强制」

- 首次 AI 请求时未登录华为账号 → 弹核验弹窗 → 登录即实名（不收集身份证），对齐 Cube。
- 影响面：所有 AI 出口（气泡对话/问AI/划词/提炼/摘要）统一前置 gate，拒绝则草稿保留。

### 决策 2：新手引导 —— ✅ 拍板选 C「4 步精简版 + AP 激励 + 每日打卡，一起做」

- 产品原话要点：先做精简版「我看看样子」，正式上线前最后再打磨；AP 点具体数额未定（先占位可配）。
- **新增拍板功能**：**每日打卡**与新手引导、AP 激励同批做（产品原话「要做了就一起做进去」）。
- 实现口径：引导 4 步每步完成给 AP（数额后续配置化）+ 每日打卡奖励 AP；AP 体系落码须守 §6.2 红线。

### 决策 3：算力包首版一起上 —— ✅ 拍板选 B ★（推翻 agent 推荐）

- 产品理由：**降低玩家入门门槛**（订阅是重承诺，算力包轻量按次付费）。
- **重大新信息：IAP 商户资格已批下来，AGC 后台已可沙盒付款测试**——IAP 不再是外部依赖，订阅+算力包可同批真接入。
- 配套动作（产品自行推进）：同步调研 DeepSeek/豆包/方舟等各家 API 价格，按实际成本倒算算力包定价（9.9元/1000次 为初始假设，最终以成本核算为准）。
- 合规要求不变：消耗规则公示（什么算一次、失败扣不扣）、AP 不可变现红线（§6.2）。

### 决策 4：审计日志 —— ✅ 拍板「本地先行 + 预留云端接口」★（升级版）

- 采纳豆包建议：先做本地元数据日志（时间/功能类型/服务商/状态，不含内容），数据结构按可上云设计，留出上报接口。
- **重大新信息：已购阿里云 99 元包年服务器**（配置够一两百用户，不够再扩），**域名 ICP 备案审批中（预计约 10 天）**，下来后部署云端日志接口。
- ⚠️ **连锁合规影响（重要）**：服务器上线后，「开发者无服务器、数据不经手」的隐私政策口径必须更新——改为「业务数据本地存储；AI 请求元数据日志（不含内容）存储于本地，可选上传至开发者服务器用于安全审计」，并披露服务器所在地、留存周期、安全措施。**隐私政策条款改版列入服务器上线后的必做项**。

### 决策 5：AI 生成内容标注 —— 🚧 倾向轻量版（待最终确认）

- AI 气泡角标「AI」+ 复制/分享附带「内容由 AI 生成」尾注；无异议即按此落码。

### 决策 6：隐私政策网页版 —— 🚧 趋势转向「要做」

- 原推荐「应用内即可，被驳回再补」；现因域名 ICP 备案已在流程中，**建议域名下来后直接挂网页版隐私政策**（成本≈一个静态页），提审材料更硬，AIGC 类目审核常要求可公开访问的隐私政策 URL。

### 决策 7（新增）：浅色模式适配 —— 🚧 查证结论 + 建议方案

- **查证状态**：华为官方《应用市场审核指南》为 JS 渲染页面，本次未能直接核实条款原文；DuckDuckGo/Bing 检索未命中明确驳回案例。以下为基于行业实践的判断，**最终以 AGC 提审后审核员反馈为准**：
  - HarmonyOS Design 规范**推荐**应用支持深浅色跟随系统，但审核硬性驳回点是「界面显示异常/错乱/文字不可读」，**未见「必须同时提供深浅两套模式」的强制条款**。
  - 行业实证：大量纯深色工具类应用已在华为市场上架（锁定深色不跟随系统是允许的做法）。
  - 真正的雷区：若应用**声明跟随系统**却没适配浅色 → 浅色模式下白字白底 → 驳回「界面显示异常」。DAG 现状=暗紫主题锁定暗色（方案A），不声明跟随系统，无此雷。
- **建议方案（低成本防身）**：不立即开发浅色模式；把 UI_GUIDELINES 色板做一层**颜色 token 抽象**（布局代码引用 token，禁止散落硬编码色值），将来若审核要求或产品需要，加浅色=只改 token 映射表、不动布局。作为待办记录，非上架阻塞项。
