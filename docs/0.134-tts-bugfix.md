## 二、根因分析（v2，含用户提供的决定性证据）

### 证据 1：用户 API Key 权限页截图（方舟控制台）

Key「DAG-AI」的访问权限范围已勾选语音类 5 个模型：**Doubao-语音播客、Doubao-语音合成-2.0、Doubao-语音合成、Doubao-实时语音交互、Doubao-流式语音识别**。
→ **Key 权限没有问题**，语音模型已授权可用。

### 证据 2：官方「语音播客 API」文档截图（用户提供）

文档地址：`https://docs.volcengine.com/docs/DoubaoVoice/PodcastAPI-websocket-v3protocol?lang=zh`

**「Doubao-语音播客」模型的官方调用方式是 WebSocket 接口，不是 HTTP**：

| 项 | 值 |
|---|---|
| 端点 | `wss://openspeech.bytedance.com/api/v3/sami/podcasttts` |
| 鉴权 | `X-Api-Key`（**方舟控制台的 API Key，用户现有 Key 即可用**）+ `X-Api-Resource-Id: volc.service_type.10050` + `X-Api-Request-Id`（uuid，可选） |
| 协议 | WebSocket + 自定义二进制帧（4 字节 header + payload，支持 gzip） |
| 生成模式 | action=0 文本/URL 总结生成 / action=3 对话文本直接生成 / action=4 联网搜索生成 |

### 证据 3：开源实证（Sourcegraph 搜 "doubao-tts"，281 条匹配 / 23 仓库）

- clipforge / Mora（tts-presets.ts）**直连方舟 HTTP 端点**：`{baseUrl: https://ark.cn-beijing.volces.com/api/v3, model: "doubao-tts", voice: "zh_female_cancan"}`
- labring/aiproxy 网关：Doubao-tts 走 AudioSpeech（即 `/audio/speech`），音色表 70+ 个（`zh_female_cancan_mars_bigtts` 等完整格式）
- 官方 Python SDK 无 TTS 模块（GitHub master + PyPI 双源确认）

### 根因定论

火山豆包语音是**两套并行体系**，模型与接口是绑定的：

| 模型 | 服务接口 | 用 HTTP /api/v3/audio/speech 调用会怎样 |
|---|---|---|
| **Doubao-语音播客**（doubao-tts-anchor-65-241005） | **WebSocket** `wss://.../api/v3/sami/podcasttts` | **404**（该端点不服务此模型）← **本次 bug 的真正根因** |
| **Doubao-语音合成 / 语音合成-2.0**（doubao-tts / doubao-tts-241215） | **HTTP** `https://ark.cn-beijing.volces.com/api/v3/audio/speech` | 正常工作（开源实证） |

次要问题：当前请求体 `voice` 误传了模型 ID（voice 应是独立音色 ID，如 `zh_female_cancan`）——无论换哪个模型都必须修。

## 三、修复方案 A（本次 0.134 实施）：换用 HTTP 端点服务的语音合成模型

**思路**：朗读 AI 消息是单人朗读场景，用「Doubao-语音合成」（走 HTTP 端点、开源实证可用、用户 Key 已授权）即可修复 404；「语音播客」模型留待方案 B（WebSocket，未来版本）。

**默认组合**采用 clipforge/Mora 整体验证过的：`model: "doubao-tts"` + `voice: "zh_female_cancan"`。

### ① ChatModel.ets（ApiConfig）

- `audioModel` 默认值：`'doubao-tts-anchor-65-241005'` → `'doubao-tts'`
- 新增 `@Trace audioVoice: string = 'zh_female_cancan'`（音色 ID）
- 持久化：ApiConfig 走 PersistenceV2，新增 @Trace 字段自动持久化，老数据升级无此字段时取默认值

### ② ApiClient.ets（synthesizeTTS 请求体）

- `voice: config.audioModel` → `voice: config.audioVoice`
- 请求日志补充 `voice` 字段输出，便于真机诊断

### ③ SettingsPage.ets

- `AUDIO_MODEL_LIST` 更新（只保留 HTTP 端点可用的模型）：
  - `{ id: 'doubao-tts', name: 'Doubao-语音合成', type: '通用语音合成', price: 'HTTP 接口，开源实证可用' }`
  - `{ id: 'doubao-tts-241215', name: 'Doubao-语音合成2.0', type: '通用语音合成', price: 'HTTP 接口，以控制台开通为准' }`
  - **移除** `doubao-tts-anchor-65-241005`（语音播客模型，WebSocket 专用，HTTP 调用必 404）
- 新增「音色 ID」TextInput（`editAudioVoice`，样式同音频 Endpoint 输入框），placeholder 提示可填 `zh_female_cancan` 等
- `aboutToAppear` 加载 `editAudioVoice`；保存按钮写入 `apiConfig.audioVoice`
- **旧值自动迁移**：`aboutToAppear` 时若 `editAudioModel === 'doubao-tts-anchor-65-241005'`（本机现存旧值）则重置为 `'doubao-tts'`，用户无感切换

### ④ ChatPage.ets（错误提示增强）

- toast 截断 `err.substring(0, 60)` → `err.substring(0, 150)`：失败时直接看到方舟返回的完整错误 JSON（含错误码与 message），无需连电脑抓日志

### ⑤ 修复问题 2：触发器显示名字（SettingsPage.ets）

- 新增辅助方法 `audioModelDisplayName(id)`：在 `AUDIO_MODEL_LIST` 按 id 匹配返回 `name`；匹配不到（自定义 ID）返回 ID 本身
- 触发器 Text 改为显示 `audioModelDisplayName(this.editAudioModel)`
- TextInput 保留原样（自定义编辑入口，显示 ID 合理）

## 四、未来方向 B（0.135+ 候选，本次不实施）：WebSocket 播客 API 接入「真·双人播客」

用户提供的官方文档已确认协议全貌，**且鉴权用的就是方舟 API Key（无需申请语音控制台双凭证）**，未来实施有据可依。协议要点存档：

- **端点**：`wss://openspeech.bytedance.com/api/v3/sami/podcasttts`
- **鉴权**：`X-Api-Key`（方舟 Key）+ `X-Api-Resource-Id: volc.service_type.10050` + `X-Api-Request-Id`（uuid，可选）；响应头 `X-Tt-Logid` 建议打印便于定位
- **二进制帧**（大端序）：byte0=协议版本 0b0001+header大小 0b0001；byte1=消息类型 0b0001+flags（sendText=0，finishConnection=0b100）；byte2=序列化（0=Raw 音频/1=JSON）+压缩（0=无/1=gzip）；byte3=保留；[4-7]=可选字段（事件号等）；后接 payload
- **三种生成模式**：action=0（input_text 或 input_info.input_url 总结生成，上下文 ≤32k）/ action=3（nlp_texts 对话文本直接生成，单轮 ≤300 字符、总长 ≤10000 字符，每轮指定 speaker 发音人）/ action=4（prompt_text 联网搜索生成）
- **便捷选项**：`input_info.return_audio_url=true` 时通过事件 363（PodcastEnd）的 `meta_info.audio_url` 返回完整播客音频下载链接（1 小时有效）——可绕过流式拼接，直接拿整段音频播放
- **鸿蒙实现要点**（未来评估）：`@ohos.net.webSocket`（支持 ArrayBuffer 二进制帧）、位运算解析 header、gzip 解压（需查证鸿蒙 zlib 能力）、流式音频分段拼接；工程量远大于 HTTP 方案
