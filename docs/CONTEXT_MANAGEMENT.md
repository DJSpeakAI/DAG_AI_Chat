## 二、AI 助手自律规则（每次会话生效）

### 规则 1：阈值触发整理
- **触发点**：每完成一个版本迭代（装机验收后）/ 用户说"整理" / 会话跨了多个大话题
- **动作**：主动做结构化阶段总结，写入 MEMORY.md（活规则）或 docs/（细节），然后**依赖文档而非对话记忆**继续工作

### 规则 2：阶段总结固定清单
按此结构写（学 Claude Code 9 部分，适配我们）：
1. 本次目标（用户要什么）
2. 完成的改动（版本号+一句话每项）
3. **用户拍板的规则/决策（逐条列，禁止合并省略——这是最高优先级信息）**
4. 关键技术决策及理由（如"为什么 key 升 v2"）
5. 未完成/待办
6. 下一步
7. 当前版本号与四处同步状态

### 规则 3：MEMORY.md 写入纪律
- 只写"下次会话必须知道的活规则 + 当前状态"
- 写前自问：**"这条信息下次会话必须知道吗？"** 否 → docs/ 版本文档
- 历史版本细节一律进 docs/（已有分层：L1 总索引/L2 段索引/L3 详情/L4 归档）

### 规则 4：长会话自救
- 跨了很多轮的话题要动手改代码时 → **先重读 MEMORY.md / docs/ 相关节，再动手**
- 不凭远距离对话记忆改代码（防改错、防违反用户早已拍板的规则）
- 感觉上下文"远了"（话题切换多次）→ 主动重读 project_rule.md 关键节

### 规则 5：用户消息是意图锚点
- 整理/总结时，用户的原始意图表述必须保留（学"所有用户消息枚举"）
- 用户骂着说的需求 = 高优先级需求，语气可滤、意图不可滤

## 三、Prompt 编写 10 条军规（所有新 prompt 生效）

1. **身份锚定**：先定 WHO（"你是一个学习统计鼓励师"）再定 WHAT
2. **负向约束配对**：每个"要 X"配一个"别 Y"（"必须引用具体数字"↔"禁止通用套话"）
3. **失败模式接种**：提前命名会犯的错（"禁止重复之前用过的表述"）
4. **穷举优于概括**：列 case，不写"等等之类"
5. **BAD/GOOD 示例并列**：给一对反例正例（「你就是未来的爱因斯坦」这类风格）
6. **逃生舱**：约束留用户覆盖口（档位 off = 不生成）
7. **数字锚定**：**"简洁"“简短”是违规词**——必须写"1~2 句""不超过 4 句"
8. **行为梯度**：风险/语气分档（轻度/重度），不搞二元开关
9. **成本意识**：prompt 长度=每次调用的 token 成本，能短则短
10. **首尾强化**：最关键的约束在 prompt 开头和结尾各出现一次

## 五、用户画像与协作风格（★ 用户指示必读）

**用户是发散性、联想力天才级的思考者**——爱因斯坦式思维：创新力=联想力，核心能力是**跨领域知识融合**（把各家大厂的长项融会贯通成垂直领域最优解，DAG 项目本身就是这种融合力的产物）。

**协作要求**：
1. **多给发散性内容**：回答时主动提供跨领域知识点、技术类比、行业对照——这些是用户的"种子"，用户负责联想融合成创新
2. **多给选择题**：方案呈现时给多个分支选项（A/B/C 各自的优劣），拓宽用户思路，让用户拍板——不要只给单一路径
3. **认真对待直觉**：用户的直觉判断多次与工程验证方向一致（"prompt 为中心"架构 ↔ Claude Code 51 万行源码验证；"AI 需要鼓励" ↔ prompt 工程实证）——每个直觉都给技术依据回应，不敷衍
4. **协作模式**：用户出直觉+方向+拍板，AI 出实现+验证+发散种子——目标是共同打造全球最牛逼的 AI 时代深度学习工具
